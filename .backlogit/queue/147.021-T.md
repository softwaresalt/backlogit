Plan unit **U2f**. Land the executable form of protected invariant **I1**: every code path that rewrites an existing checkpoint file in place must be gated, not just the two named in the stash text.

Files: `internal/events/checkpoint_writesite_test.go` (new). **No production change.**

**One mechanism, decided here.** The mechanism is a **write-site enumeration test** — the "or gated rewrite seam" alternative is withdrawn, not deferred. Carrying both mechanisms in one task meant the task's real file set was either one new test file **or** five files across `internal/events` and `internal/core` spanning the tests and code domains, so its size could not be known before work started and the larger branch breached both the three-file heuristic and width isolation. The rejected alternative and the reason are recorded in the plan's Decisions and Rationale table; this task now has a single, sized shape.

The test walks the sources of **both** `internal/events` and `internal/core` for calls to `syncWriteFileAtomic` / `atomicfile.WriteFileAtomic` / `os.WriteFile` whose target resolves under the checkpoint directory, and asserts the resulting call-site set equals the allow-list audited in the plan. `internal/core` is in scope because `AbandonCheckpoint` (`internal/core/checkpoint_disposition.go:~110-125`) calls `atomicfile.WriteFileAtomic` directly inside its `MutationEnvelope`; an enumeration limited to `internal/events` would leave that rewrite invisible — the exact hole I1 exists to close. A new in-place rewrite path added later then fails this test rather than silently joining the ungated set.

**Halt condition, not scope expansion.** If the enumeration cannot be implemented reliably — for example if call-target resolution proves ambiguous — mark this task `blocked` and re-plan the gated-seam alternative as its own units under a new task ID. Do **not** grow this task into the seam: that is the width-isolation breach this split exists to prevent.

**Why this is separate from 147.005-T.** I1's executable form is a distinct deliverable that 147.007-T (U3b) and 147.008-T (U4) must satisfy, so the allow-list must be pinned **before** those units touch their call sites. Bundling it into 147.005-T would take that unit to four scenarios across two skill domains.

Record the audited allow-list in the task log before 147.007-T or 147.008-T starts.
