Plan unit **U2f**. Land the executable form of protected invariant **I1**: every code path that rewrites an existing checkpoint file in place must be gated, not just the two named in the stash text.

Files: `internal/events/checkpoint_writesite_test.go` (new); under the fallback mechanism additionally `internal/events/checkpoint_lifecycle.go`.

Primary mechanism: a write-site enumeration test that walks the package sources for calls to `syncWriteFileAtomic` / `atomicfile.WriteFileAtomic` / `os.WriteFile` whose target resolves under the checkpoint directory, and asserts the resulting call-site set equals the allow-list audited in the plan. A new in-place rewrite path added later then fails that test rather than silently joining the ungated set.

Fallback if the enumeration proves impractical to implement reliably: a single gated helper `rewriteCheckpointFile(path string, cp *CheckpointV1, original []byte) error` that runs both gates internally and is the **only** function permitted to re-marshal an existing checkpoint. Either mechanism satisfies I1; a comment does not.

**Why this is separate from 147.005-T.** The fallback is a **production seam** that 147.007-T (U3b) and 147.008-T (U4) must route through, so the mechanism decision is taken here and consumed there. Bundling it into 147.005-T would put a possible production change inside a unit that declares itself green on landing with no red phase, and would take that unit to four scenarios across two skill domains.

Record the chosen mechanism in the task log before 147.007-T or 147.008-T starts.
