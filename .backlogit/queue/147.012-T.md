Plan unit **U6b**. Make `GetCheckpoint` agree with `ListCheckpoints`.

Files: `internal/events/checkpoint_lifecycle.go`, `internal/events/checkpoint_lifecycle_test.go`.

`GetCheckpoint` (`:105-137`) currently reports `valid: true` for any document that parses and validates. After U4/U5 that is actively misleading: an agent running the canonical `list` → `get` → choose-verb sequence would read `needs_quarantine: true` from list and `valid: true` from get, then pick the verb this feature just closed.

Add a `Conforming bool` field (and reuse `NeedsQuarantine` / `RemediationCommand`) so both read surfaces answer the same question. `valid` retains its existing meaning (schema-valid) and is **not** repurposed; conformance is reported as a distinct field so no existing consumer's contract silently changes.

<!-- BEGIN:acceptance-criteria -->
- A valid-but-non-conforming file returns `valid: true, conforming: false, needs_quarantine: true`
- A conforming file returns `conforming: true`
- The file is byte-unchanged after get
- Expected red: cases 1 and 2 fail
<!-- END:acceptance-criteria -->
