Make trust-anchor revoke (168.005-T) AUTHORITATIVE: since in-workspace status is now advisory (168.007-T), a revoke that could only flip advisory workspace status MUST NOT report success. Workspace containment (Constitution IV / cycle-3 item 4): the authoritative revocation is recorded through an INJECTED non-filesystem revocation authority (a monotonic external de-pin/tombstone provider, or a signed/read-only authority the resolver consults) -- NOT a mutable filesystem write to any path outside the workspace; the workspace holds only a contained projection of revocation state. Revoke therefore either records the revocation via that provider (so the resolver monotonic external de-pin/tombstone denies the key) or explicitly surfaces the required external operation and FAILS CLOSED (non-success) until confirmed. Domain: code. Depends on 168.005-T, 168.007-T, 168.010-T (RED). AC: (1) revoke returns success ONLY when the revocation is recorded through the non-filesystem external authority (or the explicit external operation is confirmed) -- NO external-path filesystem writes are authorized; (2) an advisory-only workspace status flip returns non-success/fails closed and does NOT claim revoked; (3) a negative test proves an advisory-only flip does not resolve the key as revoked; (4) the workspace holds only a contained projection, not the authoritative external state.
