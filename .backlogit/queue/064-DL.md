        Both incidents are permanent motivating evidence for this proposal. Neither is compliant; neither is normalized or hidden by this enforcement engine. These incidents demonstrate that prose-documented policies and agent self-discipline are insufficient. The same class of P-002 violation recurred across multiple shipments despite policy documentation, review instructions, and post-incident remediation. This proposal describes a future machine-enforcement response to break the cycle — it does not retroactively remediate or excuse the prior incidents.

        Required capabilities:
        1. Prerequisite graph with typed nodes and edges: each workflow gate (harness-scaffold, red-phase-verify, green-phase-verify, review-complete, CI-pass, merge-ready) is a node; edges encode required ordering. The graph is declared in the workflow-policy registry and evaluated at runtime.
        2. Immutable commit-SHA-bound evidence: every gate node requires a commit SHA proving the gate was satisfied. Evidence is recorded as structured frontmatter or sidecar artifacts. Evidence cannot be retroactively fabricated.
        3. Local build/agent preflight failure: before any implementation step, the engine evaluates the prerequisite graph for the current task. If required predecessor nodes lack evidence or evidence is out-of-order, the operation fails with a structured error. This applies to CLI commands, MCP tool calls, and agent skill dispatch.
        4. Fail-closed exception handling: if the graph evaluation encounters an ambiguous state, the default is BLOCK. No silent pass-through.
        5. Audited explicit overrides: where workflow policy explicitly permits overrides (e.g., harness-exempt with P-002.1 conditions), overrides are recorded as structured evidence with operator identity, justification, and the specific gate being overridden.
        6. CLI/MCP/agent surface parity: enforcement is identical across all three surfaces. No surface can bypass a gate that another surface enforces.
        7. Shipment integration: the prerequisite graph rolls up to the shipment level. A shipment cannot transition to review-ready or ship-ready unless all constituent tasks have satisfied all applicable gates.
        8. Red-test honesty integration: the red-phase-verify gate node uses deterministic verification to confirm that newly added tests actually fail against the pre-implementation baseline.
