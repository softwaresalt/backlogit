# Configure .mcp.json and reconcile canonical ToolchainManifest after tool binary install (U2)

## Description

<!-- BEGIN:description -->
Implement Unit U2 of `docs/plans/2026-11-19-init-install-target-tools-dir-mcp-config-plan.md` (`218-F`, `269D054D` / `103-DL`): run a read-only preflight inside `installWorkspaceRuntimeExecutable` (via `reconcileWorkspaceToolchainYAML` in preflight mode and `.mcp.json` validation) **before** creating any target directory or writing `<tools_dir>/backlogit[.exe]` or `.mcp.json` so any incompatible `ToolEntry.ID` -> `"backlogit"` lockfile reference (`internal/toolchain/verify.go:577-585`), incompatible `start.ps1`/`start.sh` launcher relocation (`internal/toolchain/launcher.go:471-483`), unknown YAML field, or `.mcp.json` transport conflict fails closed with existing file bytes unchanged and zero new files created; then after installing and verifying `<tools_dir>/backlogit[.exe]`, atomically create or merge `.mcp.json` (`configureWorkspaceMCPJSON`) into canonical `mcpServers.backlogit` via `map[string]json.RawMessage`, and in `reconcileWorkspaceToolchainYAML` construct and validate the proposed `ToolchainManifest` and migrated `start.ps1`/`start.sh` launcher bytes in-memory (`toolchain.VerifyWorkspaceToolchain(ctx, absRoot, manifest)`), atomically publish `<storage_root>/toolchain.yaml` on `storageHandle` and migrated `start.ps1`/`start.sh` on `wsRoot` (with pre-image rollback on partial write failure), and run disk-based `toolchain.VerifyLauncherScripts(absRoot)` **only after** both the reconciled manifest and migrated launchers are published on disk.

## Implementation Notes

<!-- BEGIN:implementation-notes -->
* Because `toolchain.VerifyLauncherScripts(absRoot)` reloads `<storageDir>/toolchain.yaml` from disk (`internal/toolchain/launcher.go:31-37`), `reconcileWorkspaceToolchainYAML` MUST: (1) validate the proposed `ToolchainManifest` and migrated `start.ps1`/`start.sh` bytes in-memory during preflight (`installedSHA256Hex == ""`) and via `toolchain.VerifyWorkspaceToolchain(ctx, absRoot, manifest)` before publication, (2) atomically publish `<storageDir>/toolchain.yaml` on `storageHandle` and migrated `start.ps1`/`start.sh` on `wsRoot` (capturing pre-image bytes and restoring them on any partial write or post-check failure), and (3) run disk-based `toolchain.VerifyLauncherScripts(absRoot)` **only after** the reconciled `<storageDir>/toolchain.yaml` and migrated launchers are both published on disk.
