EXECUTABLE schema-contract task (<=2h, width-isolated to the docline base schema family; introduced for the PR #241 correction, revised for PR #242 cycle 2 to the authoritative base/derived model). Test-first and GATED behind the RED-first regression 107.010-T. Under the authoritative model docline is the BASE contract: its schema must be OPEN/extensible so derived producers (backlogit) may carry ADDITIONAL top-level extension properties, but schemas/docline/base-frontmatter-v1.schema.json currently declares top-level additionalProperties:false, which contradicts that design and rejects producer-owned top-level extension keys (size, size_source, size_ruleset_version). Open the base schema so it ACCEPTS additional producer-owned top-level extension properties generally (e.g. set additionalProperties:true, or an equivalently open construct), WITHOUT enumerating size/size_source/size_ruleset_version as base fields and WITHOUT encoding any distinction between declared/sanctioned extensions and arbitrary legacy unknown keys. The base schema neither enumerates nor validates backlogit size semantics; it simply stops rejecting extension properties while continuing to validate ONLY the docline-owned base fields (required title/source/ingested_at/doc_type, minLength, closed doc_type vocabulary, content_sha256 pattern) unchanged. This intentional openness means the base validator ignores extension semantics by design - no claimed lint divergence between sanctioned and legacy keys is needed at the base layer. Test-first: write the FAILING schema-validation coverage first (representative producer extension keys size/size_source/size_ruleset_version validate at the top level against the base schema; base-owned field validation is unchanged and still rejects base-field violations), then change the schema to turn it green. Keep the hand-rolled Go validator internal/docline/validate.go consistent with the schema contract: it validates only base fields and does not enforce additionalProperties today, so opening the schema introduces no Go behavior regression and the validator continues to intentionally ignore extension semantics. Coordinate coherently with the codec pass-through task 107.009-T (preserves unknown top-level keys in place) and the authoring-guide task 107.012-T (documents the inheritance model); the Schema-CLI-Docs Coupling Reviewer must confirm the three stay consistent. Separation of responsibilities under the base/derived model: the base schema ACCEPTS and the codec (107.009-T) PRESERVES extension properties; neither validates their semantics. Validation of size/size_source/size_ruleset_version semantics is OWNED by backlogit's FUTURE derived schema/validators (out of scope here) - the base contract must not be made to enumerate or validate them. No text may claim the base schema sanctions specific size fields or distinguishes sanctioned-vs-legacy extension keys. Ownership stays explicit: docline owns only the base contract and never validates/defaults/emits extension semantics; size domain semantics remain backlogit-owned and derived. No CLI-distribution changes.
