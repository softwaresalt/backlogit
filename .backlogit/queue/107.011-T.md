EXECUTABLE schema-contract task (<=2h, width-isolated to the docline base schema family; introduced for the PR #241 correction, revised for PR #242 cycle 2 to the authoritative base/derived model). Test-first and GATED behind the RED-first regression 107.010-T. Under the authoritative model docline is the BASE contract: its schema must be OPEN/extensible so derived producers (backlogit) may carry ADDITIONAL top-level extension properties, but schemas/docline/base-frontmatter-v1.schema.json currently declares top-level additionalProperties:false, which contradicts that design and rejects producer-owned top-level extension keys (size, size_source, size_ruleset_version). Open the base schema so it ACCEPTS additional producer-owned top-level extension properties generally (e.g. set additionalProperties:true, or an equivalently open construct), WITHOUT enumerating size/size_source/size_ruleset_version as base fields and WITHOUT encoding any distinction between declared/sanctioned extensions and arbitrary legacy unknown keys. The base schema neither enumerates nor validates backlogit size semantics; it simply stops rejecting extension properties while continuing to constrain ONLY the docline-owned base fields it already defines (required title/source/ingested_at/doc_type, their minLength, the ingested_at date-time format, and the content_sha256 pattern) unchanged; the closed doc_type vocabulary is NOT a schema constraint (the schema declares no doc_type enum) and remains enforced solely by the Go validator internal/docline.Validate. This intentional openness means the base validator ignores extension semantics by design - no claimed lint divergence between sanctioned and legacy keys is needed at the base layer. Test-first (this repo has NO JSON-Schema runner - the internal/docline/validate.go hand-rolled validator mirrors the schema to avoid a JSON-Schema dependency, so RED is observed structurally in Go, not by executing the JSON schema): in a new test internal/docline/schema_contract_test.go run by go test ./internal/docline/..., first add a FAILING assertion that the base schema currently sets top-level additionalProperties:false (RED at HEAD) and must instead ACCEPT producer-owned top-level extension keys (size/size_source/size_ruleset_version), and pin that base-owned SCHEMA constraints are unchanged (required title/source/ingested_at/doc_type, their minLength, the ingested_at date-time format, and the content_sha256 pattern) - the schema declares NO doc_type enum, so the closed doc_type vocabulary is enforced ONLY by the Go validator internal/docline.Validate (via IsKnownDocType), NOT by the schema; the test loads the schema with encoding/json and asserts its structure, adds NO new dependency or tool, and includes companion assertions that internal/docline.Validate already accepts representative extension keys (a mirror invariant, green at HEAD) AND still rejects an unknown doc_type (pinning the Go-validator-only closed vocabulary separately from the schema). Then change the schema to turn the additionalProperties assertion green. Keep the hand-rolled Go validator internal/docline/validate.go consistent with the schema contract: it validates only base fields and does not enforce additionalProperties today, so opening the schema introduces no Go behavior regression and the validator continues to intentionally ignore extension semantics. Coordinate coherently with the codec pass-through task 107.009-T (preserves unknown top-level keys in place) and the authoring-guide task 107.012-T (documents the inheritance model); the Schema-CLI-Docs Coupling Reviewer must confirm the three stay consistent. Separation of responsibilities under the base/derived model: the base schema ACCEPTS and the codec (107.009-T) PRESERVES extension properties; neither validates their semantics. Validation of size/size_source/size_ruleset_version semantics is OWNED by backlogit's FUTURE derived schema/validators (out of scope here) - the base contract must not be made to enumerate or validate them. No text may claim the base schema sanctions specific size fields or distinguishes sanctioned-vs-legacy extension keys. Ownership stays explicit: docline owns only the base contract; it re-emits/serializes caller-provided extension properties at the top level when present but never synthesizes, defaults, validates derived semantics, or semantically interprets them; size domain semantics remain backlogit-owned and derived. No CLI-distribution changes.
