Make append+write crash-safe WITHOUT truncating the shared per-item JSONL (concurrent non-size writers dont hold the per-task lock; truncation = data loss, forbidden). Protocol under per-task lock: (1) SizeMutation.OpID optional (retry reuse); (2) applied-check: if current size_op_id==OpID return success (already applied, no append); (3) IDEMPOTENT RETRY DEDUP (Copilot F4): BEFORE appending, scan the estimate-history event stream for an event already tagged with this OpID. If one exists (orphan from a prior crash where append succeeded but the write failed - current size_op_id still ==PrevOpID, not OpID), do NOT append a second event; instead RECONCILE by completing the artifact write (CAS on PrevOpID) from the event payload, then return; (4) only if no event for this OpID exists: capture PrevOpID, append event tagged OpID+PrevOpID (fail-closed), then atomic mdfront write persisting size/provenance + reserved custom_fields.size_op_id=OpID. FULL DESIRED-STATE PAYLOAD (Copilot F5): the event Delta pins the COMPLETE presence-aware desired state for size, size_source, size_ruleset_version - each marked SET(value) or CLEAR(remove) - so doctor/retry can reconstruct the exact intended mutation (including field removal), not just a set. Doctor CAS on PrevOpID: apply fresh orphan only if current==PrevOpID; ==OpID already-applied; else stale/benign, never replayed. Files: internal/core/artifact_size.go, internal/core/doctor_target.go. Tests: retry-from-orphan-state (event exists, write did not land -> no duplicate event, write completed); doctor reconciles a CLEAR-a-field mutation exactly; retried op-id idempotent. Depends on SE-3a. <=2h, core persistence. See impl-plan SE-3b.
