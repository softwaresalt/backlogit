# Shipment B: CLI UX & Output Formatting

## Problem Frame

<!-- BEGIN:problem-frame -->
Three user-facing surface gaps in backlogit's CLI/MCP layer impair daily use and discoverability:

1. **No version visibility (68DAEC16):** Users can't determine what build they are running. There is no `--version` flag, no `version` subcommand, and no MCP-side equivalent. Bug reports and CI artifacts lack provenance.
2. **One-shape output (979D0F63):** All read commands (`list`, `queue view`, `stash`, `get`, `shipment`) emit the same human-formatted text. There is no machine-friendly format for scripting and no per-item "tile" view that pairs cleanly with intercom broadcasts (one self-contained message per item).
3. **README discoverability (842E1EE2):** README is short (130 lines) but flat — install, quick-start, features, and tech stack are mixed in one page with no deeper guides. New users can't find CLI reference, MCP tool catalog, or the stash→ship workflow doc.

Scope boundary: this shipment covers user-facing read surfaces and documentation structure only. It does not change artifact schemas, write semantics, MCP contracts beyond adding one read tool, or backlog logic.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
**Track 1 (--version):**
- A. CLI flag only (`backlogit --version`)
- B. CLI flag + `version` subcommand + MCP `backlogit_get_version` tool ← chosen
- C. Print version on every command (rejected: noisy)

Version data injected via `-ldflags -X main.version=...` at build time; falls back to `(devel)` for `go run`. Cobra's `Version` field handles `--version` automatically.

**Track 2 (output formatting):**
- A. Hand-rolled formatter with `--format=table|tile|json` flag ← chosen. No new deps. Default = table.
- B. Adopt a TUI library (rejected: too heavy for a flag)
- C. JSON-only and let users pipe through `jq` (rejected: regresses human UX)

Tile format = repeated blocks of `Property: Value` lines separated by blank lines, suitable for one-message-per-item intercom broadcasts. Coverage: `list`, `queue view`, `stash fetch/get`, `get`, `shipment list/get`.

**Track 3 (README restructure):**
- A. Keep README detailed, just reorganize sections (rejected: doesn't address discoverability)
- B. Slim README to ~50 lines (pitch + install + quick-start + links), move detail to `docs/guides/` ← chosen
- C. Move everything to a docs site generator (rejected: out of scope, premature)

CLI reference generation: cobra's `doc.GenMarkdownTree` produces deterministic per-command pages. Add a `make docs` target that regenerates `docs/guides/cli-reference/`. Hand-write `docs/guides/getting-started.md`, `docs/guides/mcp-tools.md`, `docs/guides/workflow.md`.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
**Single shipment, three implementation tracks. All tracks are read-side and additive — no breaking changes.**

**Track 1 — Version surface:**
- Add `Version`, `Commit`, `BuildDate` package vars in `cmd/backlogit/main.go`, populated via `-ldflags`.
- Wire to cobra root `Version` field → enables `backlogit --version` automatically.
- Add `backlogit version` subcommand (verbose: version, commit, build date, Go version).
- Add MCP tool `backlogit_get_version` returning the same fields as a JSON object.
- Update `Makefile`/build invocations to inject ldflags (use `git describe --tags --always`).

**Track 2 — Output formatting:**
- New package `internal/cli/format/` with three renderers: `Table`, `Tile`, `JSON`.
- Each renderer implements `Render(w io.Writer, items []Item) error` over a small `Renderable` interface that read commands map their data into.
- Add `--format` persistent flag at root command, default `table`. Honor `BACKLOGIT_OUTPUT_FORMAT` env var.
- Apply to: `list`, `get`, `queue view`, `stash fetch`, `stash get`, `shipment list`, `shipment get`.
- Tile format: blank-line-separated blocks; first line is the item ID + title bolded for terminal, plain for non-tty.

**Track 3 — README restructure:**
- Slim README.md to: project pitch, install one-liner, 3-step quick start, link grid to guides.
- Create `docs/guides/getting-started.md`, `docs/guides/workflow.md`, `docs/guides/mcp-tools.md` (hand-written).
- Add `cmd/gen-docs/main.go` that calls `cobra.GenMarkdownTree` against the root command.
- Add `make docs` target running `go run ./cmd/gen-docs`, which writes to `docs/guides/cli-reference/`.
- Add CI check that `make docs` produces no diff (keeps reference fresh).

**Why bundle these three:** All three converge on user discoverability. README restructure is most useful once the new `--version` and `--format` surfaces exist — they get documented in the new guides as part of the same change. Splitting into separate shipments would force two README touch-ups.

Defaults applied without explicit operator confirmation per "let's put Shipment B through the full stage cycle" directive; plan-review and harvest stages can adjust scope.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
- **CI diff check:** Should `make docs` failure block CI, or just warn? Recommend warn first cycle, block after one stable run. Defer final decision to impl-plan.
- **Tile format for intercom:** Does the existing `agent-intercom-broadcast` `message` field have a length cap that would clip large tiles? May need truncation logic.
- **MCP version tool naming:** `backlogit_get_version` vs `backlogit_version` vs `backlogit_about` — pick during impl-plan.
- **Bold in tile format:** ANSI sequences only when `os.Stdout` is a TTY; verify against existing patterns in `internal/cli/`.
- **Folded stash entries:** This deliberation absorbs stash 979D0F63 and 842E1EE2 in addition to 68DAEC16; harvest must remove all three on completion.
