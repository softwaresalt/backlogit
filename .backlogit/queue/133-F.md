Durable fix for core.ShipShipment over-archiving (and over-closing/relocating) the covering feature when only a subset of its children is shipped (partial-feature shipment). Observed on 114-S: archived_ids included 106-F though the manifest was only [106.001-T, 106.002-T].

ROOT CAUSE — three covering-feature mutation seams in internal/core/shipment_lifecycle.go:
1. Direct status seam (:191): the featureIDs loop calls setArtifactStatus(feature, StatusDone) on every derived covering feature.
2. Archival collector seam (:292): collectArchiveCandidateIDs appends the covering feature + its linkedDeliberationIDs + descendant sweep with only an already-archived guard (no membership/terminal gate).
3. Transitive parent-status rollup (indirect): completeReleaseScope (:171/:254) marks each shipped child StatusDone via setArtifactStatus, which unconditionally calls cascadePersistedParentStatuses (:519) -> ComputeParentStatus (harness_status.go:82); when all RECORDED children are done (body-planned units invisible) the covering feature is rolled to StatusDone and relocated out of .backlogit/queue/ BEFORE seams 1/2 run.

FIX DIRECTION (deliberation Decision = Option A, explicit shipment membership): gate the two direct seams (:191, :292) on explicit manifest membership (featureID in explicitScope, resolved at :158 pre-mutation) AND neutralize the transitive rollup for non-member covering features via a narrow pre-ship status/location snapshot+restore (or a cascade-suppression variant). No new terminal-status predicate; isTerminalReleaseStatus callsites and blocking_cascade.go untouched; Markdown-authoritative reads via findArtifact.

DELIVERABLES (see plan): Unit 1a update the three existing children-only-manifest ship tests to the membership contract; Unit 1b add feature-inclusive full-feature characterization + body-planned regression (asserts status != done AND queue-dir location, not ArchivedIDs absence); Unit 2 the three-seam neutralization (code); Unit 3 check-only doctor audit; Unit 4 retire the P-015 manual workaround in .ship.agent.md Step 6.1.b for command/workflow parity.
