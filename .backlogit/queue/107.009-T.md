Test-first: this task is GATED behind the RED integration regression 107.010-T (tests/integration/docline_extension_compat_test.go), which must be observed FAILING first; this production change turns it GREEN. The current production seam CONTRADICTS the authoritative base/extension contract in TWO places, both of which this task must change: (1) internal/docline/normalize.go folds every non-contract top-level key into the docline namespace (foldUnderDocline), driven by the CLOSED contractFields set in internal/docline/policy.go; and (2) internal/docline/frontmatter.go serializes through BaseFrontmatter.ToMap(), which emits ONLY the base-contract fields plus the docline namespace — so even after the fold is removed, unknown top-level extension keys are DROPPED on serialization because BaseFrontmatter has no carrier for them. Honest scope correction: preserving unknown top-level extension keys REQUIRES a change to internal/docline/frontmatter.go (capture non-contract, non-docline top-level keys in FromMap into a carrier field on BaseFrontmatter and re-emit them unchanged at the top level in ToMap), IN ADDITION to stopping the fold in internal/docline/normalize.go. Per the authoritative contract, docline owns only the base Markdown/frontmatter contract and MUST preserve unknown top-level extension properties (e.g. the backlogit-owned size, size_source, size_ruleset_version) unchanged IN PLACE at the top level, validating/normalizing only its own base fields, and MUST NOT relocate extension fields under docline. Update the contradictory existing unit tests in internal/docline/normalize_test.go (TestNormalize_ContractSurfaceHoldsOnlyContractKeys and TestNormalize_FoldsLegacyTypeUnderDocline, which currently assert every top-level key is a contract field / that non-contract keys are folded away) to assert top-level pass-through. internal/docline/policy_test.go is NOT changed: TestIsContractField remains valid against current HEAD because the closed contract set still governs which base fields docline normalizes and no longer governs relocation of unknown keys. The size-extension regression proof (size/size_source/size_ruleset_version stay top-level, byte-unchanged, idempotent, never validated/defaulted/emitted, survive a lint/migration round-trip) lives in the RED task 107.010-T and is out of this task's changed-file set. Ownership stays explicit: top-level pass-through is DOCLINE base-contract behavior; size semantics (validation, defaults, provenance, composition) remain BACKLOGIT-owned and are out of scope here.
