GUARD-SCRIPT specification (`scripts/check-line-endings.ps1` — fail-closed, non-vacuous over a FIXED tracked set): the script enumerates a FIXED, committed set of tracked `*.go` and `*.json` paths via `git ls-files -- '*.go' '*.json'` (NOT an attribute-driven `git ls-files --eol` query, which would go vacuous if `.gitattributes` were deleted or narrowed). It asserts THREE properties INDEPENDENTLY and exits nonzero (fail-closed) if ANY assertion fails, echoing the offending paths:
  1. `.gitattributes` CONTRACT: the required `.gitattributes` rules are present and normalize `*.go`/`*.json` (and the golden JSON) to `eol=lf`; a missing/removed/narrowed attribute is a hard failure, so deleting attributes cannot make the guard pass.
  2. WORKING-TREE EOL: every enumerated path's on-disk bytes contain NO `\r\n` (no CRLF, no mixed).
  3. STORED/INDEX BLOB normalization: each enumerated path's index/committed blob is LF-normalized independently of `.gitattributes` (hash the LF-normalized bytes and compare to the stored blob), so an LF worktree over a CRLF-committed blob still fails.
Because the three assertions are independent, narrowing or deleting `.gitattributes` FAILS assertion 1 rather than silently disabling assertions 2 and 3. The script is designed to be invoked both locally and by the U14 CI workflow.
