Plan unit **U10**. Runtime verification of the **refusal** path in a scratch workspace.

Files: `.gitignore` (ignore rule for the scratch directory). No product code changes.

**Scope note.** The acceptance and restore half moved to **147.026-T** (U10b). Five verification steps in one task exceeded the four-scenario limit, and the restore step also carried the contradiction described below. This task owns the scratch workspace, the ignore rule, the binary under test, and the live-corpus guard, so 147.026-T inherits them rather than re-declaring them.

**Scratch containment (Constitution IV).** The scratch workspace is created **inside the repository working tree** at `docs/scratch/checkpoint-verification/` — never `%TEMP%`, never outside the cwd. Assert the resolved path is repo-root-relative **before the first write**, add the directory to the freeze-scope declaration, and add the `.gitignore` rule: there is no `docs/scratch/` rule today, and while `*.exe` already covers the built binary the copied fixtures are not covered.

**Binary under test.** Build from the branch HEAD **with the repository's own version ldflags** — the `LDFLAGS` variable in `Makefile:5-8`, whose shape the release workflow reproduces at `.github/workflows/release.yml:99-107`:

```text
go build -ldflags "-X github.com/softwaresalt/backlogit/internal/version.Version=verify-<short-sha> -X github.com/softwaresalt/backlogit/internal/version.Commit=<short-sha> -X github.com/softwaresalt/backlogit/internal/version.BuildDate=<rfc3339>" -o docs/scratch/checkpoint-verification/backlogit-verify.exe ./cmd/backlogit
```

where `<short-sha>` is `git rev-parse --short HEAD`, matching the Makefile's `COMMIT` derivation. Then assert that `docs/scratch/checkpoint-verification/backlogit-verify.exe version --format json --no-update-check` reports a `commit` field **equal to that `<short-sha>`**. The flags are exact: `--format json` is the JSON selector (`internal/cli/version_cmd.go`) — there is no `--json` flag — and `--no-update-check` suppresses the remote release lookup so the assertion is hermetic. A plain `go build ./cmd/backlogit` leaves `internal/version.Version` at its `DevVersion` default with an **empty** commit and proves nothing. The pinned repo-root `backlogit.exe` predates the change and must not be used.

**Execution contract (PR #377 cycle 16 — mandatory, fail-closed).** Every command in this task MUST:

1. run under an explicit **operator approval batch** obtained **immediately before execution** (risky action A4c), naming the files and the directory it will touch — never a single approval taken once at plan time
2. bind to the canonical workspace with `--cwd docs/scratch/checkpoint-verification` and pass **bare filenames**, never paths, logging the resolved storage root before the first mutating verb
3. display, per file, **before and after each step**: the bare `filename`, its SHA-256 `hash`, its classified `state` (`valid` / `conforming` / `needs_quarantine`), and the `destination` path the step will write or move to
4. take a **pre-run byte copy (preimage)** of every fixture a mutating verb will touch, as a precondition of the approval request
5. **assert the destination is absent** before any write or move and refuse to clobber an occupied destination, matching the shipped `moveNoReplace` semantics
6. **fail closed**: a destination outside the bound root, a missing preimage, an occupied destination, an unclassifiable state, or a missing approval is a **halt**, not a warning and not a retry

**The live corpus is evidence, never a fixture and never a target.** The nine live legacy checkpoints under `.backlogit/checkpoints/` MUST NOT be used as verification fixtures and MUST NOT be mutated by any verb. Copy representative bytes into the scratch workspace instead. The only operation this task performs against the live directory is a read-only SHA-256 enumeration before and after the whole run.

Verify end to end, in the scratch workspace:

1. **Read verdict** — `list` reports `needs_quarantine: true` with a paste-runnable, POSIX-safe remediation command (see 147.011-T for the shell-contract rationale; PowerShell-safety for arbitrary accepted filenames is not claimed), and `get` reports `conforming: false` with a `non_conforming_fields` list naming the offenders for the same fixture
2. **Refusal** — `resolve` refuses and `abandon` refuses, both naming quarantine; the fixture is byte-unchanged after both refusals
3. **Quarantine accept** — `quarantine` accepts and archives the bytes verbatim (byte-identical comparison against the pre-quarantine preimage)

**Teardown is deferred to 147.026-T and MUST NOT run here** (PR #377 Copilot review cycle 4). 147.026-T inherits this workspace — the branch-built `backlogit-verify.exe`, the copied fixtures, the preimages, and the quarantine archive its step 2 inspects — so tearing the directory down at the end of this task would destroy that task's inputs. This task hands the directory over intact. Teardown stays `ActionRisk: destructive` (A4b) requiring explicit operator approval immediately before execution at the point 147.026-T performs it; if approval is withheld the directory stays in place and is recorded as a cleanup follow-up. Principle VII carries **no** documented deviation for this — cycle 16 converted both cycle-15 deviation rows into approval obligations.
