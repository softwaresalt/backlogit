# Shipment shipped-event audit-log completeness

## Problem Frame

<!-- BEGIN:problem-frame -->
A shipment can persist archived_status: shipped while its append-only JSONL log omits the shipment_status_changed: shipped event. Root cause: moveShipmentStatusWithHeadGuard (internal/core/shipment.go) emits the audit event via the best-effort appendItemEvent (fire-and-forget, warn-and-return on failure) after persisting the status, and ShipShipment then archives regardless, yielding archived_status: shipped with no shipped event. Observed from autoharness stash 84D8E6AB / shipment 114-S. Baseline reconciliation (2026-08-17, review-fix cycle 3): current source has since introduced the error-returning per-ws append seam (ws.shipmentEventAppend) that returns shipped-append failure via shipmentEventAppendError from moveShipmentStatusWithHeadGuard, so the shipped transition is no longer fire-and-forget. The remaining planned work is the failure taxonomy and rollback around that seam (class-aware NotApplied vs Indeterminate handling, untagged safe-default plus clean pre-append lock-acquisition NotApplied tagging, synchronous under-lock covering-feature rollup restoration with a MutationPartialError return) plus the report-only doctor audit and its CLI/MCP surfaces and parity. The best-effort description above is retained as the original observed root cause for provenance.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A: Reuse F5 core.MutationEnvelope to wrap the whole status-to-archival path (high blast radius on the hardened ShipShipment closure). B: Error-returning shipped-event append inside the existing envelope, classified per the two-class durable-write contract (NotApplied -> compensate via existing snapshot rollback; Indeterminate -> halt archival + surface reconciliation error), thread EventWriter for parity, add report-only doctor audit. C: Swap to error-returning and always roll back (unsafe: violates the two-class contract for indeterminate writes).
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B. Surgical integration reusing appendItemEventErr (gate_evidence.go), snapshotShipArtifacts/restoreShipArtifacts, MutationPartialError classes, and the DoctorOptions pattern. Completes 140-F Unit 1 (deferred from 106.033-T) without rewrapping the hardened closure. Full deliberation: docs/decisions/2026-08-16-shipment-shipped-event-audit-log-deliberation.md.
<!-- END:chosen-direction -->
