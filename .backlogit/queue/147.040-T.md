Plan unit **U17** (partition 4). Corrects the `%v` validation wrap on the abandon path.

Files: `internal/core/checkpoint_disposition.go`, `internal/core/checkpoint_disposition_test.go`.

Created in PR #377 cycle 17 to close gate finding **H7**. `AbandonCheckpoint` wraps its validation failure as `fmt.Errorf("%w: %v", ErrCheckpointUseQuarantine, valErr)` (`internal/core/checkpoint_disposition.go:~76-81`). The `%v` verb drops the `ErrCheckpointInvalid` sentinel `ValidateCheckpoint` returns, so `errors.Is(err, ErrCheckpointInvalid)` is false on a path this plan **already touches** in 147.008-T / U4 and 147.037-T / U14.

Change the verb to multi-`%w`: `fmt.Errorf("%w: %w", backlogiterrors.ErrCheckpointUseQuarantine, valErr)`. Go 1.20+ supports multiple `%w` verbs and the module is Go 1.24, so both sentinels stay traversable - the same idiom Q2 already requires of `ResolveCheckpoint`.

Cycles 1-16 recorded this as a documented Principle I deviation on "pre-existing" grounds. That escape hatch closes the moment 147.008-T and 147.037-T edit the same function.

**Test-lifecycle classification**: red harness plus one green-step guard. One scaffolded `TestU17_` function fails because `errors.Is(err, ErrCheckpointInvalid)` is false against the shipped `%v` wrap; the message-text assertion is green on landing and is committed with the implementation as `TestU17Guard_MessageTextPreserved`.

Red verification: `go test -count=1 -run '^TestU17_' ./internal/core`.
