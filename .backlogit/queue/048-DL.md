## Problem Frame

<!-- BEGIN:problem-frame -->
The telemetry system currently groups metrics by raw branch name (`--by branch`),
producing one row per literal branch string. Operators need two capabilities:

1. **Branch-level metrics as the base aggregation** — aggregate all sessions for a
   single branch into a coherent profile showing total tokens, sessions, duration,
   model mix, and task count.

2. **Branch enrichment from multiple data sources** — combine copilot session-level
   telemetry with git data (PR number, commit count) and backlogit archive data
   (linked shipment, feature, task count) to build a rich branch profile.

3. **Branch-type classification** — classify branches by type (feature, chore, stage,
   post-merge, spike) to enable roll-up aggregation comparing workflow phases.

The backlogit workflow produces distinct branch types with consistent naming:
- `feature/*` — Ship execution of shipment items
- `chore/stage-*` — Stage planning commits  
- `chore/*` — review fixes, housekeeping
- `post-merge/*` — closure, docs, telemetry after merge
- `ship/*` — Ship execution variant

Each branch can be further attributed by linking to backlogit artifacts (shipment ID,
feature ID) and git metadata (PR number). This enrichment turns raw session data into
an operational dashboard of workflow cost and efficiency.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
### Option A: Report-time enrichment (no schema change)

Add `DeriveBranchType` classifier and a new `telemetry branch` command that:
1. Groups sessions by branch name (base aggregation)
2. Derives branch type from prefix
3. Enriches with git PR data via `git log --merges`
4. Enriches with backlogit artifact links via branch name pattern matching + archive lookup
5. Renders per-branch and per-branch-type summaries

The CLI layer orchestrates data joining. The telemetry package stays pure.

**Pros**: Zero schema change, rich output, backward compatible, YAGNI-safe.
**Cons**: Enrichment repeated on every report run; git/backlogit lookups add latency.

### Option B: Harvest-time enrichment (store in JSONL + SQLite)

Add `BranchType`, `ShipmentID`, `FeatureID`, `PRNumber` fields to session records.
Populate at harvest time.

**Pros**: Fast queries, no runtime git calls.
**Cons**: Schema migration, backfill complexity, couples harvest to git/backlogit state.

### Option C: Hybrid — classify at harvest, enrich at report

Store `branch_type` at harvest (cheap, stable). Enrich with git/backlogit at report time
(dynamic, always current).

**Pros**: Best of both.
**Cons**: Still requires schema migration for branch_type field.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
**Option A: Report-time enrichment.** This follows YAGNI — the immediate need is a rich
branch metrics report. The enrichment data (git PRs, backlogit artifacts) is always
available at report time. No schema migration needed.

Architecture:
- `telemetry` package: `DeriveBranchType` classifier, `BranchProfile` struct, 
  `AggregateBranches` function (session → branch grouping)
- CLI layer: git enrichment via `os/exec`, backlogit enrichment via archive file lookup,
  passes enriched data to renderer
- Reporter: renders `[]BranchProfile` in table/json/markdown
- Trend command: add `--by branch-type` for roll-up aggregation

Classification rules (applied in order):
- `feature/` prefix → "feature"
- `chore/stage-` prefix → "stage"  
- `ship/` prefix → "ship"
- `post-merge/` prefix → "post-merge"
- `chore/` prefix → "chore"
- `main` or `master` → "main"
- empty string → ""
- fallback → "other"

Enrichment sources:
- Git: `git log --merges --oneline` → parse PR # from "Merge pull request #N from owner/branch"
- Backlogit: parse branch name for IDs (e.g. `feature/057-f-*` → 057-F), look up archive
<!-- END:chosen-direction -->
