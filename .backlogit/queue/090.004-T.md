Reduce the cost of the Docline frontmatter gate, which currently sets up Go and runs make docs-lint on every CI invocation. Keep the gate reliable for documentation and backlog changes.

<!-- BEGIN:acceptance-criteria -->
* Docline frontmatter gate uses change-gating and/or a lighter execution path that avoids full Go setup and build when safe.
* The Docline frontmatter gate required status check still reports success on every PR, including docs-only and backlog-only PRs.
* The gate is fail-safe: documentation/frontmatter-relevant changes and unknown path classes run the lint rather than being silently skipped.
* Heavy work is gated at the job or step level so branch protection never waits on an absent check.
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Keep the check context name Docline frontmatter gate unless the operator updates PR-Review/main branch protection. Prefer reusing the existing change detector over adding workflow-level paths-ignore.
