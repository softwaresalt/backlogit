Plan unit **U8c**. Make the CLI read surface report what 147.012-T computes.

Files: `internal/cli/checkpoint.go`, `internal/cli/checkpoint_test.go`.

`newCheckpointGetCmd` (`internal/cli/checkpoint.go:180-210`) calls `events.GetCheckpoint` and prints a **literal** `"valid": true` with no conformance field, so the CLI read surface would keep answering the superseded question after 147.012-T lands. Call `events.GetCheckpointResult` and project `valid`, `conforming`, `needs_quarantine`, and `remediation_command` from the returned result. The hardcoded `"valid": true` is removed, not shadowed.

**Scope note.** Split out of 147.015-T (U8) during PR #377 Copilot review cycle 4. 147.015-T owns the `resolve` / `abandon` refusal surfacing and nothing else; a `get` projection is a read contract, not a refusal rendering, and folding it back in would make a fourth scenario there, breaching the four-scenario limit. This unit is the CLI twin of 147.022-T (U6c) and takes the same shape.

Without this task, 147.016-T's `valid-but-non-conforming` parity row — "CLI `checkpoint get` → the same" — would describe behaviour no task implements.

**Schema-invalid documents keep their existing refusal.** 147.012-T returns `ErrCheckpointInvalid` unwrapped from `GetCheckpointResult` and the CLI already exits non-zero on that error, so `get` on a legacy file surfaces the pre-existing validation-class refusal rather than a disposition code. This task **pins** that behaviour rather than changing it, exactly as 147.022-T does for the MCP read surface.

<!-- BEGIN:acceptance-criteria -->
- A valid-but-non-conforming file reports `valid: true`, `conforming: false`, `needs_quarantine: true`, and a non-empty `remediation_command`
- A conforming file reports `conforming: true`
- A schema-invalid file exits non-zero with the pre-existing validation-class refusal rather than a success payload asserting validity — asserted against the command's actual output, not a literal
- The literal `"valid": true` no longer appears in `newCheckpointGetCmd`
- Expected red: cases 1 and 2 fail; case 3 is a declared regression guard pinning the shipped read contract
