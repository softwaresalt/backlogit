Plan unit **U8c** (partition 4). CLI `checkpoint get` projects the conformance verdict.

Files: `internal/cli/checkpoint.go`, `internal/cli/checkpoint_test.go`.

`newCheckpointGetCmd` (`internal/cli/checkpoint.go:180-210`) calls `events.GetCheckpoint` and prints a literal `"valid": true` with no conformance field. Call `events.GetCheckpointResult` and project `valid`, `conforming`, `needs_quarantine`, `remediation_intent`, and `non_conforming_fields`; the hardcoded literal is removed, not shadowed.

**Cycle-17 shapes.** `non_conforming_fields` is copied from `CheckpointReadResult.NonConformingFields` unchanged - already bounded and raw via 147.030-T / U1b through 147.012-T / U6b - so CLI and MCP cannot render different offender lists for the same file. `remediation_intent` is the structured record, not a command; the bound operator command block is owned by 147.039-T / U16.

This is the CLI twin of 147.022-T / U6c. It is separate from 147.015-T / U8 because a read projection is a different contract from a refusal rendering, and U8 already carries three scenarios.

**Schema-invalid documents keep their existing refusal**: `GetCheckpointResult` returns `ErrCheckpointInvalid` unwrapped and the CLI already exits non-zero on it. This task pins that behaviour rather than changing it.

Red verification: `go test -count=1 -run '^TestU8c_' ./internal/cli`.
