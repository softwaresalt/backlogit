Trust-anchor mutation SUCCESSFUL-path write-outcome taxonomy + marker-protected sequenced-commit protocol (behavior). Carved from 168.005-T (cycle-1 items 3/9); rewritten per cycle-2 item 4 to resolve the atomicity contradiction. There is NO cross-file atomicity claim: a config file + status + separate audit log cannot be atomically committed on a filesystem, so this task defines ONE implementable marker-protected sequenced-commit protocol. Protocol (fixed order, each step fsynced): (1) write a durable in-progress RECOVERY MARKER recording the intended mutation; (2) apply the config+status mutation; (3) persist the audit event; (4) clear the recovery marker. Write outcomes: a failure BEFORE step 2 yields ErrWriteNotApplied (state definitively unchanged, retry-safe; recovery idempotently clears any orphan marker); a failure AT/AFTER step 2 and BEFORE step 4 (state changed but audit or marker-clear incomplete) yields ErrWriteIndeterminate (never a blind state retry; the recovery pass rolls forward from the marker: re-persists the audit if missing, then clears the marker). Recovery visibility: an outstanding marker is surfaced by doctor/recovery. Denied-mutation audit-failure semantics are owned by 168.019-T. Domain: core (internal/core). TDD: RED behavior harness first with injected failures, observed failing. Depends on 168.005-T, 168.012-T. Executable scenarios (3): (a) an injected failure before the mutation returns ErrWriteNotApplied with no state change and no orphan marker after recovery; (b) an injected failure after the mutation but before audit-persist returns ErrWriteIndeterminate with the recovery marker present; (c) the recovery pass reconciles an indeterminate marker idempotently (re-persists the audit, clears the marker) with no double-apply. Build/test: go build ./cmd/backlogit; go test ./internal/core/ -run TestTrustAnchorWriteOutcomeRecovery. AC: (1) RED test first, observed failing; (2) ErrWriteNotApplied on pre-mutation failure (state unchanged); (3) ErrWriteIndeterminate on post-mutation/pre-audit failure with marker present; (4) recovery reconciles the marker idempotently and clears it; (5) denied-path audit-failure delegated to 168.019-T; (6) tests GREEN.
