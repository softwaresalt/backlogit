Trust-anchor mutation write-outcome error taxonomy + durable recovery marker (behavior). Carved from 168.005-T per plan-review cycle-1 item 3 (deterministic mutation + durable audit semantics) and item 9 (scenario count). Defines the write-outcome contract for the 168.005-T mutation transaction. Ordering: (1) a durable in-progress recovery marker is written before the config+status mutation; (2) config+status mutation and the durable audit event persist atomically; (3) the recovery marker clears only after the audit event is durably persisted. Error taxonomy: ErrWriteNotApplied = the mutation is definitively NOT applied (validation/pin rejection or a failure before any durable change) and is SAFE TO RETRY; ErrWriteIndeterminate = the mutation MAY have partially applied (failure after marker write but before audit persist) and is NOT safe to blind-retry -> requires compensation/recovery. Retry/compensation boundary: ErrWriteNotApplied is retryable; ErrWriteIndeterminate triggers a recovery/doctor pass, never a blind retry. Recovery visibility: a residual recovery marker makes an indeterminate write visible to the recovery pass. Domain: core. TDD: RED behavior harness first with injected failures. Depends on 168.005-T. Executable scenarios (3): (a) an injected pre-mutation failure yields ErrWriteNotApplied (no marker, retryable); (b) an injected failure between mutation and audit-persist yields ErrWriteIndeterminate with a residual recovery marker; (c) the recovery pass detects and surfaces the residual marker. Build/test: go build ./cmd/backlogit; go test ./internal/core/ -run TestTrustAnchorMutationWriteOutcome. AC: (1) RED tests first; (2) ErrWriteNotApplied returned and retryable on a definitively-unapplied write; (3) ErrWriteIndeterminate returned with a durable recovery marker when the outcome is uncertain; (4) recovery pass detects the residual marker; (5) tests GREEN.
