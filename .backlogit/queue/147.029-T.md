Plan unit **U7e**. `domainError` safety-net mappings — the three disposition/validation sentinels that are genuinely absent from `domainError` (`internal/mcp/errors.go:148`).

Files: `internal/mcp/errors.go`, `internal/mcp/checkpoint_disposition_test.go`.

Split from 147.013-T (U7, scenario 2) and 147.025-T (U7d, scenario 4) to satisfy the non-negotiable `<4 scenarios` and `<3 files` width limits.

`domainError` is the fallback error surface for MCP handlers that carry no filename. It already maps `ErrCheckpointInvalid` → `validation_failed` (grouped with `ErrValidation` and `ErrCheckpointCorrupt`) and has a dedicated `ErrCheckpointUnknownField` case. Three sentinels are genuinely absent:

1. **`ErrCheckpointUseQuarantine`** — should map to `checkpoint_use_quarantine`. Currently falls to `default: InternalError`.
2. **`ErrCheckpointNonConforming`** — should map to `checkpoint_non_conforming`. Currently falls to `default: InternalError`.
3. **`ErrCheckpointCannotResolveAbandoned`** — should map to `validation_failed` (consistent with `ErrCheckpointInvalid` and `ErrCheckpointCorrupt` as a validation-class refusal: the checkpoint exists and is parseable but resolve is refused because it has been administratively abandoned). **Genuine red delta**: before this unit, `domainError` has no explicit case for this sentinel and falls through to `default: InternalError`.

Add all three mappings to `domainError` and update the mapping-table doc comment (`internal/mcp/errors.go:127-144`) with the three new rows.

**Scope note (domainError ownership).** The `domainError` mapping for `ErrCheckpointUseQuarantine` and `ErrCheckpointNonConforming` was originally scoped to 147.013-T / U7 (item 3 of U7's change list). The `ErrCheckpointCannotResolveAbandoned` → `validation_failed` mapping was originally scoped to 147.025-T / U7d. Both are moved here because they are the same function in the same file and keeping them in their original tasks pushed those tasks past mandatory width limits. 147.013-T's item 3 and 147.025-T's scenario 4 are replaced by references to this unit.

<!-- BEGIN:acceptance-criteria -->
- `domainError` maps a **realistically wrapped** `fmt.Errorf("%w: %w", ErrCheckpointUseQuarantine, fmt.Errorf("%w: %v", ErrCheckpointInvalid, errSample))` to `checkpoint_use_quarantine` and **not** to `validation_failed` — this fails if the new rows are appended after the generic validation case
- `domainError` maps a wrapped `*CheckpointNonConformingError` to `checkpoint_non_conforming`, recovering the typed error through `errors.As`
- `domainError` maps a wrapped `ErrCheckpointCannotResolveAbandoned` to `validation_failed` rather than `internal`
- The three new cases are placed **before** the combined `ErrValidation` / `ErrInvalidLinkType` / `ErrTelemetrySourceMissing` / `ErrCheckpointInvalid` / `ErrCheckpointCorrupt` case, and the mapping-table doc comment lists them in that order
- Expected red: all three fail — `domainError` currently falls to `default: InternalError` for each; case 1 additionally fails on any mis-ordered insertion
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
**Reachability is proven, not assumed (cycle-15 audit).** `internal/mcp/errors.go:148-200` carries no explicit case for any of the three sentinels; all reach `default: InternalError`. After 147.025-T / U7d, `handleResolveCheckpoint` reroutes only errors matching `QuarantineIsRemedy`, and `ErrCheckpointCannotResolveAbandoned` does **not** match that predicate, so `internal/mcp/tools.go:1224` still hands it to `domainError` and it still surfaces as a 500 on a shipped agent-facing path. Row 3 is a live defect; rows 1 and 2 are the safety net for any handler that carries no filename and therefore cannot use `checkpointDispositionError`.

**Ordering is a correctness constraint, not style.** 147.006-T / U3 wraps its refusal as `fmt.Errorf("%w: %w", ErrCheckpointUseQuarantine, valErr)` where `valErr` already wraps `ErrCheckpointInvalid`, so one error satisfies **both** `errors.Is` checks. Inserted after the generic validation case, the `checkpoint_use_quarantine` row would be permanently shadowed and would never fire — a mapping table that looks complete and changes nothing. Insert all three ahead of that case.

Test against wrapped errors only. A bare-sentinel test passes under either ordering and would not detect the shadowing defect above.
