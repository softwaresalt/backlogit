Plan unit **U7e**. The one `domainError` mapping that is genuinely reachable and genuinely missing (`internal/mcp/errors.go:148`).

Files: `internal/mcp/errors.go`, `internal/mcp/checkpoint_disposition_test.go`.

**Narrowed in PR #377 cycle 16 from three mappings to one.** A reachability audit against current source removed two rows that no live path can reach:

| Row | Sentinel | Reachable at `domainError`? | Cycle-16 disposition |
|---|---|---|---|
| 1 | `ErrCheckpointUseQuarantine` | **No** | Removed |
| 2 | `ErrCheckpointNonConforming` | **No** | Removed |
| 3 | `ErrCheckpointCannotResolveAbandoned` | **Yes** | Retained |

Only two checkpoint handlers route through `domainError`: `handleGetCheckpoint` (`internal/mcp/tools.go:1205`) and `handleResolveCheckpoint` (`:1224`). `handleAbandonCheckpoint` (`:1279`) and `handleQuarantineCheckpoint` (`:1310`) already use `checkpointDispositionError`. Get never emits either removed sentinel — 147.012-T / U6b returns `ErrCheckpointInvalid` unwrapped for a schema-invalid document and a *result* carrying `conforming: false` for a non-conforming one. Resolve reroutes every `QuarantineIsRemedy` match once 147.025-T / U7d lands. Rows 1 and 2 were justified as a "safety net for any handler that carries no filename"; no such handler exists, and a mapping no path can reach is a green-looking table entry that proves nothing. If such a handler is ever added, its own unit adds its own mapping.

**The retained row is a live defect.** `QuarantineIsRemedy` does not match `ErrCheckpointCannotResolveAbandoned`, so after 147.025-T / U7d it still falls through to `domainError` at `internal/mcp/tools.go:1224` and still surfaces as `default: InternalError` — a 500 on a shipped agent-facing path. Map it to `validation_failed`, consistent with the neighbouring `ErrCheckpointInvalid` and `ErrCheckpointCorrupt` rows: the document exists and parses, and resolve is refused because of its administrative state.

Add the case to `domainError` and the corresponding row to the mapping-table doc comment (`internal/mcp/errors.go:127-144`).

**The cycle-15 mandatory-ordering constraint is withdrawn with rows 1 and 2.** That rule existed because 147.006-T / U3 wraps its refusal as `fmt.Errorf("%w: %w", ErrCheckpointUseQuarantine, valErr)` where `valErr` already wraps `ErrCheckpointInvalid`, so an appended `checkpoint_use_quarantine` row would have been permanently shadowed by the combined `ErrValidation` / `ErrCheckpointInvalid` / `ErrCheckpointCorrupt` case at `internal/mcp/errors.go:188-193`. That hazard belonged to row 1, which no longer exists. `ErrCheckpointCannotResolveAbandoned` is a bare `errors.New` value (`internal/errors/checkpoint_errors.go:59-64`) that wraps nothing, so it can collide with no other case and its placement is unconstrained. Group it with the other checkpoint rows for readability.

Width: 2 files, 1 scenario. A task below the four-scenario ceiling is compliant — the ceiling is a maximum, not a target.

Red verification: `go test -count=1 -run '^TestU7e_' ./internal/mcp`.
