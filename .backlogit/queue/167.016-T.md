Transactional SNAPSHOT/ROLLBACK primitive (split out of 167.008 per 2-hour/single-responsibility rule). A self-contained, reusable primitive that: (1) SNAPSHOTS the shipment archive file BYTES AND the COMPLETE SQLite index row (ALL items columns, not just custom_fields/updated_at) before mutation - because UpsertItem is INSERT OR REPLACE over every column (upsert_projection.go:53-109), restoring a partial snapshot would overwrite pre-existing title/status/labels/etc.; snapshot the FULL pre-call row so the restore is exact; (2) RESTORES both on rollback - the FILE restore MUST go through the SAME 167.006 handle-bound atomic writer (NOT a path-based write, which would reopen the archive-directory symlink-swap/escape race the transaction closes), with rollback outcome classification; UpsertItem(snapshot) when a pre-write row existed, else a NON-CASCADING delete of ONLY the items row (NOT db.DeleteItem, which delegates to DeleteItemCascade and would ALSO remove item logs/events, dependencies, links, stash links, and commit links - queries.go:346-377 - destroying valid auxiliary index state; use a single-row delete of just the items table row, preserve original row-presence; NEVER synthesize a row during rollback); surfaces a rollback failure as indeterminate.
