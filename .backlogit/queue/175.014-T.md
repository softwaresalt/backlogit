Persistent CI line-ending guard, split out of U1 so U1 stays a purely content-identical (EOL-only) renormalization. This unit OWNS the one genuine content change to `.github/workflows/ci.yml` (the guard step) — an ownership that would otherwise contradict U1's "line-ending-only churn" invariant. Single-domain (CI/config). Depends on U1 (`175.001-T`): the guard is authored only after U1's renormalization has landed. Feeds the U12 terminal verification sink.

STAGE-TIME CONSTRAINT: do NOT edit `.github/workflows/ci.yml` during staging. This is a planning task that authorizes Ship to add the guard at execution time. Stage's role boundary forbids workflow edits.

Guard specification (working-tree EOL identity — resolves the persistent-guard finding):
- The CI guard MUST inspect the WORKING-TREE end-of-line state via `git ls-files --eol` and FAIL the job when any tracked `.go`/`.json` (or other `eol=lf`-declared) path reports `w/crlf` or `w/mixed`. This detects re-drift on a checkout even when the index is clean.
- RUNNER (required): the working-tree `git ls-files --eol` guard MUST run on a `windows-latest` runner, AFTER `actions/checkout`. CRLF re-drift only manifests on a Windows checkout — a Linux/`ubuntu-latest` checkout keeps LF and would report a false `w/lf` green — so the working-tree inspection is meaningful only post-checkout on Windows.
- ALWAYS-RUN (required): the checkout + working-tree guard MUST run on EVERY PR/push to protected branches and MUST NOT be conditionally skipped for docs-only or backlog-only changes. Do NOT gate it behind a `paths:`/`paths-ignore:` filter or a changed-files condition that would let a docs/backlog-only PR bypass the checkout + guard; if path-based job skipping is used elsewhere in the workflow, this guard must be explicitly exempt / always-run (e.g. a required status check that always performs the Windows checkout + `git ls-files --eol` guard). A docs/backlog-only change must still exercise the checkout and guard so line endings cannot silently re-drift.
- The index-diff content-identity check (`git add --renormalize . && git diff --cached --exit-code`, or the EOL-only normalized-blob SHA-256 comparison) is SEPARATE, complementary content-identity evidence and is NOT a substitute for the working-tree `w/*` inspection: an index-only check can pass while the checked-out working tree carries CRLF. This index/identity guard MAY run on a separate `ubuntu-latest` job and MUST stay distinct from the Windows working-tree guard.
- Declared binaries (`-text`) and `.gitattributes` are excluded from the `w/lf` assertion exactly as in U1.

Acceptance criteria:
- Scope (files): only `.github/workflows/ci.yml` (the guard step). No other file is owned by this unit.
- Guard present: a persistent CI step runs `git ls-files --eol` and FAILS on any `w/crlf` or `w/mixed` for tracked `eol=lf` text paths.
- Runner (required): the working-tree EOL guard runs on `windows-latest` AFTER `actions/checkout` (the only place CRLF re-drift is observable; a Linux checkout would false-green).
- Always-run (required): the checkout + working-tree guard is NOT skipped for docs-only/backlog-only changes — no `paths:`/`paths-ignore:`/changed-files gate may bypass it; it runs on every PR/push to protected branches (exempt/always-run if path-based skipping exists elsewhere).
- Separate index-identity evidence retained: the index-diff / renormalize-exit-code check remains as distinct content-identity evidence (may run on `ubuntu-latest`), not merged into the Windows working-tree assertion.
- Ownership honesty: the `.github/workflows/ci.yml` content change is owned here, so U1's EOL-only content-identity proof does NOT need to (and must not) account for it; U1 touches no workflow content.
- Depends on U1 (`175.001-T`): guard is authored after renormalization lands; feeds U12 (`175.012-T`) terminal verification.
- No behavior change beyond adding the guard step; existing CI jobs still pass.
