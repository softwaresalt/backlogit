WORKFLOW specification (`.github/workflows/line-endings.yml` — integration of the U40 guard):
- TRIGGERS: `on: { pull_request: { branches: [main] }, push: { branches: [main] } }`. Both PR and protected-branch push are covered so CRLF re-drift landing via a direct push to `main` is caught. No `paths:`/`paths-ignore:` filter at the trigger level.
- CI-SECURITY (must match current repository convention, proven against ci.yml):
  - `permissions: { contents: read }` at workflow level (least privilege).
  - `actions/checkout` pinned to the SAME full commit SHA the repository already uses: `actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683 # v4.2.2`, with `with: { persist-credentials: false }`.
  - `concurrency: { group: line-endings-${{ github.ref }}, cancel-in-progress: true }`.
- JOB: a SINGLE always-run job on `runs-on: windows-latest` with NO `needs:` gate, NO changed-files/`needs.changes` condition, and NO `paths` filter anywhere. Steps: `actions/checkout` (pinned, persist-credentials:false) then a step that INVOKES `pwsh scripts/check-line-endings.ps1` (the U40 guard). Because it is a standalone workflow with no change-detection job, a docs-only or backlog-only PR — or a direct push — cannot skip it. The guard runs on `windows-latest` AFTER checkout (the only place CRLF re-drift is observable; a Linux checkout would false-green).
