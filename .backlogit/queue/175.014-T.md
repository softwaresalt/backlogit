Guard specification (working-tree EOL identity — resolves the persistent-guard finding):
- The CI guard MUST inspect the WORKING-TREE end-of-line state via `git ls-files --eol` and FAIL the job when any tracked `.go`/`.json` (or other `eol=lf`-declared) path reports `w/crlf` or `w/mixed`. This detects re-drift on a checkout even when the index is clean.
- RUNNER (required): the working-tree `git ls-files --eol` guard MUST run on a `windows-latest` runner, AFTER `actions/checkout`. CRLF re-drift only manifests on a Windows checkout — a Linux/`ubuntu-latest` checkout keeps LF and would report a false `w/lf` green — so the working-tree inspection is meaningful only post-checkout on Windows.
- ALWAYS-RUN (required) — concrete ownership given the CURRENT `.github/workflows/ci.yml`, which triggers on `pull_request` ONLY (no `push`) and skips the Windows checkout for docs/backlog-only changes via `needs.changes.outputs.code == 'false' && needs.changes.outputs.plugin_bundle == 'false'` step conditions. To make the guard run on the relevant PUSH and PR events AND be unskippable by changed-file conditions, U14 owns, within the SAME workflow file, these coordinated changes:
    1. TRIGGER: add a `push:` trigger for protected branches (`main`) alongside the existing `pull_request:` trigger, so a direct push to a protected branch also exercises the checkout + guard. Reconcile the workflow's existing header comment ("PR-only validation removes duplicate push-to-main runs"; "Do not add trigger-level paths filters"): the EOL guard is INTENTIONALLY push+PR and always-run — it is exempt from the PR-only rationale because CRLF re-drift can land via a direct push, not only via a PR.
    2. JOB: add a DEDICATED always-run Windows guard job modeled on the existing always-run `md-lint` / `topology-check` jobs — NO `needs: changes`, NO `paths:`/`paths-ignore:` filter, and NO changed-files/`needs.changes` skip condition on its checkout or guard steps — that runs `actions/checkout` then the `git ls-files --eol` working-tree guard on `windows-latest`. The existing scoped `test-windows` job (167.013-T) is left UNCHANGED; the EOL guard is a SEPARATE, always-run job so a docs/backlog-only PR (or a direct push) still performs the Windows checkout + guard.
  A docs/backlog-only change — via PR or push — must still exercise the checkout and guard so line endings cannot silently re-drift.
- The index-diff content-identity check (`git add --renormalize . && git diff --cached --exit-code`, or the EOL-only normalized-blob SHA-256 comparison) is SEPARATE, complementary content-identity evidence and is NOT a substitute for the working-tree `w/*` inspection: an index-only check can pass while the checked-out working tree carries CRLF. This index/identity guard MAY run on a separate `ubuntu-latest` job and MUST stay distinct from the Windows working-tree guard.
- Declared binaries (`-text`) and `.gitattributes` are excluded from the `w/lf` assertion exactly as in U1.
