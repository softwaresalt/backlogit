Plan unit **U10b**. Runtime verification of the **acceptance** path, **quarantine evidence integrity**, and the **recovery sweep**.

Files: none. No product code changes and no repository file changes — this task runs entirely inside the scratch workspace 147.019-T created.

**Scope note.** Split out of 147.019-T (U10), which exceeded the four-scenario limit at five verification steps. This task inherits 147.019-T's scratch workspace, its repo-root containment assertion, its `.gitignore` rule, its preimages, and its branch-built `backlogit-verify.exe`; it does not re-declare them.

**Restore-and-repair step withdrawn (PR #377 cycle 16).** Cycles 4-15 carried a mandatory step 2 that executed 147.018-T / U9b's rename-aside, copy-back, and hand-repair sequence and called it proof that quarantine is recoverable. That runbook is withdrawn from 147.018-T on security grounds — it performs rename, copy, in-place rewrite, and conditional delete against a directory the codebase does not open with real-root / no-follow semantics, with no read-to-write CAS and no adversarial coverage (stash `35A27CD0`). A verification step that executes a procedure the plan no longer publishes would be verifying nothing. It is replaced by the evidence-integrity step below, which proves the property the restore step actually needed: the verbatim pre-quarantine bytes and their sidecar survive intact and cannot be clobbered. A verified automated round trip moves to `35A27CD0` with the procedure it verifies.

**The inherited workspace is a hard precondition, not a convenience.** 147.019-T deliberately does not tear the scratch directory down, because step 2 inspects the quarantine archive it produced and every step needs its branch-built binary, fixtures, and preimages. Verify those inputs are present before step 1 rather than rebuilding them; if the directory is missing, this task is blocked on re-running 147.019-T, not on rebuilding state by hand. **Teardown of `docs/scratch/checkpoint-verification/` is owned by this task** and runs only after all three steps pass. It stays `ActionRisk: destructive` (A4b) and requires explicit operator approval taken immediately before execution; if approval is withheld the directory stays in place and is recorded as a cleanup follow-up. Principle VII carries **no** documented deviation for this — cycle 16 converted both cycle-15 deviation rows into approval obligations.

**The recovery sweep runs against a scratch mirror, never the live directory.** 147.019-T requires every file under `.backlogit/checkpoints/` to be byte-unchanged. A session-start recovery sweep that "succeeds on every other file in that directory" would `resolve` the conforming active checkpoints there and rewrite them — the two requirements cannot both hold against the live corpus. The sweep therefore runs against a **copied mirror** of the live directory inside the scratch workspace: `New-Item -ItemType Directory -Force docs/scratch/checkpoint-verification/mirror/.backlogit/checkpoints` then `Copy-Item .backlogit/checkpoints/* docs/scratch/checkpoint-verification/mirror/.backlogit/checkpoints/` first, then sweep the mirror using `--cwd docs/scratch/checkpoint-verification/mirror` with bare filename arguments. The nine enumerated legacy filenames (listed in the plan) keep their names in the mirror, so the discrimination assertion is unchanged while the live bytes stay read-only.

**Execution contract.** 147.019-T's six-point contract applies unchanged to every step here, against both the scratch root and the mirror root: an operator approval batch obtained immediately before execution, `--cwd` binding with bare filenames, per-file filename / SHA-256 hash / classified state / destination display before and after each step, a preimage byte copy of every fixture a mutating verb touches, an absent-destination and no-clobber assertion, and fail-closed halting on any breach.

Verify end to end, in the scratch workspace:

1. **Acceptance is not over-refused** — a conforming active fixture is accepted by `abandon`, and a second conforming active fixture is accepted by `resolve`; the gates refuse only what they are meant to refuse
2. **Quarantine evidence integrity** — the archive 147.019-T step 3 produced is verified as a complete, no-clobber, verbatim record: the archived bytes are SHA-identical to the preimage, the `<filename>.disposition.json` sidecar names the original filename, and a **second** quarantine of a fixture carrying the same filename is refused rather than overwriting the existing evidence pair
3. **Recovery sweep discrimination** — against the scratch mirror, a session-start recovery sweep refuses **exactly** the nine enumerated legacy filenames and succeeds on every other mirrored file

Step 2 inspects the quarantine archive produced by 147.019-T step 3, which is why this task depends on it and why 147.019-T must leave the workspace standing.
