Plan unit **U10b**. Runtime verification of the **acceptance** and **restore** paths.

Files: none. No product code changes and no repository file changes — this unit runs entirely inside the scratch workspace 147.019-T created.

**Scope note.** Split out of 147.019-T (U10), which exceeded the four-scenario limit at five verification steps. This unit inherits 147.019-T's scratch workspace, its repo-root containment assertion, its `.gitignore` rule, and its branch-built `backlogit-verify.exe`; it does not re-declare them.

**The inherited workspace is a hard precondition, not a convenience** (PR #377 Copilot review cycle 4). 147.019-T deliberately does not tear the scratch directory down, because step 2 below consumes the quarantine archive it produced and every step needs its branch-built binary and copied fixtures. Verify those inputs are present before step 1 rather than rebuilding them; if the directory is missing, this unit is blocked on re-running 147.019-T, not on rebuilding state by hand. **Teardown of `docs/scratch/checkpoint-verification/` is owned by this unit** and runs only after all three steps pass. It stays `ActionRisk: destructive` (A4b) and requires operator approval; if approval is withheld the directory stays in place and is recorded as a cleanup follow-up, matching the Principle VII deviation recorded in the plan's Constitution Check.

**The recovery sweep runs against a scratch mirror, never the live directory.** 147.019-T requires every file under `.backlogit/checkpoints/` to be byte-unchanged. A session-start recovery sweep that "succeeds on every other file in that directory" would `resolve` the conforming active checkpoints there and rewrite them — the two requirements cannot both hold against the live corpus. The sweep therefore runs against a **copied mirror** of the live directory inside the scratch workspace: `Copy-Item .backlogit/checkpoints/* docs/scratch/checkpoint-verification/mirror/` first, then sweep the mirror. The nine enumerated legacy filenames (listed in the plan) keep their names in the mirror, so the discrimination assertion is unchanged while the live bytes stay read-only.

Verify end to end, in the scratch workspace:

1. **Acceptance is not over-refused** — a conforming active fixture is accepted by `abandon`, and a second conforming active fixture is accepted by `resolve`; the gates refuse only what they are meant to refuse
2. **Restore and repair** — the body-preserving repair path, entry point (b) of the single 147.018-T procedure followed by entry point (a): rename the archived bytes **and** their `.disposition.json` sidecar aside to `<filename>.quarantined-<disposition_at>` first, copy the preserved bytes back into the now-free active filename, apply the classified hand-repair moving unmodeled top-level keys under `context.legacy_top_level`, confirm `conforming: true`, then `resolve` succeeds
3. **Recovery sweep discrimination** — against the scratch mirror, a session-start recovery sweep refuses **exactly** the nine enumerated legacy filenames and succeeds on every other mirrored file

Step 2 consumes the quarantine archive produced by 147.019-T step 3, which is why this unit depends on it and why 147.019-T must leave the workspace standing.
