Plan unit **U2b**. Nested `progress` rule plus preservation of the open `context` namespace.

Files: `internal/events/checkpoint_conformance.go`, `internal/events/checkpoint_conformance_test.go`.

Recurse into every case-insensitive `progress` match using `unknownNestedProgressKeys`, reporting offending paths in the existing `progress.<key>` form. A `progress` value that is not a JSON object (null, scalar, array) is **not** a conformance failure — `ParseCheckpoint` already governs that — and must not panic.

The `context` namespace shipped open in 146-F. Sweeping it into refusal is the highest-risk regression in this plan.

**Scope note.** `unknownNestedProgressKeys` (`internal/events/checkpoint_strict.go:210-232`) decodes `progress` into a `map[string]json.RawMessage`, so duplicate and fold-variant nested keys collapse before the unknown-key diff and are invisible to this unit. That gap is closed by **147.020-T** (plan unit U2e) and must not be folded into this unit's three scenarios.
