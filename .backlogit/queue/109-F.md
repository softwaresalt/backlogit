Size, size_source, and size_ruleset_version are optional backlogit-owned extension properties layered on the docline base Markdown/frontmatter contract; they remain TOP-LEVEL in the derived backlogit contract, and docline does not calculate, default, aggregate, validate domain semantics, or emit them. Bounded investigation for PR #241 (recorded in docs/exec-plans/2026-07-14-size-estimation-feature-shipment-plan.md) found the current core.SetArtifactSize seam accepts only (id, size) with no provenance inputs and emits no event, item history is append-only JSONL with call-site-specific durability policies (LinkCommit warn-continue, AppendComment fail-surface, gate-evidence fail-closed), no canonical XS-XL aggregation ruleset exists, and size writes reach atomicfile via FindArtifactPath/WalkDir without a SafeResolve containment check. Because provenance/history atomicity, ruleset ownership, and the workspace-containment boundary remain unresolved, this feature is a genuine time-boxed architecture SPIKE composed ONLY of four sequenced research/decision tasks (109.001-T ownership + typed surface inventory; 109.002-T mutation/provenance/JSONL history durability + failure ordering + containment; 109.003-T structured-composition membership/dedup/missing/ruleset; 109.004-T CLI/MCP parity + decision synthesis + explicit proceed/pivot exit record). Each task is <=2h and independently verifiable; the spike is capped at 8h total. It contains NO implementation tasks and asserts NO implementation readiness. This spike INFORMS the blocked future-implementation placeholder 108-F (harvested from stash D7B1B33D): 108-F stays blocked and depends on 109.004-T as a necessary-but-not-sufficient gate. Any implementation may be planned, harvested, and reviewed ONLY after 109.004-T records an explicit proceed decision and a later Stage restaging. D7B1B33D traceability is preserved via 108-F.
