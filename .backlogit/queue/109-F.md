Size, size_source, and size_ruleset_version are optional backlogit-owned extension properties layered on the docline base Markdown/frontmatter contract; they remain TOP-LEVEL in the derived backlogit contract, and docline does not calculate, default, aggregate, validate domain semantics, or synthesize them (docline re-emits/serializes caller-provided extension properties at the top level when present but attaches no semantics). Bounded investigation for PR #241 (recorded in docs/exec-plans/2026-07-14-size-estimation-feature-shipment-plan.md) found the current core.SetArtifactSize seam accepts only (id, size) with no provenance inputs and emits no event, item history is append-only JSONL with call-site-specific durability policies (LinkCommit warn-continue, AppendComment fail-surface, gate-evidence fail-closed), no canonical XS-XL aggregation ruleset exists, and size writes reach atomicfile via FindArtifactPath/WalkDir without a SafeResolve containment check. Because provenance/history atomicity, ruleset ownership, and the workspace-containment boundary remain unresolved, this feature is a genuine time-boxed architecture SPIKE. It was refocused in PR #242 to split the former oversized parity/synthesis task into width-isolated <=2h evidence tasks; it is now composed ONLY of seven sequenced research/decision tasks (109.001-T base-contract/extension ownership + typed surface inventory; 109.002-T mutation/provenance/JSONL history durability + failure ordering + containment + generic rewrite-path inventory; 109.003-T structured-composition membership/dedup/missing/ruleset; 109.005-T CLI/MCP read-surface request/response/context parity inventory; 109.006-T CLI/MCP mutation validation/error parity inventory + future size_source/size_ruleset_version flag/field options; 109.007-T target inheritance-bridge + generic backlog rewrite-path preserve/drop classification + canonical size-location evidence; and 109.004-T final synthesis consuming 109.002/109.003/109.005/109.006/109.007 to select the durability policy, ratify composition, SELECT the inheritance bridge, make the canonical size-location decision, and record an explicit proceed/pivot/defer exit). Each task is <=2h and independently verifiable; the spike is capped at 14h total. It contains NO implementation tasks and asserts NO implementation readiness. The generic backlog rewrite paths are CLASSIFIED preserve/drop by 109.007-T (the current enumerated-key models.ArtifactFromFrontmatter mapping and struct-only core.WriteArtifactFile re-emit demonstrably DROP unknown top-level fields; only nested custom_fields survives, while the unknown TOP-LEVEL extension key/value graph is DROPPED on the generic route and preserved only by core.SetArtifactSize), and where the GENERIC rebuild route preserves data it preserves ONLY that NESTED custom_fields - asserted honestly as SEMANTIC/deep-value equivalence of the nested custom_fields map plus canonical, LF-normalized body equivalence and idempotent read/modify/write, NOT preservation of the top-level extension graph. On this backlog-writer path the generic reader models.ParseFrontmatter normalizes CRLF to LF across the whole document before ArtifactFromFrontmatter/WriteArtifactFile run, so a CRLF body is canonicalized to LF and its raw bytes are NOT preserved; core.WriteArtifactFile then re-serializes the frontmatter via models.SerializeFrontmatter/yaml.Marshal (which may canonicalize ordering/quotes/scalar spelling and drops comments/anchors). That LF-normalization and top-level-key drop is specific to the generic rebuild route (models.ParseFrontmatter -> ArtifactFromFrontmatter -> WriteArtifactFile). The size-mutation seam core.SetArtifactSize is the OTHER backlog-writer path and behaves oppositely: it decodes/encodes through internal/mdfront directly, preserving EXACT body bytes and the full frontmatter map including unknown top-level keys, and deliberately bypasses the generic rebuild route to avoid the drop (internal/core/artifact_size.go). So mdfront IS on a backlog-writer path (the size seam), and the canonical LF-normalized body-equivalence description applies ONLY to the generic rebuild route. Neither path preserves the frontmatter block as raw lexical bytes (both re-emit YAML). This spike INFORMS the blocked, UNMANIFESTED future-implementation placeholder 108-F (harvested from stash D7B1B33D; traceability preserved on 108-F). 108-F stays authored blocked and unmanifested (no shipment home until a later Stage restaging) and depends on THREE necessary-but-not-sufficient prerequisite gate edges, ALL of which must be named: (1) 109.004-T - this spike's explicit proceed exit decision (with the containment boundary, canonical size-location, and inheritance-bridge selection resolved); (2) 107.009-T - the docline top-level extension pass-through PRODUCTION CODEC task in shipment 095-S; and (3) 107.011-T - opening the docline base JSON schema to ACCEPT producer-owned top-level extension properties, shipment 095-S. The 107.009-T and 107.011-T base-contract edges are necessary but do NOT by themselves provide backlog-artifact round-trip preservation (backlogit's own writers must be bridged separately, per 109.007-T/109.004-T); completing all three edges only lifts dependency-based queue suppression and is outcome-agnostic. Any implementation may be planned, harvested, and reviewed ONLY after 109.004-T records an explicit proceed decision and a later Stage restaging moves 108-F blocked->active, gives it a shipment home, and re-harvests bounded <=2h units. D7B1B33D traceability is preserved via 108-F.
