Plan unit **U2c**. Duplicate and fold-variant top-level keys.

Files: `internal/events/checkpoint_conformance.go`, `internal/events/checkpoint_conformance_test.go`.

The predicate is **round-trip safety**, not merely "no unknown keys". Two top-level entries whose keys are `strings.EqualFold`-equal — including exact duplicates — make the document non-conforming, reported as `duplicate:<key>`.

Without this rule `{"status":"active", ..., "Status":"active"}` yields zero unknown keys, is judged conforming, and is rewritten with one member's bytes destroyed — the identical loss class this feature exists to close. `decodeTopLevelEntries` already preserves exact-duplicate members precisely so this is detectable (`internal/events/checkpoint_strict.go:75-90`).

<!-- BEGIN:acceptance-criteria -->
- An exact duplicate top-level key is non-conforming and reported as `duplicate:<key>`
- A case-variant duplicate (`status` + `Status`) is non-conforming
- A document with one occurrence of every modeled key remains conforming
- Red harness (P-002/P-004 gate): two scaffolded `TestU2c_` functions (cases 1 and 2), both failing
- Green-step guards (`TestU2cGuard_*`, landing with the implementation): case 3 — a document with one occurrence of every modeled key remains conforming
