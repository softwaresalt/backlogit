Unit 2 of the plan (persisted-config migration). CONFIRMED GAP: internal/config/loader.go:120-151 LoadHooks unmarshals hooks.yaml and normalizes ONLY the PreTaskCompletionGate block; it does NOT merge newly-added default transition entries. WriteDefaults persists hooks.yaml with a full lifecycle.transitions: map, and internal/core/workspace.go:114-118 wires THAT persisted map. So the Task 124.002-T defaults.go edit reaches ONLY newly-initialized workspaces; existing consumer workspaces (including the BD8DBB85 reporter) keep their persisted map and keep rejecting blocked->queued / active->queued until the persisted map is normalized on load. This task makes persisted-config normalization a first-class, testable unit of work. Depends on 124.002-T (the mandatory default entries must be defined first). Execution posture: test-first (TDD red->green).

APPROACH:
1. (red) Add an internal/config loader test that writes an OLD hooks.yaml whose lifecycle.transitions map has blocked:[active] and active:[done,blocked,review,shipped,abandoned] (NO queued), calls LoadHooks, and asserts the returned config's transitions include blocked->queued and active->queued (and/or feeds the loaded map into hooks.ValidateStatusTransition and asserts both pass). Confirm RED against current LoadHooks.
2. (green) In internal/config/loader.go LoadHooks, after unmarshal/validate, normalize the loaded Lifecycle.Transitions map to guarantee the mandatory default return-to-queued entries are present: merge queued into the blocked and active target lists if absent (idempotent; preserves operator-added targets; never drops existing entries). Mirror the existing PreTaskCompletionGate.Normalize() precedent (082-F) via a small normalizeTransitions/Normalize helper invoked from LoadHooks.
3. Add a second test case: when transitions is entirely absent, the existing empty-map fallback to DefaultTransitions() already yields the correct set — assert this still holds.
4. Run targeted suite + quality gates.

ACCEPTANCE CRITERIA:
- An OLD persisted hooks.yaml lacking queued in the blocked/active entries honors blocked->queued and active->queued after LoadHooks (red before, green after) — this is the core, first-class acceptance criterion (NOT a fallback note).
- Normalization is idempotent and additive-only: it never removes operator-customized targets and never rejects a valid config (monotonic).
- A config with an absent transitions block still resolves to the correct default set via the existing fallback.
- go test ./internal/config/..., go vet ./..., golangci-lint run, gofmt -l . all pass.

OUT OF SCOPE: the transition-map definition edits themselves (Task 124.002-T); comment/doc alignment (Task 124.003-T); any schema/config-file format change beyond the in-memory load-time normalization.
