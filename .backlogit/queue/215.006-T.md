## Objective

Implement cross-branch and multi-session artifact ID sequence counter reservation and isolation (`3083FC1A` / `091-DL` / Unit U5) in `internal/core/id_history.go` and `internal/core/artifacts.go` so concurrent or interleaved branch sessions never allocate duplicate `NNN-F` or `NNN.MMM-T` work item numbers.

## Scope and Affected Files

* **Domain**: `code` (`internal/core`)
* **Execution posture**: `test-first`
* **Affected files (3)**:
  * `internal/core/id_history.go`
  * `internal/core/artifacts.go`
  * `internal/core/id_history_test.go`

## Implementation Details

1. In `internal/core/id_history.go`, implement a workspace-scoped sequence reservation store backed by `<storage_root>/.locks/id-sequences.json` (validating `<storage_root>/.locks` containment via `EvalSymlinks` + `pathContained` + `core.IsSymlinkOrReparsePoint` before creating `.locks/` or accessing files, and protecting mutations with an in-process mutex plus cross-process advisory file lock `<storage_root>/.locks/id_allocator.lock` via `lockTaskFileWithHeartbeat` with a dedicated `idAllocatorLockBoundedWait = 30 * time.Second` budget). Keep `historicalIDsFromDisk(ws)` and `allocateTypedHierarchicalID` strictly read-only (zero-write when `.locks/id-sequences.json` is absent so `ReconstituteShipments` `DryRun: true` writes nothing), and include all reserved IDs from `<storage_root>/.locks/id-sequences.json` (plus a fingerprint-cached scan of `.backlog/` and `.backlogit/` artifact filenames across local `refs/heads/*` branches when `.git` exists at `ws.RootPath` with multiple branches, executed with `ws.boundedHelperTimeout()`, `gate.MinimalEnv()`, `--no-replace-objects`, and `--no-optional-locks`) inside `historicalIDsFromDisk(ws)`.
2. In `internal/core/artifacts.go` (`CreateArtifact`), place `id_allocator.lock` at the innermost leaf of the canonical lock hierarchy (`stash -> lifecycle-global -> A -> C -> B -> id_allocator.lock`): acquire `id_allocator.lock` strictly *after* `validateArtifactParent` and `ws.HookRunner.FirePre(ctx, hooks.HookCreateArtifact, hookCtx)`, hold it across ID computation (`allocateTypedHierarchicalID` / `NextID`) and `MutationEnvelope`, and release `id_allocator.lock` *before* `ws.HookRunner.FirePost(ctx, hooks.HookCreateArtifact, hookCtx)`. Inside `CreateArtifact` (when `ctx.Value(shipmentOperationContextKey{}) == nil`), make persisting the newly allocated `artifactID` to `<storage_root>/.locks/id-sequences.json` a **compensated `MutationStep` (`Name: "id-sequence-reservation"`) inside `MutationEnvelope`**:
   * Capture the preimage of `<storage_root>/.locks/id-sequences.json` (existence + raw bytes) before running `MutationEnvelope`.
   * In `Apply`: persist the updated `<storage_root>/.locks/id-sequences.json` atomically (with deterministic sorted JSON keys and an injectable seam `writeIDSequenceReservationFn` for deterministic failure testing). If `Apply` fails, `MutationEnvelope` automatically compensates prior steps (`db-upsert` and `file-write`) so neither Markdown nor SQLite retains an unreserved artifact.
   * In `Compensate`: restore `<storage_root>/.locks/id-sequences.json` to its exact preimage (removing the file if it did not exist before, or rewriting the preimage bytes atomically) if any subsequent `MutationEnvelope` step fails.
