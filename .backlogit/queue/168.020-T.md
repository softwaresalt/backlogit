Trust-anchor resolver ROLE-SCOPED resolution + pinned-algorithm binding (behavior). Carved from 168.003-T per plan-review cycle-2 item 6 (width) resolving security F1 (confused-deputy) and F4 (algorithm substitution). The resolver caller requests a key for a specific PURPOSE (attestation-signer vs token-issuer); an anchor whose role does not match the requested purpose is rejected, preventing cross-protocol key reuse. The resolved key carries the anchor pinned algo so callers verify with the pinned algorithm and reject any caller/payload-declared algorithm (including none/alg-substitution). Domain: core (internal/core, pure). TDD: RED table-driven harness first, observed failing. Depends on 168.003-T. Executable scenarios (3): (a) a key requested for attestation-signer purpose against a token-issuer-role anchor is rejected with a typed role-mismatch error; (b) a role-matching request returns the key carrying the anchor pinned algo; (c) a verification attempt using a payload-declared algo different from the pinned algo (incl. none) is rejected with a typed algo-mismatch error. Build/test: go build ./cmd/backlogit; go test ./internal/core/ -run TestTrustedKeyResolverRoleScopedAlgo. AC: (1) RED test first, observed failing; (2) role mismatch returns a typed error (F1); (3) the resolved key carries and enforces the anchor pinned algo, rejecting payload-declared algos incl. none (F4); (4) pure (no I/O); (5) tests GREEN.
