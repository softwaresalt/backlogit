Eliminate the non-member covering-feature **status-rollup / snapshot / restore** side effects from
shipment ship/rollback entirely (spec §0.5 point 8 / SBLK-R28; plan §0.4 rev6). Green-maker for
`174.061-T` (`^TestUNonMemberRollupSafe_`). Resolves the P1 concurrency defect: after `174.057-T`
drops unlisted ancestors from the outer artifact lock (`:603-612`), the preserved
`snapshotNonMemberFeatureStatuses`/`restoreRolledUpNonMemberFeatures` status-revert path snapshots and
later restores an **unlocked** non-member ancestor, so a mutation to it between snapshot and restore
is overwritten (lost update). The flat-manifest-consistent resolution is to remove the side effect at
its ROOT rather than re-lock the ancestor (re-locking would re-introduce the very hierarchy expansion
`174.057-T` removed and violate SBLK-R28). No separate protected CAS is introduced — none is needed
once the non-member mutation is eliminated.

All changes in `internal/core/shipment_lifecycle.go` (+ coupled tests). Two coordinated moves, applied
atomically in ONE task so no intermediate state leaves a non-member ancestor rolled-up-but-unreverted:

**(1) Bound the completion cascade to explicit members (root cause).** The unwanted rollup originates
in `completeReleaseScope` → `setArtifactStatus` → `cascadePersistedParentStatuses`
(`shipment_lifecycle.go:1267`), which walks UP the parent chain and marks any ancestor `done` (and
relocates it to `archive`) purely because its recorded children are all terminal — with no knowledge
of shipment membership. Thread the explicit-membership set (`explicitScopeSet`, already built in
`ShipShipment`) onto the context via an unexported context key and have `cascadePersistedParentStatuses`
STOP the walk when the next parent's ID is NOT in that boundary set (do not load, mutate, relocate, or
recurse past a non-member parent). When the boundary key is absent on `ctx` (every non-ship caller of
`setArtifactStatus`), behavior is unchanged — full generic cascade. This makes the non-member ancestor
never get rolled up, so there is nothing to snapshot or restore. **Injection point (mandatory):** set
the boundary key onto the `ctx` value that is actually threaded into EVERY in-closure
`setArtifactStatus` caller — `completeReleaseScope`, the `:648` governed member loop, and
`returnUnreleasedFeatureItems` (`:735`) — and do so AFTER the `lockArtifactMutations` context
reassignment (`:610`) and BEFORE `completeReleaseScope`; injecting on the pre-lock `ctx` or a sibling
branch leaves one of those callers on a keyless context and re-opens the non-member rollup. Explicitly-listed member features are
UNAFFECTED: rollup onto a parent that IS a manifest member still fires, and the existing member-feature
`setArtifactStatus(featureID, StatusDone, "feature released")` at `:648` (guarded by
`explicitScopeSet[featureID]`) still marks listed feature members `done` — governed member status
handling is preserved. **Member-above-non-member invariant (pin explicitly):** a member feature `E`
sitting ABOVE a non-member `F` (`T`(member) → `F`(non-member) → `E`(member)) is intentionally NOT
reached by the bounded up-walk (the walk stops at `F`); `E` still receives its correct `done` status
via the DIRECT `:648` governed member write (and member tasks via `completeReleaseScope`), never solely
via cascade. The impl and tests MUST pin this invariant so a future change that drops the direct member
write cannot silently reintroduce a stale-member-ancestor bug.

**(2) Remove the now-dead non-member snapshot/restore machinery + coupled callers.** With the cascade
bounded, the compensation machinery is dead and is deleted: remove `snapshotNonMemberFeatureStatuses`
(`:845`) and `restoreRolledUpNonMemberFeatures` (`:1034`) and the `featureStatusSnapshot` type /
`nonMemberFeatureSnapshots` variable; drop the snapshot call (`:598`), the deferred non-member restore
fallback (the second `defer` registered at `:490`), and the in-line restore (`:684`) from
`ShipShipment`; and drop the `nonMemberFeatureSnapshots` parameter and its restore branch from
`classifyShippedEventAppendFailure` (`:908`, called at `:529`). `featureScopeRoots`/`featureIDs`,
`returnUnreleasedFeatureItems`, and `collectArchiveCandidateIDs` are OUT OF SCOPE here — they are owned
(membership-guarded, not for status rollup) by `174.058-T`; only the STATUS-ROLLUP snapshot/restore of
non-members is removed.

Update the coupled tests that encode the removed behavior (they call the deleted functions or assert
the non-member revert, so they must change in the same commit): rewrite
`TestShipShipment_RestoresNonMemberFeatureEvenWhenShipFailsAfterRollup` and
`TestShipShipment_RestoresNonMemberFeatureBeforePostShipHooksObserveIt` (`shipment_test.go`) to assert
the unlisted ancestor is LEFT UNTOUCHED (no rollup, no revert) on both success and forced-rollback;
delete `TestRestoreRolledUpNonMemberFeatures_SucceedsWithCanceledContext` and
`TestRestoreRolledUpNonMemberFeatures_RestoresDeepestFirstRegardlessOfMapOrder` (`shipment_test.go`,
they test a deleted function); and update
`TestShipShipment_NonMemberFallbackRunsBeforeArtifactLockRelease` (`shipment_lifecycle_test.go`) to
the no-non-member-fallback reality. `174.061-T`'s `^TestUNonMemberRollupSafe_` harness is the
replacement behavioral coverage.

Constraints: **no public/exported API** introduced or changed (`NormalizeShipmentItems` unchanged;
the context boundary key is unexported); internal behavior change only. Do NOT re-lock, snapshot, or
CAS-protect non-member ancestors. Do NOT restore any archived/superseded artifact. Do NOT change the
external topology/wave gate.

AC: (1) `174.061-T` (`^TestUNonMemberRollupSafe_`) passes; (2) on ship success and on forced rollback,
a hierarchy-derived non-member covering-feature ancestor receives NO shipment-originated status write
(no `"child status rollup"`, no `"reverted unintended rollup…"`) via ANY in-closure path — the
`completeReleaseScope` completion cascade AND the `returnUnreleasedFeatureItems` (`:735`)
return-to-backlog cascade — and a concurrent mutation to it is never overwritten; (3) an explicitly-listed member feature still transitions to `done` via the
preserved `:648` governed path; (4) `snapshotNonMemberFeatureStatuses` and
`restoreRolledUpNonMemberFeatures` are removed and no caller references them (`classifyShippedEventAppendFailure`
signature no longer takes `nonMemberFeatureSnapshots`); (5) no new exported symbol; existing
`blocked`-lifecycle and flat-scope (`174.055-T`/`174.056-T`/`174.059-T`/`174.060-T`) tests remain
green. Domain: code. ≤5 functions (`cascadePersistedParentStatuses`, the `ShipShipment` governed
closure, `classifyShippedEventAppendFailure`, and deletion of `snapshotNonMemberFeatureStatuses` +
`restoreRolledUpNonMemberFeatures`).
