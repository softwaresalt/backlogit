Unit 2. Make the ShipShipment locked-closure rollback CLASS-AWARE for the shipped-event-append failure SPECIFICALLY. Capture the shipped-append error at its source (a privately-typed boundary, e.g. shipEventAppendError) rather than inspecting the generic closureErr. Only that captured error is classified: ErrWriteNotApplied (and clean pre-append event-log lock-acquisition) compensates via the existing deferred restoreShipArtifacts back to active/unarchived; post-append ErrWriteIndeterminate (and any untagged append error, treated as indeterminate by safe default) does NOT roll back. ALL OTHER closure errors (incl. untagged pre-append failures from completeReleaseScope / returnUnreleasedFeatureItems / cascades) keep the EXISTING unconditional rollback. On indeterminate: suppress restoreShipArtifacts, synchronously restore transient non-member covering-feature rollups while artifact locks are held (mark restored=true on both success and failure so the outer fallback cannot rerun after releaseArtifactLocks), halt archival, and return MutationPartialError{Class:"indeterminate", FailedStep:"shipped-event-append", CompensationState:"not-compensated", Cause: err} wrapping with %w. A compensation restore failure is JOINED onto the returned error; indeterminate dominates. slog on both branches. Files: internal/core/shipment_lifecycle.go + internal/core/shipment.go. Test-first.

<!-- BEGIN:acceptance-criteria -->
- Only the captured shipped-append error is classified; NotApplied (and clean pre-append lock-acquisition) compensates, post-append Indeterminate/untagged never rolls back, and all other/pre-append closure errors keep the existing unconditional rollback.
- The indeterminate branch halts archival, marks the outer fallback consumed, joins any restore failure onto the error, and returns a MutationPartialError with Class: indeterminate wrapping the cause with %w.
- Transient covering-feature rollups are restored synchronously while artifact locks are held; the membership lock and release-scope flow are otherwise unchanged.
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Reuse blerrors.IsWriteIndeterminate and errors.MutationPartialError; no new error infrastructure. Classification carries tagged sentinels only under durable_writes; an untagged shipped-append error degrades safely to the indeterminate (never-roll-back) branch + doctor detection (143.004-T). Tagging the clean pre-append event-log lock-acquisition failure as ErrWriteNotApplied in appendItemEventWithActorErr is REQUIRED, not optional: the NotApplied-compensation acceptance criterion depends on it, so absent the tag the clean pre-append failure would wrongly degrade to the indeterminate branch instead of compensating to active/unarchived. Unit 2 lands its own unit-level failing (red) classification assertions before the production change; broader integration scenarios are 143.003-T.
