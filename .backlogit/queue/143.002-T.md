## Description

<!-- BEGIN:description -->
Unit 2 (implementation; turns the 143.001-T red assertions green). The error-returning shipped-event append seam (ws.shipmentEventAppend) and its captured boundary error (shipmentEventAppendError) already exist in current source; this task adds the CLASS-AWARE handling of that captured error to the ShipShipment locked-closure rollback. Classify only the captured shipped-append error (do not inspect the generic closureErr): ErrWriteNotApplied -- and a clean pre-append event-log lock-acquisition failure, which appendItemEventWithActorErr must tag ErrWriteNotApplied -- compensates via the existing deferred restoreShipArtifacts back to active/unarchived; a post-append ErrWriteIndeterminate, and any untagged shipped-append error treated as indeterminate by safe default, does NOT roll back. ALL OTHER closure errors (including untagged pre-append failures from completeReleaseScope / returnUnreleasedFeatureItems / feature-status cascades) keep the EXISTING unconditional rollback so release-scope mutations are never left applied with the shipment still active. On indeterminate: suppress restoreShipArtifacts, synchronously restore transient non-member covering-feature rollups while artifact locks are held (mark restored=true on both success and failure so the outer fallback cannot rerun after releaseArtifactLocks), halt archival, and return MutationPartialError{Class: indeterminate, FailedStep: shipped-event-append, CompensationState: not-compensated, Cause: err} wrapping with %w. A compensation restore failure is JOINED onto the returned error; indeterminate dominates. slog on both branches. Reuse blerrors.IsWriteIndeterminate and errors.MutationPartialError; no new error infrastructure. Files: internal/core/shipment_lifecycle.go + internal/core/shipment.go. Depends on the 143.001-T red harness.
<!-- END:description -->

## Acceptance Criteria

<!-- BEGIN:acceptance-criteria -->
- Only the captured shipped-append error is classified; NotApplied (and clean pre-append lock-acquisition) compensates, post-append Indeterminate/untagged never rolls back, and all other/pre-append closure errors keep the existing unconditional rollback.
- The indeterminate branch halts archival, marks the outer fallback consumed, joins any restore failure onto the error, and returns a MutationPartialError with Class: indeterminate wrapping the cause with %w.
- Transient covering-feature rollups are restored synchronously while artifact locks are held; the membership lock and release-scope flow are otherwise unchanged.
- The change makes the 143.001-T failing taxonomy/rollback assertions pass without weakening the existing pre-append/other-error rollback coverage.
<!-- END:acceptance-criteria -->

## Implementation Notes

<!-- BEGIN:implementation-notes -->
Reuse blerrors.IsWriteIndeterminate and errors.MutationPartialError; no new error infrastructure. Classification carries tagged sentinels only under durable_writes; an untagged shipped-append error degrades safely to the indeterminate (never-roll-back) branch + doctor detection (143.004-T). Tagging the clean pre-append event-log lock-acquisition failure as ErrWriteNotApplied in appendItemEventWithActorErr is REQUIRED, not optional: the NotApplied-compensation acceptance criterion depends on it, so absent the tag the clean pre-append failure would wrongly degrade to the indeterminate branch instead of compensating to active/unarchived. The failing (red) classification assertions are owned by the 143.001-T harness; this task makes them green. Broader integration/regression scenarios are 143.003-T.
