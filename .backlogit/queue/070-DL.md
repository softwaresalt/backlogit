# Isolate external core_test fixture from recovery-enabled workspace constructor

## Problem Frame

<!-- BEGIN:problem-frame -->
External core_test setupTestWorkspace (100+ callers) calls recovery-enabled core.NewWorkspace; a newly-started hierarchy test hangs in Windows FindFirstFile/EvalSymlinks during synthetic global-lock root canonicalization. Need to isolate the broad fixture from recovery without changing production defaults.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A1 (CHOSEN): add a test-only package-core seam NewWorkspaceWithoutRecoveryForTest delegating to newWorkspace(ctx,root,false); external setupTestWorkspace uses it; recovery-specific tests keep explicit NewWorkspace. | A2 (rejected): reuse production NewDiagnosticWorkspace in tests — couples fixtures to a production doctor/recovery API and misrepresents intent; operator explicitly forbids repurposing it. | A3 (rejected): change NewWorkspace default to autoRecover=false — production behavior change that disables recovery for real callers.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
A1: minimal test-only seam in internal/core package (can call unexported newWorkspace), consumed by the external core_test fixture. No production default/lock/recovery change.
<!-- END:chosen-direction -->
