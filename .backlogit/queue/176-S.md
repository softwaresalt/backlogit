## Prerequisite shipment (RS-W(-1)) — gates the entire replacement baseline sequence

`176-S` carries exactly the three dependency-ordered runner-bootstrap prerequisite
tasks — `175.099-T` (task-lint runner), `175.100-T` (baseline-lint runner), and
`175.101-T` (terminal-lint runner) — that between them OWN creation of the three
shared lint runners (`scripts/verify-task-lint.ps1`,
`scripts/verify-baseline-lint.ps1`, `scripts/verify-terminal-lint.ps1`) that every
baseline-remediation member's `task_lint_cmd` depends on. Each task owns exactly one
runner plus one uniquely named Go harness (at most two files) and a bounded
behavioral scenario matrix (at most three scenario classes), splitting the prior
oversized single bootstrap task per PR #449 cycle 9.

This shipment is the FRONT of the replacement chain: `157-S depends_on 176-S`.
The wave-aligned replacement baseline sequence `157-S`..`169-S` (RS-W00..RS-W12)
MUST NOT begin until `176-S` has shipped, because before the shared runners exist
no member has an executable task-lint command. The task-only manifest (no `175-F`
member) matches the descendant-expansion avoidance used by `157-S`..`169-S`.

The three tasks are dependency-ordered inside the shipment: `175.099-T` is the
in-degree-zero source of the runner-bootstrap chain (no bootstrap dependency),
`175.100-T depends_on 175.099-T`, and `175.101-T depends_on 175.100-T`. The
terminal-lint task `175.101-T` is the bootstrap SINK, and U1 depends on it
(`175.001-T depends_on 175.101-T`), so the whole feature graph opens only after all
three bootstrap tasks ship.

Each task carries a SELF-CONTAINED bootstrap harness/lint contract for its own
runner. Statically it proves its created runner exists, is tracked, parses cleanly
under the PowerShell AST parser, and declares its required parameter surface;
behaviorally (non-vacuous) — after that runner exists — it exercises the runner
against harness-authored deterministic fixtures for its success and
failure/fail-closed contracts, so a no-op runner is rejected. Each uses only
existing main-branch tooling (`go test` + `pwsh`); the GATE for each task is its own
owned Go harness and is NEVER a direct invocation of the runner it creates (see
`.backlogit/queue/175.099-T.md`, `.backlogit/queue/175.100-T.md`,
`.backlogit/queue/175.101-T.md`, and
`docs/decisions/2026-09-19-baseline-convergence-decomposition.md`).

No Go source, workflow, or runtime implementation ships here; the deliverable is the
three imperative PowerShell runners and three uniquely named Go harnesses, produced
by Ship during execution of `175.099-T`, `175.100-T`, and `175.101-T`.
