Plan unit **U4**. Conformance gate on `AbandonCheckpoint`.

Files: `internal/core/checkpoint_disposition.go`, `internal/core/checkpoint_disposition_test.go`.

Call `events.CheckConformingTopLevelNamespace(data)` **immediately after `ValidateCheckpoint` and BEFORE the already-abandoned short-circuit** (`~:78-80`), returning its typed error unchanged.

Placement matters twice:
* *Before the short-circuit* — a non-conforming file carrying `disposition: "abandoned"` would otherwise return `nil` (reported success, no write) from abandon while quarantine accepts it and list/get report `needs_quarantine: true`: three surfaces disagreeing about one file. This is "authenticate before filter" applied literally.
* *Before `appendCheckpointDispositionAudit`* — the shipped ordering guarantee is audit-then-mutate, so a refusal must leave no audit event and no byte change.

It is a non-writing refusal, so nothing is lost by refusing earlier.

- A non-conforming **already-abandoned** document returns `ErrCheckpointNonConforming` rather than `nil`
- The existing "conforming active document abandons successfully" test stays green
- Expected red: all three new cases fail
