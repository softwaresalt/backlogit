DEFERRED follow-up from spike 120-F (conclusion: proceed). Implement a repo-wide, opt-in fsync durability protocol for backlogit's two shared write primitives — atomicfile.WriteFileAtomic and events.EventWriter.AppendEvent — so the whole write path is durable against OS-crash/power-loss, not just process-crash. This is a SEPARATE later release unit and is explicitly NOT part of v1.7.0.

Design (from findings): promote the existing internal/events/fsutil.go synced patterns into the two shared primitives; add the missing POSIX parent-dir fsync; gate directory fsync on runtime.GOOS != "windows" (Windows FlushFileBuffers has no directory-handle support). Ship behind an opt-in `durable_writes` mode (default off) so bulk paths keep current performance. Handle fsync errors fail-closed on critical single-item mutations (size seam, status transitions), best-effort on bulk regeneration. Document the platform-asymmetric guarantee (full POSIX power-loss durability; Windows file-content durability with best-effort dirent). Add regression harnesses mirroring the 040-F/041-S pattern.
