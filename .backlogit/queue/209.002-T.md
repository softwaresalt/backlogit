   - Suppress/buffer child post-hooks during ReconstituteShipments execution: child calls (CreateArtifact, AdoptItemWithOptions, etc.) suppress immediate ws.HookRunner.FirePost publication (by temporarily wrapping/suspending ws.HookRunner or buffering pending HookContext emissions in memory during the transaction) and only flush/emit post-hooks AFTER all durable writes and post-apply Doctor validation succeed (so a midway failure never publishes post-hooks into .backlogit/hooks_queue.jsonl for rolled-back artifacts).
   - Execute feature creation (CreateArtifact + AddLink when related_to is specified), task re-parenting via AdoptItemWithOptions (propagating oldID -> newID across manifests, dependencies, links, archive/stash.jsonl, and archive/provenance_corrections.jsonl), destination-aware planMemberDetach / claim-marker transitions for every member moving out of an active source shipment (Force: true + Reason) as well as unassigned_items (first verifying custom_fields.scheduler_baseline_claim == sourceShipmentID and no WORK_STARTED: comment in the current claim epoch, refusing ineligible members with blerrors.ErrInvalidStatus / blerrors.ErrShipmentConflict; second, transitioning status from active to queued, clearing custom_fields.scheduler_baseline_claim, and emitting a status_changed active -> queued event on the item log when moving to a queued target shipment or unassigned_items, or keeping status: active and updating custom_fields.scheduler_baseline_claim = targetShipmentID when moving to an active target shipment), target shipment creation/update with covering-feature-first + two-phase topological manifest ordering, blocks_on and rewire dependency edge updates (AddDependency / RemoveDependency), post-apply detectShipmentManifestFindings verification, correlated shipment_reconstituted events (EventShipmentReconstituted) on all source and target shipments, and flushing buffered post-hooks.
