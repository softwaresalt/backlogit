Domain: code (U2 of 209-F / 210-S, blocked by 209.001-T).

Scope & Approach:
1. In internal/core/stash_lock.go and internal/core/shipment_lifecycle.go, add stashLockHeldContextKey{} and withStashLockHeld(ctx) / stashLockHeld(ctx) so adoptItem skips calling lockActiveStash(ws) when the outer ReconstituteShipments caller already holds the active stash lock.
2. In internal/hooks/hooks.go, add operation-local context.Context post-hook buffering via hooks.WithBufferedPostHooks(ctx) and hooks.FlushBufferedPostHooks(ctx, ws.HookRunner):
   - ws.HookRunner is NEVER nil'd, replaced, or mutated on ws (so concurrent operations on the same Workspace are unaffected).
   - Synchronous ws.HookRunner.FirePre(...) runs normally on every child CreateArtifact and AdoptItemWithOptions call (so a rejecting pre-hook vetoes the operation and triggers clean rollback).
   - When HookRunner.FirePost(ctx, ...) sees a post-hook buffer in ctx, it appends the (event, hookCtx) entry to the ctx-local buffer instead of dispatching immediately; ReconstituteShipments flushes the buffer only after the journal reaches Phase: "committed" (and discards the buffer on rollback).
3. In internal/core/shipment_ops.go, internal/core/shipment_recovery.go, and internal/core/shipment_reconstitute.go, implement durable Operation: "reconstitute" (RecoveryPolicy: "rollback") journaling and live ReconstituteShipments execution:
   - Acquire outer locks in interoperable canonical order: lockActiveStash(ws) outermost (attaching withStashLockHeld(ctx)) -> lockShipmentLifecycleGlobal(ctx, ws) (running recoverPendingShipmentOperations) -> lockShipmentMembership(ctx, ws, id) in sorted shipment ID order -> lockArtifactMutations(ctx, ws, affectedArtifactIDs) in sorted ID order. Do NOT bulk-acquire events.LockItemLogCrossProcess upfront under lockShipmentLifecycleGlobal (which would invert against AssociateCommit holding an item-log lock before acquiring lockShipmentLifecycleGlobal in persistArtifact); instead, acquire events.LockItemLogCrossProcess only briefly per-item during individual event appends and during operation-correlated log rollback (restoreReconstitutedItemLogs).
   - Re-validate the plan under lock and before any mutation write a durable Operation: "reconstitute" (RecoveryPolicy: "rollback", Phase: "intent", CorrelationID) operation journal containing preimage byte/struct snapshots of all touched shipment and member .md files, archive/stash.jsonl and archive/provenance_corrections.jsonl snapshots, commit_links preimages, CreatedArtifactIDs / CreatedPaths (all deterministically pre-computed from the dry-run plan before mutation), and AdoptedIDMap (oldID -> newID).
   - Attach ctx = hooks.WithBufferedPostHooks(ctx) and _reconstitute_operation: correlationID event metadata on ctx.
   - Execute feature creation (CreateArtifact + AddLink when related_to is specified), task re-parenting via AdoptItemWithOptions (propagating oldID -> newID across manifests, dependencies, links, archive/stash.jsonl, and archive/provenance_corrections.jsonl), destination-aware planMemberDetach / claim-marker transitions for every member moving out of an active source shipment (Force: true + Reason) as well as unassigned_items (first verifying custom_fields.scheduler_baseline_claim == sourceShipmentID and no WORK_STARTED: comment in the current claim epoch, refusing ineligible members with blerrors.ErrInvalidStatus / blerrors.ErrShipmentConflict; second, transitioning status from active to queued, clearing custom_fields.scheduler_baseline_claim, and emitting a status_changed active -> queued event on the item log when moving to a queued target shipment or unassigned_items, or keeping status: active and updating custom_fields.scheduler_baseline_claim = targetShipmentID when moving to an active target shipment), target shipment creation/update with covering-feature-first + two-phase topological manifest ordering, blocks_on and rewire dependency edge updates (AddDependency / RemoveDependency), post-apply detectShipmentManifestFindings verification, and correlated shipment_reconstituted events (EventShipmentReconstituted) on all source and target shipments.
   - After all mutations, Doctor manifest integrity check, and shipment_reconstituted events succeed, durably transition the journal on disk to Phase: "committed" BEFORE calling cleanupShipmentOperationJournal and flushing buffered post-hooks via hooks.FlushBufferedPostHooks(ctx, ws.HookRunner).
   - Teach validateShipmentLifecycleJournalRecord and reconcileShipmentLifecycleIntent (internal/core/shipment_ops.go, internal/core/shipment_recovery.go) to handle Operation == "reconstitute": if Phase == "committed", finalize and remove the journal without rolling back; if Phase == "intent" (or on any in-process midway failure), discard buffered post-hooks, execute idempotent rollback (remove created .md files, rename <newID>.jsonl -> <oldID>.jsonl and run restoreReconstitutedItemLogs to lock one item log at a time, read the current .jsonl lines, filter out only events carrying _reconstitute_operation: correlationID while preserving any independent concurrent AppendComment or AssociateCommit events, write the filtered log atomically, and re-index it in SQLite, restore preimage .md/stash.jsonl/provenance_corrections.jsonl snapshots, restore commit_links, and rehydrate SQLite), and only remove the journal once rollback succeeds (retaining the intent journal if rollback itself encounters an error so the next lockShipmentLifecycleGlobal barrier retries recovery).
4. In internal/core/shipment_reconstitute_test.go (TestU2_ReconstituteShipmentsAtomicExecutionAndRollback / TestU2_ReconstituteShipments_AtomicApplyAndRollback):
   - Include hooks-enabled failure-injection coverage asserting .backlogit/hooks_queue.jsonl is unchanged on rollback, plus rejecting-pre-hook rollback and concurrent-create post-hook isolation tests.
   - Seed existing commit_links on an adopted task in the U2 failure-injection rollback test and assert commit_links are restored to oldID after rollback.
   - Add a regression test verifying concurrent/interleaved AssociateCommit + ReconstituteShipments completes without lock-order deadlock or lost commit/comment events, and that independent comment/commit events are preserved across rollback (including across an adopted/renamed log path) and re-indexed in SQLite.
   - Add crash-interruption recovery barrier tests (Phase: "intent" rolled back, Phase: "committed" finalized) and failed-rollback journal-retention tests.
   - Test an active source shipment split into a queued target shipment in live execution (U2).
