<!-- BEGIN:description -->
Implement `ShipmentManifestOptions`, `RemoveFromShipmentResult`, `MoveShipmentItemResult`, `RemoveFromShipment`, and `MoveShipmentItem` in `internal/core/shipment_manifest.go` (and `move_item` recovery journal handling in `internal/core/shipment_recovery.go`) with unit tests in `internal/core/shipment_manifest_test.go`.

* Enforce `queued`-only default and blocked-manifest seal: unconditionally refuse `blocked` shipments (`status == "blocked"` or carrying a blocked-manifest seal) with `ErrShipmentBlockedManifestSealed` / `ErrInvalidStatus` / `blerrors.ErrShipmentConflict` even when `opts.Force == true` (in both live and `DryRun` modes), requiring governed `UnblockShipment` first; for other non-`queued` shipments (`active`, `shipped`, `abandoned`), refuse with `blerrors.ErrShipmentConflict` unless `opts.Force == true`, and require non-empty `opts.Reason` (`blerrors.ErrValidation`) whenever `opts.Force == true`.
* Support status-preserving manifest removal in `RemoveFromShipment`: the item remains in `.backlogit/queue/` unassigned from the shipment manifest with its current `status` preserved (`queued` for queued shipments, `active` for claimed active shipments) and any matching `custom_fields.scheduler_baseline_claim == shipmentID` cleared on the member inside the same compensated `MutationEnvelope`.
* Support read-only zero-write preview when `opts.DryRun == true`: do NOT call `lockShipmentLifecycleGlobal`, `GetShipment`, or `loadArtifact`; instead check the shipment lifecycle recovery journal directory read-only (refusing with a pending-recovery error if any unfinished journal exists) and read Markdown files directly via `readArtifactFromDiskReadOnly` with zero SQLite, lock-file, or JSONL writes.
* In `MoveShipmentItem`, acquire `lockShipmentLifecycleGlobal` and then acquire `lockShipmentMembership` on `fromShipmentID` and `toShipmentID` in canonical lexicographical order, and execute the durable correlated `move_item` recovery protocol (`intent` journal + preimages -> manifest updates -> correlated `committed` `shipment_item_moved` events, retaining the journal on `ErrWriteIndeterminate` and rolling back both manifests plus appending a correlated `phase: "aborted"` event if the second audit append fails with `ErrWriteNotApplied`).
* Emit and index `shipment_item_removed` and `shipment_item_moved` events when `!opts.DryRun`.
* Files modified: `internal/core/shipment_manifest.go`, `internal/core/shipment_recovery.go`, `internal/core/shipment_manifest_test.go`.
