Core mutation logic for add/rotate/revoke: deterministically edits config + status only and enforces the external-pin policy (a mutation introducing an unpinned fingerprint is rejected fail-closed), and persists a durable audit event as the FINAL step of the ordered sequenced-commit protocol whose write-outcome taxonomy, marker semantics, and denied-path audit-failure handling are OWNED by 168.017-T (cycle-3 item 13; the cycle-2 168.019-T is withdrawn and folded into 168.017-T). This task does NOT claim cross-file transactional atomicity; it performs the deterministic ordered sequence and returns the base WriteOutcome type, deferring ErrWriteNotApplied/ErrWriteIndeterminate/ErrAuditNotPersisted classification and marker handling to 168.017-T. Constitution VII (cycle-3 item 3): rotate and revoke are DESTRUCTIVE security-state mutations; explicit operator approval is ALWAYS required, and any safety-mode gate is ADDITIONAL, never an alternative to that approval. The core refuses to apply a rotate/revoke unless it is presented with VERIFIABLE authorization EVIDENCE -- a signed/verifiable operator-approval token or capability that the core itself validates -- NOT a bare caller-supplied boolean the core would have to trust; an unproven caller boolean is NOT authorization evidence, so even a programmatic core caller cannot forge approval. NO CLI parsing (CLI wiring is 168.013-T). Deterministic ordering: validate -> enforce pin policy -> mutate config -> mutate status -> persist audit event, with add/rotate/revoke sharing ONE parametrized mutation path. Domain: core (internal/core). TDD: RED behavior harness first, observed failing. Depends on 168.003-T and 168.012-T. Executable scenarios (3): (a) add/rotate/revoke each mutate config+status via the shared parametrized path in fixed order; (b) an unpinned-fingerprint mutation is rejected fail-closed at the pin gate before any state change AND the denied mutation persists a durable audit event (F2); (c) a rotate/revoke presented WITHOUT verifiable operator-approval evidence (or with invalid/forged evidence) is refused with a typed error and no state change (Constitution VII), while one with valid verified evidence proceeds and persists its audit as the final ordered step. Build/test: go build ./cmd/backlogit; go test ./internal/core/ -run TestTrustAnchorMutationCore. AC: (1) RED test first, observed failing; (2) add/rotate/revoke mutate config+status deterministically in fixed order; (3) an unpinned-fingerprint mutation is rejected fail-closed before any state change AND persists a durable denial audit (F2); (4) rotate/revoke without VERIFIABLE operator-approval evidence (bare boolean, absent, invalid, or forged) are refused with a typed error and no state change (Constitution VII -- approval always required, safety mode additional); (5) each successful mutation persists a durable audit event as the final ordered step (NOT claimed atomic); (6) the core DECLARES the base WriteOutcome type; write-outcome taxonomy/marker/denied-path handling delegated to 168.017-T; (7) tests GREEN.
