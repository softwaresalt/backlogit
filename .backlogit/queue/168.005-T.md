Core mutation logic for add/rotate/revoke: deterministically edits config + status only and enforces the external-pin policy (a mutation introducing an unpinned fingerprint is rejected fail-closed), and persists a durable audit event as the FINAL step of the marker-protected sequenced-commit protocol whose write-outcome taxonomy and recovery semantics are OWNED by 168.017-T. This task does NOT claim cross-file transactional atomicity (a config file + status + separate audit log cannot be atomic on a filesystem); instead it performs the deterministic ordered sequence and returns the base WriteOutcome type, deferring ErrWriteNotApplied/ErrWriteIndeterminate classification and recovery-marker handling to 168.017-T and denied-path audit-failure recovery to 168.019-T. Constitution VII (cycle-2): rotate and revoke are DESTRUCTIVE security-state mutations; the core refuses to apply a rotate/revoke unless it receives an explicit approved-authorization argument (set only after the 168.013-T CLI operator-approval/safety-mode gate passes), so even a programmatic core caller cannot bypass the gate. NO CLI parsing (CLI wiring is 168.013-T). Deterministic ordering: validate -> enforce pin policy -> mutate config -> mutate status -> persist audit event, with add/rotate/revoke sharing ONE parametrized mutation path. Domain: core (internal/core). TDD: RED behavior harness first, observed failing. Depends on 168.003-T and 168.012-T. Executable scenarios (3): (a) add/rotate/revoke each mutate config+status via the shared parametrized path in fixed order; (b) an unpinned-fingerprint mutation is rejected fail-closed at the pin gate before any state change AND the denied mutation persists a durable audit event (F2); (c) a rotate/revoke WITHOUT the explicit approved-authorization argument is refused with a typed error and no state change (Constitution VII), while an approved one proceeds and persists its audit as the final ordered step. Build/test: go build ./cmd/backlogit; go test ./internal/core/ -run TestTrustAnchorMutationCore. AC: (1) RED test first, observed failing; (2) add/rotate/revoke mutate config+status deterministically in fixed order; (3) an unpinned-fingerprint mutation is rejected fail-closed before any state change AND the denied mutation persists a durable audit event (F2); (4) rotate/revoke without the explicit approved-authorization argument are refused with a typed error and no state change (Constitution VII); (5) each successful mutation persists a durable audit event as the final ordered step (NOT claimed atomic); (6) the core DECLARES the base WriteOutcome type; write-outcome taxonomy/recovery-marker delegated to 168.017-T and denied-path recovery to 168.019-T; (7) tests GREEN.
