Plan unit **U1d** (partition 1). Declares the structured, non-executable remediation carrier that replaces the ambient-cwd command string.

Files: `internal/events/checkpoint_schema.go`, `internal/events/checkpoint_remediation_test.go` (new).

Created in PR #377 cycle 17 to close gate finding **H1** (P0). `internal/events` has no knowledge of the caller''s working directory, so any command string it emits is bound to an ambient cwd, carries no approval, preimage, or no-clobber obligation, and is paste-runnable by whoever reads it.

```go
type RemediationIntent struct {
    Verb             string `json:"verb"`              // "quarantine"
    TargetFilename   string `json:"target_filename"`   // bare filename, never a path
    RequiresApproval bool   `json:"requires_approval"` // always true
    ApprovalClass    string `json:"approval_class"`    // "A4c"
    Reason           string `json:"reason"`            // schema_invalid | non_conforming | unparseable
}
```

Add `RemediationIntent *RemediationIntent` with tag `json:"remediation_intent"` to `CheckpointSummary` (`internal/events/checkpoint_schema.go:371`). No `omitempty` on any field.

The shipped `CheckpointSummary.RemediationCommand` keeps its shipped meaning and its shipped parse-failure population. Mark it `// Deprecated: use RemediationIntent`. Do **not** extend it to any new branch. Removal is follow-up stash `F350503F`.

This task has no dependencies inside the plan; with 147.001-T it is one of the two ready roots and
one of the two members of **wave 1** under P-002.6.

**Test-lifecycle classification: harness-required, source-shape RED (cycle-29).** This task is
**not** `harness-exempt`. It lands a serialized `remediation_intent` field on `CheckpointSummary`
and a new exported type — observable production surface — so Constitution Principle II applies in
full and admits no carve-out. The `declaration-only` exemption class that cycle 20 created for it
was withdrawn in cycle 29 (`workflow-policies.md` P-002.1) after PR #377 review found that it let

not exist is a **build error**, which P-004 does not accept, and a test that passes the instant the
shape lands was never red. A **source-shape harness** is neither. It parses
`internal/events/checkpoint_schema.go` with `go/parser` and asserts the declared shape through
`go/ast`, so it references no undeclared identifier:

  `go/token`, `strings`, and `testing` — so `go test -run=^$ -count=1 ./internal/events` exits 0
  and P-002's harness-compiles postcondition holds;
