## Description

<!-- BEGIN:description -->
Unit 1 (RED harness). Current source already routes the active-to-shipped shipment_status_changed emission through an error-returning per-ws append seam (ws.shipmentEventAppend, defaulting to appendItemEventErr) and returns append failure via the privately-typed shipmentEventAppendError from moveShipmentStatusWithHeadGuard, so this task does NOT introduce that seam. It authors the failing (red) unit-level test harness for the remaining failure-taxonomy and rollback gaps and adds characterization tests that pin the already-existing seam behavior (explicitly labeled characterization, not new behavior). Failing red assertions (kept red until 143.002-T lands): (a) a captured shipped-append ErrWriteNotApplied -- and a clean pre-append event-log lock-acquisition failure tagged NotApplied -- compensates via the existing deferred restoreShipArtifacts back to active/unarchived; (b) a post-append ErrWriteIndeterminate, and any untagged shipped-append error treated as indeterminate by safe default, is NEVER rolled back, halts archival, and returns MutationPartialError{Class: indeterminate, FailedStep: shipped-event-append, CompensationState: not-compensated} wrapping the cause with %w; (c) on the indeterminate branch a transient non-member covering-feature rollup is restored synchronously while artifact locks are held and the outer fallback is marked consumed. Inject through the existing per-ws seam restored with t.Cleanup so tests stay parallel-safe. Test-first: these red assertions must be observed to fail against the pre-implementation baseline before 143.002-T.
