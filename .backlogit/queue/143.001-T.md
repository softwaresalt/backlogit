# Add shipment-scoped append seam and error-returning appender

## Description

<!-- BEGIN:description -->
Unit 1. Purely additive plus one behavior-preserving call-site change. Add the per-workspace seam field `shipmentEventAppend` to `Workspace`, mirroring `gateEvidenceAppend` (`internal/core/workspace.go:55-59`). Add `appendShipmentEventErr`: a shipment-scoped error-returning appender that acquires the item-log lock itself so a lock failure and an append failure arise in two distinguishable statements, and so the message reads `shipment event log`, not `gate evidence`. Tag the lock failure with `blerrors.ErrWriteNotApplied` (nothing written, compensation safe). Tag a short or partial write with `blerrors.ErrWriteIndeterminate`: the default non-durable `appendFast` path writes with `fmt.Fprintf`, which can return an untagged error after bytes reached the file, and compensating over a partially written append-only log is what the `AppendEvent` contract forbids. Add the dispatcher `(ws *Workspace).appendShipmentEvent` mirroring `appendGateEvent`, and declare the private boundary type `shipmentEventAppendError` here so it lives in the same package as the call site that wraps it (143.003-T) and the closure that classifies it (143.004-T). Route the `shipment_status_changed` call site (`internal/core/shipment.go:205`) through the dispatcher while PRESERVING best-effort semantics: log the error, do not return it. Declare the failed-step name once as an exported constant in `internal/errors` (`StepShippedEventAppend`) so core and MCP share one literal. Execution posture: characterization-first.
<!-- END:description -->

## Acceptance Criteria

<!-- BEGIN:acceptance-criteria -->
- `Workspace` carries a `shipmentEventAppend` seam field and an `appendShipmentEvent` dispatcher that falls back to `appendShipmentEventErr`.
- `appendShipmentEventErr` owns the item-log lock, tags lock failure `ErrWriteNotApplied` and short or partial writes `ErrWriteIndeterminate`, and never mentions gate evidence.
- The shipped call site routes through the dispatcher with unchanged best-effort behavior.
- `go test ./internal/core/ -run 'TestShipShipment|TestClaimShipment|TestRestoreShipArtifacts'` is green with no test edits.
