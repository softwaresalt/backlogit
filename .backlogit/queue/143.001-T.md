# Add RED harness for shipped-event durability

## Description

<!-- BEGIN:description -->
Unit 1, RED harness, first task on the durability track. NO production behavior. Add `internal/core/shipment_shipped_event_durability_test.go` with three table-driven scenarios, ALL RED, plus the ONE declaration the tests need to compile: the per-workspace seam field `shipmentEventAppend` on `Workspace`, mirroring `gateEvidenceAppend` (`internal/core/workspace.go:55-59`), with its exact signature pinned here because 143.002-T consumes it and does not re-touch `workspace.go`. Nothing in production reads that field on this tree; the harness is its only consumer, and `staticcheck` counts a field write as a use with test files included, so the declaration is lint-clean. This is the compile-then-fail pattern `.github/skills/harness-architect/SKILL.md` Step 4.3 prescribes, NOT a scaffold task: no dispatcher, no appender, no call-site change. Real-filesystem injection AT THE APPEND was evaluated and REJECTED: a directory planted at the item log or lock path before the call aborts earlier in `snapshotShipArtifacts` (`internal/core/shipment_lifecycle.go:152-164`, called at `:478`, before the transition at `:509`), leaving `shipSnapshots` empty so the rollback defer short-circuits at `:391`. Scenario 1 proven not-applied compensates: a seam error wrapping `ErrWriteNotApplied` restores the shipment to active, leaves the release scope not completed, archives nothing, and returns `MutationPartialError` with `Class: not-applied`, `CompensationState: compensated`, and `FailedStep` equal to the literal `shipped-event-append`. Scenario 2 indeterminate and unclassified never roll back: subtests for a seam error wrapping `ErrWriteIndeterminate`, a bare untagged `errors.New`, and an error wrapping BOTH sentinels (which must classify indeterminate because indeterminate dominates), all on a fixture whose ship would roll up a non-member covering feature; the release scope is NOT rolled back, the covering feature is restored and re-read through `loadArtifact`, archival is halted, the shipment is left shipped-and-unarchived, and the error carries `Class: indeterminate` and `CompensationState: not-compensated`. Scenario 3 compensation reports itself: the same not-applied injection PLUS one release-scope item that cannot be restored, yielding `CompensationState: partially-compensated` naming the un-restored ID. Execution posture: test-first (red phase).

## Acceptance Criteria

<!-- BEGIN:acceptance-criteria -->
- The package compiles: `go test -run=^$ -count=1 ./internal/core/` succeeds.
- ALL three scenarios fail on this tree. On this tree `ShipShipment` returns nil and archives, so each scenario fails on its expected-an-error assertion; if any scenario passes, halt, the declaration carried behavior it was not supposed to carry.
- The only production edit is the `shipmentEventAppend` field declaration with its signature pinned; no dispatcher, no appender, no call-site change, no behavior difference in `ShipShipment`.
- Scenario 3 arms the compensation failure from INSIDE the seam callback by planting a directory at that item's lock sidecar path; the harness never calls `events.LockItemLog` or `events.LockItemLogCrossProcess`, which would block `restoreShipArtifacts` on an unbounded in-process mutex and hang the test binary.
- Every scenario carries a watchdog so a lock regression surfaces as a failure, not as a suite timeout.
- `FailedStep` is asserted against the string literal `shipped-event-append`, not against a constant that does not exist yet.
- No scenario asserts short-write or partial-write detection.
- The file does not call `t.Parallel` and every fixture pins `Config.DurableWrites` explicitly.
<!-- END:acceptance-criteria -->
