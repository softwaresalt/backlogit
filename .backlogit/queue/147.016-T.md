Plan unit **U8b**. Cross-surface parity from one stored state.

Files: `internal/cli/checkpoint_parity_test.go` (new). **No production change.**

U6/U6b/U6c/U7/U7b/U8/U8c each assert their own surface in isolation. Nothing yet asserts that CLI, MCP, and the `events` read layer answer the **same** question about the **same** bytes. Governed-operation parity is an explicit repo contract (`docs/design-docs/governed-operation-parity.md`), and the failure mode this feature exists to prevent is precisely surfaces disagreeing about one file.

Use the plan's **three-row** shared fixture table. Each row is written **once** into a scratch workspace, then driven through the CLI command handler **and** the MCP handler **and** the `events` read layer against that same file. Shape differences (exit code plus text vs JSON payload) are expected; the **classification** must not differ.

| Row | Stored shape | Expected agreement |
|---|---|---|
| `legacy-shaped` | schema-invalid **and** non-conforming | every surface refuses `resolve` and routes to quarantine (MCP `code: checkpoint_use_quarantine` via 147.025-T); `get` returns the **validation-class** refusal on all three — `events.ErrCheckpointInvalid`, MCP `code: validation_failed`, CLI non-zero exit — **not** a success payload |
| `valid-but-non-conforming` | parses and validates, carries unmodeled top-level keys | `events.GetCheckpointResult` → `conforming: false`; MCP `get_checkpoint` → `conforming: false`; CLI `checkpoint get` → the same; `resolve` and `abandon` refuse with `checkpoint_non_conforming` |
| `conforming-active` | conforming, `status: active` | every surface accepts `abandon`; `get` reports `conforming: true` |

The `valid-but-non-conforming` row's CLI `checkpoint get` expectation is implemented by **147.027-T** (U8c), which is why this unit depends on it: before cycle 4 no task projected `conforming` on the CLI read surface, so this row asserted behaviour nothing produced.

A schema-invalid document never reaches a conformance verdict, so the `conforming: false` assertions belong to the `valid-but-non-conforming` row only. Asserting them on the `legacy-shaped` row would assert an outcome the read path cannot produce. For the same reason the `legacy-shaped` `get` expectation is the **validation-class** refusal, not a disposition code: `GetCheckpointResult` returns `ErrCheckpointInvalid` unwrapped (147.012-T) and the MCP read handler maps it through `domainError` to `validation_failed` (147.022-T). `checkpoint_use_quarantine` belongs to the `resolve` column, where 147.025-T routes it.

**Posture: regression guard — this unit is the parity contract itself.**
