Plan unit **U8b**. Cross-surface parity from one stored state.

Files: `internal/cli/checkpoint_parity_test.go` (new). **No production change.**

U6/U6b/U6c/U7/U7b/U8 each assert their own surface in isolation. Nothing yet asserts that CLI, MCP, and the `events` read layer answer the **same** question about the **same** bytes. Governed-operation parity is an explicit repo contract (`docs/design-docs/governed-operation-parity.md`), and the failure mode this feature exists to prevent is precisely surfaces disagreeing about one file.

Use the plan's **three-row** shared fixture table. Each row is written **once** into a scratch workspace, then driven through the CLI command handler **and** the MCP handler **and** the `events` read layer against that same file. Shape differences (exit code plus text vs JSON payload) are expected; the **classification** must not differ.

| Row | Stored shape | Expected agreement |
|---|---|---|
| `legacy-shaped` | schema-invalid **and** non-conforming | every surface refuses `resolve` and routes to quarantine; `get` returns the invalid-document refusal (`ErrCheckpointInvalid` / `checkpoint_use_quarantine`) on all three, **not** a success payload |
| `valid-but-non-conforming` | parses and validates, carries unmodeled top-level keys | `events.GetCheckpointResult` → `conforming: false`; MCP `get_checkpoint` → `conforming: false`; CLI `checkpoint get` → the same; `resolve` and `abandon` refuse with `checkpoint_non_conforming` |
| `conforming-active` | conforming, `status: active` | every surface accepts `abandon`; `get` reports `conforming: true` |

A schema-invalid document never reaches a conformance verdict, so the `conforming: false` assertions belong to the `valid-but-non-conforming` row only. Asserting them on the `legacy-shaped` row would assert an outcome the read path cannot produce.

**Posture: regression guard — this unit is the parity contract itself.**

<!-- BEGIN:acceptance-criteria -->
- All three fixture rows are written once each; CLI, MCP, and `events` are read from that single stored state per row
- `valid-but-non-conforming`: `events.GetCheckpointResult` → `conforming: false`; MCP `get_checkpoint` → `conforming: false`; CLI `checkpoint get` → the same
- `legacy-shaped`: all three surfaces refuse `resolve` with a message naming quarantine, and `get` returns the invalid-document refusal rather than a success payload
- `conforming-active`: all three surfaces accept `abandon`
- Every fixture file is byte-identical after all three surfaces have been exercised
<!-- END:acceptance-criteria -->
