A harness that depends on the implementations it pins can never be red against a pre-implementation state. The direction is inverted: this task now depends on **declarations only** and the partition-4 implementations depend on it.

`docs/compound/2026-07-03-cli-mcp-honest-fallback-map-and-registry-drift-test.md` Rule 3 requires a guard spanning CLI and MCP to exercise both surfaces **from the same stored state**. **Already-green assertions relocated (cycle 20).** Cycle 16 claimed the `legacy-shaped` row''s `get` assertions were red. They are not: `GetCheckpoint` already runs `ValidateCheckpoint` and returns `ErrCheckpointInvalid`, `domainError` already maps that to `validation_failed`, and the CLI already exits non-zero. They now land with the parity implementation as `TestU8bGuard_*` functions and are **not committed in the harness step**.

Red verification: `go test -count=1 -run '^TestU8b_' ./internal/cli`.
