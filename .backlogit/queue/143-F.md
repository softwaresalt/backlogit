# Shipment shipped-event audit-log durability and doctor reconciliation

## Description

<!-- BEGIN:description -->
Guarantee the shipment shipped-event audit log is durable on the GOVERNED ShipShipment archival path, so that path can never persist archived_status: shipped while the append-only JSONL omits shipment_status_changed: shipped. Verified against clean origin/main 3ec95ee3: the shipped path still emits through the best-effort appendItemEvent (internal/core/shipment.go:205) after the status is already persisted (:200), and ShipShipment archives unconditionally (internal/core/shipment_lifecycle.go:515-527); no shipment-scoped append seam and no shipment append-error classification exist. This feature introduces a per-workspace shipment append seam plus a shipment-scoped error-returning appender, routes ONLY the active -> shipped transition fail-closed, and classifies the captured append error conservatively because EventWriter.AppendEvent exposes only error and the default non-durable appendFast path discards the fmt.Fprintf byte count (internal/events/stream.go:243, :290-291): only a PROVEN not-applied outcome compensates (the lock failure raised before any writer call, and writer errors explicitly tagged ErrWriteNotApplied), while tagged ErrWriteIndeterminate and every unclassified append error never roll back and surface a MutationPartialError. It also makes compensation honest rather than silently partial, corrects the adjacent defer ordering so the non-member covering-feature fallback runs with locks held, and adds a report-only doctor reconciliation audit emitting two distinct findings plus its CLI, MCP, recovery-guidance, and policy surfaces. The audit detects residue from ANY producer; PREVENTION for non-ShipShipment producers (generic update and archive paths) is deferred to active stash 47B48DB0 and is explicitly NOT promised here. No file under internal/events is modified. Source: stash 0115F71F; deliberation 059-DL.
<!-- END:description -->

## Goals

<!-- BEGIN:goals -->
- On the governed ShipShipment archival path, no shipment reaches archived_status: shipped unless the durable shipment_status_changed: shipped event landed first, or archival was halted and a MutationPartialError returned. Universal prevention across all producers is NOT claimed; it is deferred to stash 47B48DB0.
- An append failure is classified honestly and conservatively: only a proven not-applied outcome compensates; tagged indeterminate and every unclassified append error never roll back and return a structured MutationPartialError.
- No artifact, test, or code comment promises detection of short or partial writes, and no file under internal/events is modified.
- Compensation is all-or-nothing or reports itself as partially-compensated with the un-restored IDs.
- Historical residue from any producer is detectable through a report-only audit that never writes or rewrites JSONL.
- The audit is reachable from both the CLI and MCP, and the MCP recovery guidance names a check that can actually detect the residue.
- Policy, the reconcile skill, and the Ship agent no longer instruct git restore over the intended residue.
<!-- END:goals -->
