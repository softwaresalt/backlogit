Guarantee the shipment shipped-event audit log is durable across active -> shipped -> archived transitions, so a shipment can never persist archived_status: shipped while the append-only JSONL omits shipment_status_changed: shipped. Integrates an error-returning shipped-event append into the hardened ShipShipment rollback envelope with class-aware, two-class durable-write handling (NotApplied compensates; Indeterminate/untagged never rolls back and surfaces a MutationPartialError), scoped to the shipped transition, and adds a report-only doctor audit (detection net) plus its CLI and MCP surfaces. Completes 140-F Unit 1 (deferred from 106.033-T). Source: stash 0115F71F; deliberation 059-DL.

<!-- BEGIN:dod -->
- All child tasks done with tests passing (go test ./...), go vet, golangci-lint, gofmt clean.
- Injected NotApplied and Indeterminate append failures produce the two distinct, tested outcomes across the shared ShipShipment core.
- doctor --check-shipped-event-completeness reports seeded inconsistencies (archived and queue-resident residue) and clean fixtures, writing no JSONL, on both CLI and MCP.
- Plan-review gate PASS and adversarial multi-model review PASS recorded in the plan.
<!-- END:dod -->

<!-- BEGIN:goals -->
- Make the shipment_status_changed: shipped event durable before archival can proceed; archival must not continue without it.
- On append failure: compensate active/unarchived state (NotApplied) or surface an explicit indeterminate reconciliation error (Indeterminate), never a silent success.
- Behave identically across the shared CLI and MCP core path.
- Provide a report-only doctor audit detecting archived shipments with archived_status: shipped but no shipped event, and shipped-but-unarchived residue; never rewrite historical JSONL.
