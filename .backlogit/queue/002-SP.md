SPIKE (operator-requested 2026-10-05; caveat on ruling B of 196-S Amendment 3). Source stash: DB071B5D (high, task). NOT a member of shipment 196-S and must not be added to any shipment until it is separately planned. Investigation only: no production change is authorized by this item.

Question: how should already-done work be reopened, if at all?

Mechanisms to compare:
1. Governed done->queued allowance: a scoped, audited reopen operation in core (e.g. a dedicated reopen command/MCP tool, actor + reason required, emits a REOPENED event), instead of a temporary hooks.yaml lifecycle edit.
2. No reopen: create a new work item that references the closed item with a recorded rationale (e.g. a reopens/supersedes/follows_up link plus a reason field), leaving the closed item and its evidence untouched.
For each, record the rationale for preferring it and the cost of building it.

Traceability risk analysis (required): for each mechanism, assess the effect on gate evidence (gate_passed records, ancestor-aware head_sha staleness), commit links, shipment closure / GI-GR reconciliation, archived_from / archived_status provenance, WORK_STARTED epochs and claim markers, member_status_snapshot, item logs, hooks_queue events, and stash harvest provenance. Name the hypothesis to test: reopening a task that belonged to a closed or shipped shipment breaks traceability, so new work items should be the default even when the new work logically continues the old work.

Expected output: a findings artifact under docs/decisions/ with a recommendation and a decision table of when each mechanism is legal, keyed at least by (artifact type, current status, shipment state of the owning shipment: none / queued / active-unshipped / shipped / abandoned). Example hypothesis row: reopen allowed only inside an active, unshipped shipment; otherwise a new linked work item.

Evidence: 196-S needed a one-time, operator-executed temporary hooks.yaml done->[archived, queued] exception for 196.001-T and 196.003-T (docs/exec-plans/2026-10-03-195s-dispatch-closure-contract-plan.md, Amendment 3 A3.4 Option A), because no governed reopen exists (internal/hooks/builtin_pre.go ValidateStatusTransition; internal/config/defaults.go DefaultHooksConfig allows done->{archived} only).

Related: stash 69B0B3F0 (medium, feature, not yet harvested): define, document, and enforce the work-item lifecycle state machine with a decision table of legal (command, artifact_type, current_status) transitions. This spike's decision table should feed that work; link related_to once 69B0B3F0 is harvested.
