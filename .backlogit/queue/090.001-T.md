Change the required CI workflow event model so the same validation is not executed on both pull_request and push to main. Prefer pull_request-only validation, or pull_request plus merge_group if a merge queue is adopted. Do not use workflow-level paths-ignore on required workflows.

<!-- BEGIN:acceptance-criteria -->
* ci.yml and the CLI drift workflow no longer run full validation on both push to main and pull_request for the same change lifecycle.
* Current PR-Review branch-ruleset required status checks Detect code changes, test, and Docline frontmatter gate still produce PR check runs that satisfy branch protection for code and docs/backlog-only changes; if CLI Reference Drift remains or becomes required, it also reports.
* Required-check satisfiability from the 2026-07-04 CI cost-gating plan is preserved: no required check is left pending or expected. Do not use workflow-level paths-ignore. Use job-level if only where the skipped check still reports and is verified mergeable; otherwise keep required jobs always running and gate heavy steps inside the job.
* The chosen trigger strategy remains compatible with P-009 by requiring up-to-date branches or using merge_group before merge commits land.
<!-- END:acceptance-criteria -->

Coordination note: if required-check names or workflow events change, the operator may need to update the PR-Review/main branch-protection ruleset before or alongside the workflow change.
