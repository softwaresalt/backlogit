Fail-closed TOP-LEVEL refusal in the exported generic `MoveShipmentStatus` entry point that
refuses any shipment `active<->blocked` transition BEFORE the transition-table edges are enabled.
This closes the ordering gap where R5 (174.043-T) enables the governed `active->blocked` edge and
R6 (174.044-T) enables `blocked->{queued,active}` in `isValidShipmentTransition` while the generic
`MoveShipmentStatus` refusal was previously not scheduled until R7a (174.045-T) — which exposed
ungoverned `active->blocked` at wave 5 and ungoverned unblock at wave 6 (no lock, no
intent/preimage, no member disposition). This task lands the refusal at WAVE 4, strictly BEFORE any
edge enablement, so every intermediate commit is safe.

Placement (CRITICAL — must precede the table check, not follow it like the `shipped` guard): add a
top-of-function fail-closed check in `MoveShipmentStatus`'s top-level path
(`internal/core/shipment.go`, `moveShipmentStatusWithHeadGuard` when `topLevel==true`) placed
BEFORE the `isValidShipmentTransition` call. It refuses when `newStatus == core.ShipmentBlocked`
(block direction) OR the shipment's current `oldStatus` is `blocked` (unblock direction), gated on
`ArtifactType=="shipment"`, with NO forgeable exemption flag. Because the check runs ABOVE the
transition table it refuses identically whether or not the R5/R6 edges are present, so the guard is
armed-and-active from the moment it lands (pre-edge: the direction is anyway unreachable through the
table; post-edge: the top guard refuses before the table would allow it). Returns the ALREADY-DECLARED governed
sentinel `blerrors.ErrShipmentBlockedRequiresEnvelope` (declared declaration-only by Rd 174.052-T
alongside `ErrNotImplemented`, mirroring the
existing `ErrShipmentShippedRequiresEnvelope`:
`errors.New("backlogit: shipment must be blocked/unblocked via the governed BlockShipment/UnblockShipment seam, not a direct status update")`).
This task WIRES the sentinel into the guard; it does NOT introduce the symbol — introducing it here
would create a declare-after-use cycle with R2 174.040-T (which references the sentinel and precedes
this task via its dependency on Rd 174.052-T).

Governed exemption is BY CONSTRUCTION: `BlockShipment`/`UnblockShipment` (R5/R6) write the
`active<->blocked` edge through the U2c seam-private lower-level persistence primitive that lives
BENEATH this choke point — they do NOT call the top-level `MoveShipmentStatus` entry point — so
they never traverse this refusal and need no flag. R7a (174.045-T) retains the REMAINING bypass
routing (generic move/update, bulk/cascade writes delegate to the governed writer); R7b
(174.051-T) retains create-as-active/generic-activation refusal. This task owns ONLY the
`MoveShipmentStatus` top-level block/unblock refusal moved out of R7a.

Domain: code. AC: (1) turns the `MoveShipmentStatus` block/unblock-refusal portion of R2
(174.040-T, `TestUR2_`) GREEN — the generic exported `MoveShipmentStatus` refuses BOTH directions
with `blerrors.ErrShipmentBlockedRequiresEnvelope`; (2) the refusal is placed above the
transition-table check so it holds identically before AND after the R5/R6 edges land (guard active
before any edge enablement); (3) the governed `BlockShipment`/`UnblockShipment` seam path is
unaffected (it never traverses this top-level entry point) and member `blocked` items are
unaffected (`ArtifactType=="shipment"` gate). <5 functions (1 top-level guard; optional

by Rd 174.052-T, not added here), <4 scenarios. Depends R2 (174.040-T), Rd (174.052-T).
