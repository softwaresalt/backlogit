# Size/complexity core_test fixture recovery isolation and internal/core Windows budget disposition

## Problem Frame

<!-- BEGIN:problem-frame -->
Stash 62C6A469 (DEFERRED SCOPE EXPANSION, P-021 C6 forced deliberate route). Three consecutive separately-authorized `go test ./...` runs on this Windows host (post-wave14 HEAD 3588cad2; post-174070 HEAD 46145ed5; post-wave17 HEAD eedc48a1, 803.433s) each failed ONLY because package internal/core hit the default 10m package timeout (602.093s / 600.818s / 602.192s). Every other package, including tests/integration, passed. At each deadline the reported running test was 0-1s old and parked in a DIFFERENT, unrelated, normal I/O stack: (1) gate ExecVersionRunner `autoharness version` process wait in TestShipShipment_RestoresNonMemberFeatureEvenWhenShipFailsAfterRollup (fixed since by 174.069-T GateBroker=nil); (2) recovery EvalSymlinks/FindFirstFile in setupTestWorkspace -> TestCreateArtifact_RejectsLevel2WithoutParent (fixed since by 174.071-T seam); (3) config.LoadTemplates ReadFile in setupSizeWorkspace -> TestSetArtifactSize_BusyLockReturnsErrTaskBusy. No lock waiter, holder cycle, or per-test hang appears in any stack. Root cause: cumulative wall time of the single internal/core test binary (881 top-level tests; 590 package core + 291 core_test) exceeds the 10m default on this host. The blamed fixture is incidental. Current-tree run order puts the three deadlines at about 59% -> 69% -> 79% of the test list, so each corrective helped, but the package is still over budget. A linear estimate puts the package near 760s, about 160s over budget; the distribution is non-uniform. The last-log silence after 60-90s in each capture is a diagnostics artifact: tests restore slog.SetDefault(prev), but the log package output stays redirected to the dead test buffer. It is not a hang.
<!-- END:problem-frame -->
