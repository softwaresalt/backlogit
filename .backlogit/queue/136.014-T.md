Follow-up hardening identified during 122-S PR review (Copilot, review-fix cycle 4, accepted as
backlog per the 3-cycle review-fix limit rather than blocking merge).

QuarantineCheckpoint classifies the target from bytes read earlier (parse+validate in memory), then
calls moveNoReplace, which links whatever file currently exists at the resolved path. If another
process atomically replaces the malformed checkpoint with a valid one between the classification
read and the move, this call would quarantine that valid replacement, violating the malformed-only
contract.

This is a narrow race requiring a concurrent process to atomically rewrite the exact same checkpoint
file at the exact moment between classification and move; it does not affect the common single-agent,
single-invocation usage pattern documented for this feature. Close it by either (a) holding an
advisory lock on the target across classification and move, or (b) re-verifying the source file's
identity (e.g. content hash or inode) immediately before the move under an appropriate synchronization
protocol, refusing if it has changed since classification.

Files likely touched: internal/core/checkpoint_disposition.go (QuarantineCheckpoint, moveNoReplace).
