Covering feature for CC0EBB59 (re-validated via stash C29EBEE5). ENABLING PRECONDITION, not full defect resolution: adds an additive, backward-compatible scheduler-baseline marker — the single custom_fields key scheduler_baseline_claim, value = activating shipment ID — written by ClaimShipment on every manifest member whose preimage status was queued, so a claim-activated manifest task can be told apart from an organic active residual. The observable P-002.6 misclassification is resolved only once the out-of-workspace autoharness scheduler consumes the marker.

Option A lifecycle (operator decision 2026-09-28, docs/decisions/2026-09-28-173f-marker-lifecycle-option-a-decision.md): the marker is kept through block, unblock, ReturnBlockedItem, ship, abandon, normalize and generic writes; it is removed only by rollback (exact preimage restore). Consumer predicate (normative, published by U5): an item is claim-activated iff status == active AND its marker == the ID of the currently active shipment AND it is in that shipment's current items manifest; "non-empty => claim-activated" is withdrawn.
