Pure ResolveVerificationKey(role|id, at time) honoring not_before/not_after rotation and returning the active key; not-yet-valid and expired inputs return typed errors. Revocation (status==revoked) and ambiguity (multiple active matches for a role) error paths are carved into 168.015-T (plan-review cycle-1 item 9). Single reusable primitive consumed by 169-F and 170-F. Domain: core (pure, internal/core). TDD: RED table-driven harness first. Depends on 168.002-T. Executable scenarios (3): (a) returns the active key inside not_before/not_after with status=active; (b) a not-yet-valid key returns a typed error; (c) an expired key returns a typed error. Build/test: go build ./cmd/backlogit; go test ./internal/core/ -run TestTrustedKeyResolver. AC: (1) the active key is returned inside its validity window; (2) not-yet-valid returns a typed error; (3) expired returns a typed error; (4) pure (no I/O), proven by table-driven tests; (5) revoked/ambiguous paths delegated to 168.015-T; (6) SECURITY (cycle-1 F1): resolution is role-scoped -- caller requests a key by purpose (attestation-signer vs token-issuer) and an anchor whose role does not match is rejected, preventing cross-protocol key reuse; (7) SECURITY (cycle-1 F4): the resolved key carries the anchor pinned algo so callers verify with the pinned algorithm, never a payload-declared one (incl. none).
