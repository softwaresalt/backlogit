ArchiveItem preservation guard for re-archived items (reconcile durability). ArchiveItem currently sets fm["archived_status"] = oldStatus where oldStatus = fm["status"] (archive.go:159,230). For an ALREADY-archived item (re-archive / pre-archived branch, currentPath==archivePath, archive.go:224), oldStatus == "archived", so line 230 OVERWRITES an existing archived_status (e.g. reconcile's archived_status: shipped) with the malformed self-provenance "archived", serially destroying the reconciled state AFTER reconcile has released its locks (C->B locking cannot protect a later serial write). GUARD: when ArchiveItem runs on an item whose status is ALREADY archived (re-archive path), it MUST NOT overwrite a non-empty existing archived_status; PRESERVE the existing value. Only the genuine queued->archive transition (oldStatus != archived) stamps archived_status = oldStatus. This also fixes the latent general bug where re-archiving ANY archived item corrupts archived_status to "archived". TDD (policy): behavior harness FIRST — (a) re-archiving a reconciled shipment (status:archived, archived_status:shipped) PRESERVES archived_status:shipped; (b) genuine queued->archive still stamps archived_status = pre-archive status (byte-for-byte unchanged); (c) cascade re-archive preserves each descendant's terminal archived_status — then implement. Single domain (archive guard). Domain: code. Files internal/core/archive.go + test. No new deps (edits an existing function).
