Fix rehydration ghost entries caused by deleted markdown files persisting in the SQLite index.

Files: internal/db/rehydration.go
Test files: internal/db/rehydration_expansion_test.go
Execution note: test-first

Root cause: Rehydrate() uses UpsertItem (INSERT OR REPLACE) which only adds/updates items. When markdown files are deleted, their index entries persist as ghosts. 11 ghost entries currently exist (F015.T009-T011, F016.T008-T014, DL002).

Approach:
1. At the top of Rehydrate(), after DeleteAllItemLogs, add DELETE FROM items and DELETE FROM item_deps in sequence.
2. Do NOT clear item_links (populated by explicit tool calls and MigrateCustomFieldLinks, not rehydration).
3. FTS content table cleanup handled automatically by the items delete trigger.
4. (Review F-2: At current scale of hundreds of items, per-row FTS trigger firing is acceptable.)

Verification:
- Test: create workspace with 2 artifacts, rehydrate (both appear), delete one markdown file, rehydrate again, verify only survivor in index
- After sync, ghost items no longer appear in list_items or query_sql
