Verification only — P-002.1 `verification-only` harness-exempt unit. This task
records green evidence for behavior already delivered by its prerequisites (the
four mandatory quality gates go green as U1–U11, U13, and U14 land); it commits
ONLY its named evidence artifact and adds NO new red assertion, so it scaffolds
no red harness. It is a member of the plan's closed harness-exempt set (see the
"Harness-Exempt Set (closed)" section of
`docs/exec-plans/2026-09-17-baseline-convergence-plan.md`); U12 is the SOLE member.

The `exempt_verification_command` EXECUTES the four mandatory gates directly (it
does NOT trust hand-authored claims): it runs `go test ./...`, `go vet ./...`,
`golangci-lint run`, and `gofmt -l .`, FAILS on any nonzero exit, and SEPARATELY
FAILS when `gofmt -l .` stdout is non-empty. Only after all four gates pass does
it validate the evidence artifact and its marker. The evidence artifact MUST be
generated from the observed command results captured during this task, never
hand-authored.

Deliverable (evidence artifact — verification-only class delta surface, under
`docs/closure/`): `docs/closure/175-baseline-convergence-convergence-evidence.md`,
generated from the observed gate outputs. The artifact MUST record each of the
four gates as green using these EXACT marker strings (one per gate) plus the
nolint enumeration section header, which are the strings the
`exempt_verification_command` asserts AFTER it has itself re-run and confirmed the
gates:

- `go test ./...: GREEN`
- `go vet ./...: GREEN`
- `golangci-lint run: GREEN`
- `gofmt -l .: GREEN`
- `//nolint enumeration:` (section header, followed by the full enumerated list)

Must-fail-before-deliverable: on the pre-work tree the four gates are RED (the
errcheck/staticcheck/gofmt debt is unremediated), so the command exits non-zero;
and even once the gates are green, the command still exits non-zero until the
evidence artifact exists and records all five required strings. Only after BOTH
the gates pass AND the deliverable lands does it exit 0 and print its unique
`EXEMPT_VERIFY_OK:175.012-T` marker.

Acceptance criteria:
- Scope (files): only the evidence artifact under `docs/closure/` (verification-only
  class delta surface — no non-test `*.go` file and no repository-configuration file
  is changed).
- Runnable gate execution: the `exempt_verification_command` itself runs
  `go test ./...`, `go vet ./...`, `golangci-lint run`, and `gofmt -l .`, fails on any
  nonzero exit, and fails when `gofmt -l .` prints any path — it does NOT rely on a
  test selector's exit status or on string-only evidence.
- Evidence provenance: the evidence artifact is generated from the observed command
  results (not hand-authored claims) and records all four mandatory gates green with
  the exact marker strings above and the full enumerated `//nolint` suppression list
  with justifications.
- Must-fail-before-deliverable: the command fails on the pre-work tree (gates red) AND
  fails whenever the evidence artifact is absent or missing any required string; it
  passes (exit 0 + `EXEMPT_VERIFY_OK:175.012-T`) only after the gates are green AND the
  deliverable lands.
- Posture: runtime-verification. Terminal sink node (unblocks 149-S).
