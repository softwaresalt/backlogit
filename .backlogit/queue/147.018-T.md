Plan unit **U9b**. Update `.github/instructions/backlogit.instructions.md` (requirement R10).

Files: `.github/instructions/backlogit.instructions.md`.

The shipped Continuity Protocol §6 currently tells agents a rejected create "means retry with the offending keys nested under context… there is nothing to recover". That advice is correct for **create** and wrong for a **stored legacy** document, where the keys are already on disk and the only safe path is quarantine.

Add:
* a clause stating a stored checkpoint carrying unmodeled top-level keys cannot be resolved or abandoned, and that the routed remedies are hand-repair or quarantine
* the **body-preserving repair path**, written as **one** procedure with two entry points so this file, plan unit U9b, and the U10 restore row cannot drift apart. Without it an operator reads "quarantine" as "throw the session state away".

**Canonical repair procedure (single flow, two entry points).**

* **(a) Direct repair** — the document is still under `.backlogit/checkpoints/`. Open it, move every unmodeled top-level key under `context`, re-run `checkpoint get` to confirm `conforming: true`, then use the normal verb (`resolve` or `abandon`).
* **(b) Post-quarantine restore** — the document was already quarantined. Copy the archived bytes back from `archive/checkpoints/` into `.backlogit/checkpoints/`, then apply step (a) unchanged.

Both entry points preserve the original document body. Neither creates a **replacement** checkpoint: a fresh file would abandon the original filename, `created_at`, and session identity, so "quarantine, then create a new conforming checkpoint" is a different operation and must not be written as the repair path.
