170.008-T [4E210DB4]. Move nonce single-use consumption state to externally-protected, rollback-resistant storage and consume it via an ATOMIC COMPARE-AND-CONSUME (compare-and-swap on a monotonic external counter / externally protected reference) so that ledger deletion/truncation cannot re-enable replay and two concurrent consumers cannot both succeed; fail closed if the external state is unavailable. Option A (externally protected atomic compare-and-consume) is REQUIRED before 151-S is marked complete, shipped, archived, or presented as merge-ready — 151-S MAY be CLAIMED so its members implement this external compare-and-consume control (claim-time is NOT the gate; the hard gate is PRE-COMPLETION / PRE-SHIPPING / merge-readiness). Documentation-only closure is NOT acceptable for this replay/privilege-escalation vector (consistent with 168 Decision 1 and 168.008-T). If Option A is infeasible: block 151-S from completion/shipping/merge-readiness (never at claim time), OR retain a fold ONLY behind a hard-reviewed non-exploitability proof that RESTS ENTIRELY ON INDEPENDENTLY-PROTECTED STATE the workspace writer cannot forge or replay (e.g., externally-issued request-identity binding + externally-enforced short not_after + reconcile idempotency reducing replay to a no-op/conflict) — a proof that depends on any self-suppliable in-workspace state is NOT acceptable. EXPLICITLY EXCLUDED as a fold basis: archived_status and any other workspace-resident reconcile/ledger frontmatter (the concurrency CAS guards it only against concurrent stale overwrite, NOT against a deliberate workspace-writer reset), and any reconcile-idempotency record that is not itself externally protected and bound to the same external pin root of trust as the nonce store. Domain: code. Depends on 170.003-T, 170.010-T (RED). AC: deleting/truncating the in-workspace ledger does not permit replay of a still-valid token via atomic external compare-and-consume (Option A); OR a hard-reviewed non-exploitability proof grounded solely in externally-protected state (NOT archived_status or any workspace-resident idempotency record) is approved, else 151-S is blocked from completion/shipping/merge-readiness (never at claim time); the 170.010-T RED replay test transitions RED->GREEN.
