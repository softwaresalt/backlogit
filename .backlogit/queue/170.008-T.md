Nonce single-use ATOMIC compare-and-consume via an injected external rollback-resistant provider + consume audit (behavior). SINGLE AUTHORITATIVE nonce-consume owner (cycle-3 item 11: the competing 170.017-T is REMOVED and its atomic check-then-consume seam + consume-audit + consumed-but-audit-missing outcome folded here). Workspace containment (Constitution IV / cycle-3 item 4): the consume goes through an INJECTED non-filesystem authority provider (a monotonic counter / compare-and-swap capability) -- NO mutable filesystem writes outside the workspace are authorized; the workspace holds only a contained projection/audit of consumption. Atomic compare-and-consume: the presence check and the consume are a single atomic CAS so in-workspace ledger deletion/truncation cannot re-enable replay and two concurrent consumers cannot both succeed; fail closed if the provider is unavailable. Consumed-but-audit-missing: when the CAS consume succeeds but the consume-audit write fails, the result is a typed INDETERMINATE outcome (nonce definitively consumed, audit missing) surfaced fail-closed -- the consume is NEVER rolled back (rollback would re-enable replay); the missing audit is an operator-visible gap, not an automatic replay re-enable and not a new recovery subsystem. Gate: this atomic external compare-and-consume is REQUIRED before 151-S is completed, shipped, archived, or presented as merge-ready (claim-time is NOT the gate); documentation-only closure is NOT acceptable for this replay/privilege-escalation vector. Domain: core (internal/core). TDD: RED harness first including a concurrency probe, observed failing. Depends on 170.003-T, 170.010-T (RED). Executable scenarios (3): (a) an atomic compare-and-consume via the injected provider succeeds once and persists a consume audit, and deleting/truncating the in-workspace projection does not permit replay of a still-valid token (the 170.010-T RED replay test transitions RED->GREEN); (b) two concurrent consumes of the same nonce yield exactly one success and one typed replay rejection (atomicity), and a provider-unavailable condition fails closed; (c) a consume that succeeds but whose consume-audit write fails yields a typed INDETERMINATE outcome, the nonce stays consumed (no rollback, no replay re-enable), and the audit gap is operator-visible.
