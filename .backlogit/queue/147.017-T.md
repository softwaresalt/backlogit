The shipped doc states abandon and quarantine are "disjoint by design" over `{valid, malformed}`. That dichotomy is now a **four-class** classification over `status: "active"` documents **with no administrative disposition**:

| Class | abandon | resolve | quarantine |
|---|---|---|---|
| valid + conforming | accept | accept | refuse (`ErrCheckpointUseAbandon`) |
| valid but non-conforming | refuse (`ErrCheckpointNonConforming`) | refuse (`ErrCheckpointNonConforming`) | **accept** |
| parses but schema-invalid | refuse (`ErrCheckpointUseQuarantine`) | refuse (`ErrCheckpointUseQuarantine`) | accept |
| does not parse | refuse (`ErrCheckpointUseQuarantine`) | refuse (`ErrCheckpointUseQuarantine`) | accept |

**Administrative disposition precedence.** `ResolveCheckpoint` checks disposition **before** the four-class validity/conformance classification. A document that has been administratively abandoned (`disposition: abandoned`) returns `ErrCheckpointCannotResolveAbandoned` from `resolve` regardless of its validity or conformance class — the disposition guard fires first. This precedence guard is a regression test for the implemented check order, not a new feature; it is captured as a separate section so the four-class table above remains accurately scoped to "active documents with no administrative disposition".

Row 3 must be written out separately rather than folded into "malformed": it is the exact shape of the nine live legacy files — they parse cleanly and fail `ValidateCheckpoint` — so a table that only names parse failure is **not total** over active checkpoints and omits the very class this feature exists to handle.

Record explicitly that the classification is **total only over `status: "active"` documents with no administrative disposition** (I3 scoping, pinned by U5 / 147.009-T), and that the invariant preserved is C2 — a document that cannot be trusted to round-trip is moved verbatim, never rewritten.
