Plan unit **U6c**. Make the MCP read surface report what 147.012-T computes.

Files: `internal/mcp/tools.go`, `internal/mcp/checkpoint_disposition_test.go`.

`handleGetCheckpoint` (`internal/mcp/tools.go:1194-1212`) returns a **literal** `"valid": true` and carries no conformance field, so the MCP read surface would keep answering the superseded question after 147.012-T lands. Call `events.GetCheckpointResult` and project `valid`, `conforming`, `needs_quarantine`, and `remediation_command` from the returned result. The hardcoded `"valid": true` is removed, not shadowed.

Without this task, 147.014-T's `get_checkpoint` description and 147.016-T's MCP `get` parity rows would describe behaviour no task implements.

**The CLI twin is 147.027-T (U8c).** `newCheckpointGetCmd` carries the same hardcoded literal on the CLI side and is owned by that task, added in PR #377 Copilot review cycle 4. This task must not change the CLI command, and 147.027-T must not change the MCP handler; the two are the same shape on different surfaces, and 147.016-T asserts they agree.

**Schema-invalid documents keep their existing refusal.** `handleGetCheckpoint` routes errors through `domainError` (`internal/mcp/errors.go:148`), which takes no filename and already maps `ErrCheckpointInvalid` to `code: validation_failed`. 147.012-T returns that sentinel **unwrapped** from `GetCheckpointResult`, so `get` on a legacy file surfaces the pre-existing validation-class refusal — **not** `checkpoint_use_quarantine`, which 147.013-T only ever emits from `checkpointDispositionError` on the *mutation* handlers. Demanding a disposition code here would require re-routing the read handler through a mutation-shaped error path, widening this task into 147.013-T's file set and changing a shipped read contract for no safety gain: the quarantine remedy is already discoverable from `list_checkpoints`, which reports `needs_quarantine: true` for the same file (147.011-T). This task therefore **pins** the existing behaviour rather than changing it, and drops its dependency on 147.013-T.
