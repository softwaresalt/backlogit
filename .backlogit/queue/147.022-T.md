Plan unit **U6c** (partition 4). MCP `backlogit_get_checkpoint` projects the conformance verdict.

Files: `internal/mcp/tools.go`, `internal/mcp/checkpoint_disposition_test.go`.

`handleGetCheckpoint` (`internal/mcp/tools.go:1194-1212`) returns a literal `"valid": true` and carries no conformance field. Call `events.GetCheckpointResult` and project `valid`, `conforming`, `needs_quarantine`, `remediation_intent`, and `non_conforming_fields`; the hardcoded literal is removed, not shadowed.

**Cycle-17 shapes.** `non_conforming_fields` is the object `{"paths": [...], "truncated": bool, "omitted_paths": int, "truncated_paths": int}` copied straight from `CheckpointReadResult.NonConformingFields`. This handler must not re-derive it from a typed error, must not re-cap it, and must not quote its entries. `remediation_intent` is the structured `RemediationIntent` object (147.032-T / U1d) - the MCP surface publishes no shell string, so an agent cannot paste an unbound command out of a tool response.

**Schema-invalid documents keep their existing refusal.** `handleGetCheckpoint` routes errors through `domainError`, which already maps `ErrCheckpointInvalid` to `validation_failed`. Demanding a disposition code here would route a read through a mutation-shaped error path and change a shipped contract for no safety gain: the quarantine remedy is already discoverable from `backlogit_list_checkpoints`.

Red verification: `go test -count=1 -run '^TestU6c_' ./internal/mcp`.
