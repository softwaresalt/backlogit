Plan unit **U7b**. Update the **two read-surface** MCP checkpoint tool descriptions.

Files: `internal/mcp/tools.go` (descriptions at `:176-192`), `internal/mcp/tools_test.go`. If `.autoharness/backlog-registry.yaml` carries description text for these two tools, update it in the same commit and re-run `internal/cli/registry_parity_test.go`.

**Scope note.** The three **mutation-surface** descriptions (`resolve_checkpoint`, `abandon_checkpoint`, `quarantine_checkpoint`) moved to **147.024-T** (U7c). Five rows in one task exceeded the four-scenario limit and mixed a read contract with a refusal contract; the split is by surface, so each half is verifiable on its own.

Tool descriptions are the **only** contract most agents ever read; they are the primary context surface. Leaving them stale means an agent trusts `valid: true` for a document `list_checkpoints` has already flagged.

Exact replacement strings (current text captured verbatim in the plan):

| Line | Tool | Delta |
|---|---|---|
| `:178` | `list_checkpoints` | append: ` A summary with needs_quarantine true is not safely rewritable; use quarantine_checkpoint, not resolve_checkpoint or abandon_checkpoint.` |

The `get_checkpoint` qualifier is load-bearing. `GetCheckpoint` runs `ValidateCheckpoint` and returns `ErrCheckpointInvalid` before any conformance result exists (`internal/events/checkpoint_lifecycle.go:~105-137`), so an unqualified promise of `conforming false` for every document with unmodeled top-level keys would describe a verdict the read path cannot produce for the nine legacy files. This table is reproduced verbatim in plan unit U7b; the two must not drift.
