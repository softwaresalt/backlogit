## Findings

### P2 — No CHECK constraint on `item_links.link_type` (manual follow-up)

**File**: `internal/db/` (schema definition)  
**Reviewer**: SQLite Reviewer  
**Action**: `manual`

The `isValidLinkType` gate added in `rehydration.go` and `merge_sync.go` enforces link type validation at the application layer, which is correct. However, the SQLite schema has no `CHECK (link_type IN ('related_to', 'duplicate_of', 'informs', 'supersedes', 'spike_ref'))` constraint on the `item_links` table. This means any code path that writes directly to `item_links` (e.g., via raw SQL in tests or future tools) bypasses validation without compile-time or DB-level enforcement.

**Recommendation**: Add a CHECK constraint to the `item_links` table schema and migrate existing databases. Tracked as follow-up.

---

### P2 — Full-file read in `extractItemIDFromFrontmatter` (advisory)

**File**: `internal/db/manifest.go`  
**Reviewer**: SQLite Reviewer  
**Action**: `advisory`

The previous 512-byte scan was replaced with `os.ReadFile` + `models.ParseFrontmatter` to fix a correctness bug (IDs beyond byte 512 were invisible to relocation detection). The fix is correct. On workspaces with 10,000+ artifacts, the manifest rebuild now reads every file in full — a potential performance concern. In practice backlogit workspaces rarely exceed a few hundred artifacts, and the correctness fix takes priority over the micro-optimization.

**Recommendation**: Monitor manifest rebuild time on large workspaces. If needed, a future optimization could use a streaming YAML parser that stops after the frontmatter block.

---

### P3 — `isValidLinkType` linear scan (advisory)

**File**: `internal/db/rehydration.go`, `internal/db/merge_sync.go`  
**Reviewer**: SQLite Reviewer  
**Action**: `advisory`

`isValidLinkType` iterates a 5-element slice on every link. A `map[string]struct{}` would be O(1). At 5 elements this is unmeasurable in practice.

**Recommendation**: Low-priority optimization; convert to map lookup if the valid set grows.
