Remove redundant under-lock request-identity-digest recomputation; thread precomputed digest (behavior). Created per plan-review cycle-2 item 3, grounded in authoritative code. FACT: shipmentReconcileRequestIdentityDigestForNormalized is computed lock-free pre-lock in shipment_reconcile_transaction.go (~line 76) and threaded through, BUT prepareShipmentReconcileEvidence RECOMPUTES it at internal/core/shipment_reconcile_evidence.go:186 while the Phase-A membership lock is held (called from reconcileShipmentPhaseCAndD, transaction.go:281). This task removes the second computation site and threads the single precomputed digest into prepareShipmentReconcileEvidence so the digest is computed exactly once, before any lock, eliminating drift and lock-held recomputation. This is the behavior that 170.011-T design documents; 170.011-T is a forward reference (docs) and cannot claim behavior no task owns. Domain: core (internal/core). TDD: RED harness first asserting the digest is computed once and identical to the pre-lock value. Depends on 170.011-T.
