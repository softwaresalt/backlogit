Config unit and STRICT PREDECESSOR of all code units (U2, U3, U4-U11, U13). Scope: `.gitattributes` line-ending hardening + whole-tree `git add --renormalize .`. Declared file-count exception (content-identical churn); single-domain (config).

APPROVAL GATE (blocking): MANDATORY, explicitly-recorded OPERATOR-ONLY approval of the renormalization diff immediately BEFORE the commit lands. Ship may prepare and present the diff and its verification evidence but CANNOT authorize the renormalization; authorization is the operator's alone.

Changes:
- Add explicit `eol=lf` rules for `*.go` and `*.json`.
- For the byte-exact golden fixture, FIRST normalize its committed bytes to LF (rewrite the working-tree fixture to LF and stage it) BEFORE applying any `-text` treatment, OR prefer a `eol=lf` attribute that preserves LF rather than `-text`. Do NOT stage CRLF golden bytes under `-text` (that would freeze CRLF as the canonical bytes).
- Pin true binaries (`*.exe`, `*.db`, images, intentionally-binary fixtures) as `-text`.
- Run `git add --renormalize .`. Because `--renormalize` refreshes the INDEX but does NOT rewrite working-tree `.go`/`.json` files, EXPLICITLY refresh/rewrite the affected working-tree files (e.g. re-checkout or rewrite to LF) AFTER the index renormalization and BEFORE asserting `w/lf`.
- Add a durable CI guard that fails on line-ending re-drift.

Safety checks (corrected):
- Assert `git ls-files --eol` shows `w/lf` for tracked `.go`/`.json` ONLY AFTER the working-tree refresh above; `-text` (or `w/lf` under the `eol=lf` variant) for the golden; `-text` for declared binaries.
- Content-identity (EOL-only proof): do NOT use `git diff --cached -w` — `-w` ignores ALL intra-line whitespace, not just line-ending bytes, so it would mask a genuine non-EOL whitespace edit. Instead, for each staged text path EXCLUDING `.gitattributes` and declared binaries, compare base vs index blob content after canonicalizing ONLY CRLF->LF: `B = git cat-file blob HEAD:<path>`, `I = git cat-file blob :<path>`; replace every CRLF (`\r\n`) with LF (`\n`) in each (leaving every other byte, including any bare CR, untouched); require `SHA-256(canon(B)) == SHA-256(canon(I))` for every path. Equal hashes prove ONLY line-ending bytes changed; any non-EOL byte difference fails the check. Exclude `.gitattributes` because it changes content by design.
- Binary identity: do NOT treat `git diff --cached --numstat` `-`/`-` as proof of byte-identity (`-`/`-` marks binary CLASSIFICATION, not unchanged bytes). Instead require each declared binary to be ABSENT from the staged diff, OR compare its pre/post blob hashes (`git rev-parse :<path>`) and confirm identical.

Acceptance criteria:
- `.gitattributes` declares `eol=lf` for `*.go`/`*.json`, LF-preserving treatment for the golden fixture, and `-text` for all true binaries.
- After renormalization + working-tree refresh, `git ls-files --eol` reports `w/lf` for all tracked `.go`/`.json`.
- Content-identity confirmed by the EOL-only normalized-blob SHA-256 comparison (CRLF->LF canonicalized, all non-EOL bytes preserved), `.gitattributes` and declared binaries excluded — no non-EOL content change.
- Every declared binary proven byte-identical by staged-diff absence or blob-hash equality (NOT by numstat `-`/`-`).
- Operator-only approval of the renormalization diff is recorded before the commit lands.
- CI guard present and fails on re-drift.
