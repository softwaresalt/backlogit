Plan unit **U7**. MCP error **mapping layer** — the response shape and the code table.

Files: `internal/mcp/errors.go`, `internal/mcp/checkpoint_disposition_test.go`.

**Scope note.** The handler-routing half of the original U7 — making `handleResolveCheckpoint` reach the disposition shape at all — moved to **147.025-T** (U7d) because it touches `internal/mcp/tools.go` and would have taken this task to three files across two behavioural surfaces. This task owns `errors.go` only.

1. `checkpointDispositionError` (`internal/mcp/errors.go:309`) emits `checkpoint_use_quarantine` today; add `ErrCheckpointNonConforming` with `Code: "checkpoint_non_conforming"`. Its existing `ErrCheckpointNotFound` → `NotFound` case and its `default: InternalError` tail both stay as-is.
2. The two response shapes are incompatible: `checkpointUnknownFieldsResponse` (`:29-39`) carries `error`/`message`/`unknown_fields`, `checkpointDispositionErrorResponse` (`:291-299`) carries `error`/`message`/`code`/`filename`/`retryable`/`outcome`/`remediation`. Extend the latter with `UnknownFields []string` — **no `omitempty`** — populated via `errors.As`.
3. `domainError` (`:148`) is the fallback surface for handlers that carry no filename. It already maps `ErrCheckpointInvalid` to `validation_failed` (grouped with `ErrValidation` and `ErrCheckpointCorrupt`) and already has a dedicated `ErrCheckpointUnknownField` case, so **only** `ErrCheckpointUseQuarantine` and `ErrCheckpointNonConforming` are missing. Add them as a **safety net** mapping to the same two codes, so a refusal reaching a handler that has not been re-routed can never surface as a 500.

Add the two rows to the mapping-table doc comment (`:127-144`).

4. The three disposition-class remediation strings — `checkpoint_use_quarantine`, `checkpoint_use_abandon`, and the new `checkpoint_non_conforming` — currently name a hardcoded originating verb (the shipped `checkpoint_use_quarantine` string is `"this target is malformed; call backlogit_quarantine_checkpoint instead of backlogit_abandon_checkpoint"`). After **147.025-T / U7d** routes `handleResolveCheckpoint` through the same formatter, that hardcode would advertise `backlogit_abandon_checkpoint` as the operator's original verb on a resolve refusal — a lie that would send the operator to the wrong entry point. The formatter already receives `op` (`"abandon checkpoint"`, `"quarantine checkpoint"`, and after U7d `"resolve checkpoint"`); derive the operator-facing verb from the first word of `op` and interpolate `backlogit_<verb>_checkpoint` into the "instead of" clause of each of the three disposition-class remediations. This makes the formatter operation-aware without adding a new parameter, keeps this task's ownership scoped to `errors.go` only (handler-side assertions are 147.025-T's boundary), and lets 147.025-T pin `backlogit_resolve_checkpoint` as the resolve-side verb from the handler direction. The remedy verb itself (`quarantine` for the two "target is malformed / non-conforming" classes, `abandon` for the "target is valid" class) is **unchanged**; only the wronged verb becomes op-derived.

**Correcting a stale plan claim.** Earlier plan text asserted `domainError` had "no case for `ErrCheckpointUseQuarantine`, `ErrCheckpointInvalid`, or `ErrCheckpointNonConforming`". The `ErrCheckpointInvalid` third of that claim is false against `internal/mcp/errors.go:~188-193` and is corrected in plan unit U7; the acceptance criteria below are scoped to the two sentinels that are genuinely absent.
