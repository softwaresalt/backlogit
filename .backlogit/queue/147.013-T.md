Plan unit **U7**. MCP error mapping and response shape — three coupled defects in the mapping layer.

Files: `internal/mcp/errors.go`, `internal/mcp/checkpoint_disposition_test.go`.

1. `handleResolveCheckpoint` (`internal/mcp/tools.go:1214-1225`) routes through `domainError`, which has **no case** for `ErrCheckpointUseQuarantine` (and must gain `ErrCheckpointNonConforming`). Without this every new refusal falls to `default: InternalError` and surfaces to agents as a 500.
2. `checkpointDispositionError` emits `checkpoint_use_quarantine` for the abandon/quarantine handlers only; add `ErrCheckpointNonConforming` with `Code: "checkpoint_non_conforming"`.
3. The two response shapes are incompatible: `checkpointUnknownFieldsResponse` (`:29-39`) carries `error`/`message`/`unknown_fields`, `checkpointDispositionErrorResponse` (`~:290-300`) carries `code`/`filename`/`retryable`/`remediation`. Extend the latter with `UnknownFields []string` — **no `omitempty`** — populated via `errors.As`.

Add the row to the mapping-table doc comment (`:127-144`).

<!-- BEGIN:acceptance-criteria -->
- Invoking the **`handleResolveCheckpoint` handler** on a legacy document returns `checkpoint_use_quarantine` and explicitly asserts the payload is **not** `"error":"internal"`
- Invoking `handleAbandonCheckpoint` on a non-conforming target returns `checkpoint_non_conforming` with `unknown_fields` read through a `.([]any)` type assertion so an absent or `null` key fails
- A conforming refusal returns `unknown_fields: []` rather than omitting the key
- Expected red: all three fail
