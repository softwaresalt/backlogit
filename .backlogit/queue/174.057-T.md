Flatten the lifecycle **release-scope derivation** to flat explicit membership (spec §0.5 / SBLK-R28; plan §0.4). Green-maker for `174.055-T` (`TestUReleaseScopeFlat_`) **and `174.059-T` (`TestURollbackScopeFlat_`)**.

**(1) Flatten the derivation seam in place (retain the seam — do NOT bypass it).** Change `releaseScopeItemIDs` (`internal/core/shipment_lifecycle.go:1142`) to normalize/dedupe its input and return the flat explicit manifest — `return uniqueNonEmptyStrings(itemIDs)` — removing the `descendantItems` BFS expansion (`:1150-1160`). **Retain the function as the derivation seam** with the same name and signature; line 549 still calls `releaseScopeItemIDs(ctx, ws, explicitScope)`. Do NOT replace the call with a direct `explicitScope` assignment: `174.055-T` pins `releaseScopeItemIDs` itself, so RED and GREEN target the **same function**, not a bypass. All callers then consume its flat result — the member-evidence set / `validateMemberGateEvidence` (via the `releaseScope` argument to `gateShipmentCompletion`) and `completeReleaseScope` flatten transitively with no change to their own logic.

**(2) Neutralize the independent rollback/snapshot expansion (`:603-612`).** The rollback lock + snapshot + restore set is NOT derived from the flat `releaseScope` parameter — the closure builds it **independently**: `rollbackIDs := append([]string{shipmentID}, releaseScope...)`, then appends `featureIDs` and, for each, every `descendantItems(featureID)`. Remove that ancestor+descendant append so the set becomes `{shipmentID} ∪ flat releaseScope` only — this is exactly the set handed to `lockArtifactMutations` and `snapshotShipArtifacts` (and restored by `restoreShipArtifacts` on failure). This makes `174.059-T` green. Covering-feature **status-rollup** protection is a SEPARATE mechanism (the `nonMemberFeatureSnapshots`/`restoreRolledUpNonMemberFeatures` status-revert path), not this artifact snapshot/lock set; **this task leaves it in place** (`featureIDs`/`snapshotNonMemberFeatureStatuses` remain in use here). That non-member status-rollup path is **ELIMINATED as a follow-on by `174.062-T` (SCOPE-IMPL-3)**, which resolves the P1 concurrency defect this task would otherwise expose — once the ancestor is dropped from the outer lock (this task), snapshotting then restoring its status without a lock allows a concurrent mutation between snapshot and restore to be overwritten. This task neither perturbs nor depends on the removal beyond leaving the path intact pending `174.062-T`.

**Consumers that re-expand independently are OUT OF SCOPE here and handled by `174.058-T`:** `returnUnreleasedFeatureItems` (`:735`) and the covering-feature descendant loop (and its `linkedDeliberationIDs` append) inside `collectArchiveCandidateIDs` (`:800`) call `descendantItems(featureID)` / `linkedDeliberationIDs(feature)` directly and are NOT flattened by changing the derivation or the rollback set — do not rely on this task to neutralize them.

Preserve parent-first ordering as manifest ORDERING (deterministic order from the manifest), never as expansion. Introduce **no public/exported API** — `NormalizeShipmentItems` unchanged; internal behavior change only (no new source-shape seam). Remove descendant expansion from `releaseScopeItemIDs` and the rollback/snapshot set; retain `descendantItems` for the callers `174.058-T` handles. Do NOT restore any archived/superseded task.
