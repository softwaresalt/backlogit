# CLI/MCP command parity: audit, honest fallback map, highest-value gap fills

## Problem Frame

<!-- BEGIN:problem-frame -->
Agents depend on MCP tools; when MCP is unavailable/degraded they need a discoverable CLI fallback with equivalent capability. The .autoharness/backlog-registry.yaml operation map (the fallback map) has silently drifted from the real surfaces: grounded against 56 MCP tools (backlogit manifest) vs the actual cobra CLI tree, 9 rows are STALE (CLI exists but column empty), 3 ops are MISSING entirely (docs_lint/migrate/scope), and 3 rows OVER-CLAIM a non-existent 'link' CLI command (add_link/remove_link/get_links) which would make an agent run a command that does not exist. True CLI gaps (no CLI) total 14, highest-value being add_to_shipment.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) Fill ALL gaps now (large, mixes net-new command surfaces + high risk of scope blow-out). B) Fill highest-value gaps now + make the registry HONEST + add a drift-detection test, and DEFER net-new command surfaces to a phase-2 stash with documented intentional exceptions (chosen). C) Documentation-only (rejected: leaves real workflow gap add_to_shipment and the dangerous over-claim unfixed).
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B. Ship: (T1) parity audit matrix; (T2) correct the registry op-map drift AND add a reflection/enumeration drift-detection test so it cannot silently re-drift (per 063-S manual-schema-registry-drift-detection pattern); (T3) add 'backlogit shipment add' CLI mirroring add_to_shipment (highest-value workflow fallback gap); (T4) fold in stash 7ECBAC7E by calling the existing core.NormalizeShipmentItems in the CLI shipment-list handler + a cross-surface null-vs-[] guard test; (T5) discoverability + a documented CLI-fallback guide (grouped help, export_command_map accuracy). Defer link CLI group, checkpoint create, hook poll/ack, save_memory, append_comment, wit/types/templates, merge_sync to a phase-2 stash.
<!-- END:chosen-direction -->
