Plan unit **U1b**. The single bounded diagnostic projection for `CheckpointNonConformingError` field paths.

Files: `internal/errors/checkpoint_errors.go`, `internal/errors/checkpoint_errors_test.go`.

Split out of 147.001-T / U1 in PR #377 cycle 16. Cycle 15 attached quoting and bounding to `Error()` as a "contract constraint, not a fourth scenario". Two problems: a cap-trip case **is** a fourth effective flow inside U1, and bounding only `Error()` leaves the MCP `unknown_fields` array free to carry the raw `Fields` slice — the CLI would be bounded while the MCP payload was not.

Add the exported method:

```go
// BoundedFieldPaths returns the offending key paths quoted and capped for
// safe rendering into an operator message, an MCP payload, or a CLI line.
func (e *CheckpointNonConformingError) BoundedFieldPaths() []string
```

It returns the sorted, de-duplicated paths from `Fields`, each rendered through `strconv.Quote`, capped at **16 paths** and **128 bytes per path**, with a truncation marker element carrying the omitted count when either cap trips. Re-point `Error()` to render from this method rather than joining `Fields` directly.

A key path is untrusted text read out of a document that is by definition already malformed, and it lands in an operator-facing message, an MCP JSON payload, and a CLI line. Unbounded interpolation is a disclosure and log-injection surface.

**Single-projection rule — this is the point of the task.** `BoundedFieldPaths()` is the **only** sanctioned source of offender text:

* 147.013-T / U7 populates `unknown_fields` from it
* 147.015-T / U8 renders the CLI key list from it
* 147.012-T / U6b populates `CheckpointReadResult.NonConformingFields` from it

None of the three may re-derive a list from the raw `Fields` slice. Copying the slice would make the bound a property of one renderer instead of a property of the error, and would reintroduce exactly the cross-surface drift R8 exists to prevent.

Two-step red: land the declaration stub (`return nil`) so the package compiles, then the harness, then implement.

Red verification: `go test -count=1 -run '^TestU1b_' ./internal/errors`. Harness test functions carry the mandatory `TestU1b_` prefix so the selector cannot match sibling units.

<!-- BEGIN:acceptance-criteria -->
- `BoundedFieldPaths()` returns every path quoted via `strconv.Quote`, sorted and de-duplicated, for an under-cap field list, and emits no truncation marker
- A field list of 21 paths yields exactly 16 entries plus a truncation marker naming the 5 omitted paths
- A path longer than 128 bytes is truncated with a marker, and `Error()` emits no raw unquoted key text for it
- `Error()` renders from `BoundedFieldPaths()` rather than joining `Fields` directly, so a single change of bound moves every surface at once
- Expected red: all three cases fail on assertions after the declaration step — `BoundedFieldPaths` returns `nil`, so the quoted-and-capped, marker, and per-path-truncation assertions each fail rather than producing a build error
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
`Fields` stays exactly what 147.001-T / U1 declares: sorted, de-duplicated key **paths**, never key values. This task adds a renderer over it; it does not change what is collected.

The cap constants belong beside the method in `internal/errors/checkpoint_errors.go`, not in the MCP or CLI packages. A consumer that wants a different bound is a signal to change the contract here, not to render its own list.

Choose a truncation marker that cannot be mistaken for a real key path — a quoted path is always surrounded by double quotes, so an unquoted marker such as `+5 more` is unambiguous.

`CheckpointUnknownFieldError` (`internal/errors/checkpoint_errors.go:81-108`) is the **create**-boundary sibling and is deliberately **not** modified here. Its bounding is a separate question tied to stash `E429A031`; widening this task to cover it would breach width isolation and reach into 146-F's shipped surface.
