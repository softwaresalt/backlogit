Plan unit **U2g**. Context-member duplicate detection read boundary — ordered duplicate detection for immediate `context` members BEFORE `map[string]json.RawMessage` collapse.

Files: `internal/events/checkpoint_schema.go`, `internal/events/checkpoint_schema_test.go`.

`CheckpointContext.UnmarshalJSON` decodes the `context` JSON object into `map[string]json.RawMessage`. Go's `json.Decoder` last-wins on exact-duplicate keys, and fold-equivalent keys (e.g. `shipment_id` / `Shipment_Id`) occupy distinct map entries but collide when the existing `strings.EqualFold` guard routes one to the modeled field and discards the other from `Extra`. Neither case is detected — the data is silently lost.

Add a token-level or raw-byte pre-scan of the `context` JSON object that detects:
1. **Exact duplicate** context member names — two entries with identical raw key spelling within the same `context` JSON object.
2. **Case-fold-equivalent** context member names — two entries whose `strings.EqualFold` comparison is true but whose raw spellings differ.

Return `ErrCheckpointNonConforming` with `duplicate:<key>` entries in the unknown-fields list (consistent with U2c/U2e duplicate reporting). Preserve all unique extension keys — the open context namespace (U2b) is not violated by this rule; only duplicate members are refused.

The pre-scan MUST run before the map decode so that no information is destroyed by map insertion before the duplicate is reported. This enforces the cycle-12 universal no-implicit-survivor invariant for `context` members specifically.

Wire the rule into the conformance helper so all mutating operations (resolve, abandon) are protected before decode/rewrite.

<!-- BEGIN:acceptance-criteria -->
- Exact duplicate context member name (e.g. two `"mykey"` entries in `context`) returns `ErrCheckpointNonConforming` with `duplicate:mykey` in the unknown-fields list
- Case-fold-equivalent context member names (e.g. `"shipment_id"` and `"Shipment_Id"` both present as unmodeled extensions, or two unmodeled keys like `"foo"` and `"Foo"`) returns `ErrCheckpointNonConforming` with `duplicate:<key>` reporting
- Unique extension keys with no duplicates are preserved and round-trip through `Extra` intact — the open context namespace (U2b) is not narrowed
- Expected red: all three fail
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
The pre-scan must use `json.NewDecoder` token-level iteration or equivalent raw-byte scanning to enumerate context member names before the `map[string]json.RawMessage` decode collapses duplicates. Do not attempt to detect duplicates after map insertion — the information is already lost at that point.

Consistent with U2c (top-level duplicates) and U2e (progress duplicates), report each duplicate pair as `duplicate:<key>` in the unknown-fields carrier so the repair matrix in U9b can classify and route it.
<!-- END:implementation-notes -->
