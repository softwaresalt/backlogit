Plan unit **U2g** (partition 1). Context-member duplicate detection at the read boundary.

Files: `internal/events/checkpoint_conformance.go`, `internal/events/checkpoint_conformance_test.go`.

Extend the read-boundary conformance helper to walk the **original raw bytes** of the top-level `context` member as an ordered token stream and report context-member collisions the shipped decode cannot round-trip. `ParseCheckpoint` and `CheckpointContext.UnmarshalJSON` stay **lenient and unchanged**.

Offenders are returned inside the existing `*CheckpointNonConformingError` / `ErrCheckpointNonConforming` pair from 147.001-T / U1, reported as `duplicate:context.<key>`. **No new sentinel is introduced.**

Refusal rule:

1. **Exact duplicate decoded member names are refused universally.** Comparison is on the decoded JSON member name, so `{"foo":1,"\u0066oo":2}` is an exact duplicate and is caught.
2. **Fold variants are refused only when they alias a modeled context field** - `shipment_id`, `feature_id`, `task_ids`, `branch` under `isModeledContextKey`.
3. **Distinct unmodeled names stay conforming.** `foo` and `Foo`, and NFC/NFD-distinct extensions, occupy distinct `Extra` keys and round-trip losslessly. Broad `EqualFold`-everything or Unicode-normalizing comparison is forbidden - it would narrow the open `context` namespace 147.003-T / U2b exists to protect.
4. **Unicode semantics are Go `strings.EqualFold`, no normalization.**
5. **Cycle-17 scope note:** this task walks the member spelled literally `context`. The wider routing question - that `encoding/json` sends every key satisfying `strings.EqualFold(name, "context")` to the modeled field, so a lone `Context` is also subject to the same loss - is owned by **147.033-T / U2h**. Folding it in would make a fourth scenario.

**Cycle-20 red timing (supersedes the cycle-17 narrowed selector):** the red gate is `go test -count=1 -run '^TestU2g_' ./internal/events`, and it selects exactly the two failing functions `TestU2g_DuplicateExactContextMember` and `TestU2g_DuplicateFoldVariantAliasingModeledField` - because the open-namespace preservation guard is **not committed in the harness step at all**. Cycle 17 kept the guard inside the harness commit and excluded it with the narrower `^TestU2g_Duplicate` selector; the cycle-20 Copilot review raised that as a P1, since P-002/P-004 gate the harness commit rather than the selector. The guard lands with the implementation as `TestU2gGuard_OpenNamespacePreserved`.
