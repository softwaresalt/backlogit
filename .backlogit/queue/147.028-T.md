Plan unit **U2g**. Context-member duplicate detection at the **read-boundary conformance helper** — ordered detection over the original raw `context` bytes, before any rewrite.

Files: `internal/events/checkpoint_conformance.go`, `internal/events/checkpoint_conformance_test.go`.

**Contract (cycle-15 resolution — one contract, not two).** `ParseCheckpoint` and `CheckpointContext.UnmarshalJSON` stay **lenient and unchanged**. The verdict lives in `CheckConformingTopLevelNamespace`, the caller-invoked helper that already receives the original bytes before any rewrite and already returns `*backlogiterrors.CheckpointNonConformingError` / `ErrCheckpointNonConforming`. Report offenders as `duplicate:context.<key>`, matching 147.004-T / U2c's `duplicate:<key>` and 147.020-T / U2e's `duplicate:progress.<key>` one level down. **No new sentinel.** The withdrawn alternative — a parse-time `ErrCheckpointContextDuplicateKey` — was rejected because `ParseCheckpoint` wraps with `fmt.Errorf("%w: %v", ErrCheckpointCorrupt, err)`, so `%v` drops the sentinel and `errors.Is` cannot recover it, and because a parse-time refusal fires on non-mutating reads, making `list`, `get`, `resolve`, `abandon`, and `quarantine` disagree about the same file.

Walk the `context` member's raw value as a JSON token stream using the `decodeTopLevelEntries` technique (`internal/events/checkpoint_strict.go:75-90`), which preserves exact-duplicate members in source order. Do not use a `map[string]json.RawMessage` decode — it collapses duplicates before any caller code runs, which is the loss class this unit closes.

**Refusal rule (decided; do not widen or narrow it during implementation):**

1. **Exact duplicate decoded member names are refused universally.** Compare the *decoded* member name, so `{"foo":1,"\u0066oo":2}` is an exact duplicate and is caught. A raw-byte key comparison would miss escape-equivalent spellings.
2. **Fold variants are refused only when they alias a modeled context field.** A pair that is `strings.EqualFold`-equal but not byte-equal is refused **iff** either member matches `shipment_id`, `feature_id`, `task_ids`, or `branch` under `isModeledContextKey`. That is the real loss path: the `plainContext` shadow decode picks one winner for the modeled field and `isModeledContextKey` filters **both** members out of `Extra` (`internal/events/checkpoint_schema.go:196-223`), so the loser's bytes are destroyed on re-marshal.
3. **Distinct unmodeled names stay conforming.** `foo` and `Foo`, and NFC/NFD-distinct extension keys, occupy distinct `Extra` map keys and round-trip losslessly. They MUST NOT be refused. Broad `EqualFold`-everything or Unicode-normalizing comparison is **forbidden** — it would narrow the open `context` namespace that 147.003-T / U2b exists to protect, the highest-risk regression in this plan.
4. **Unicode semantics are Go `strings.EqualFold`, no normalization.** Same matcher as the shipped `isFoldKeyIn`, same equivalence relation `encoding/json` applies to field matching. No `strings.ToLower`, no NFC/NFD folding.

**Modeled-collision disposition.** A refused fold-collision against a modeled context field is not auto-repairable: `legacy_top_level` cannot relocate a pair whose members both collapse into the same modeled slot. It carries the operator-choice-or-quarantine semantics 147.018-T / U9b already states for modeled duplicates, extended to the `context` object.

Because the rule lives in the shared helper, every mutating verb (`resolve` via 147.007-T / U3b, `abandon` via 147.008-T / U4, `quarantine` via 147.009-T / U5) and every read surface (147.011-T / U6, 147.012-T / U6b) inherits it from the predicate it already calls.

<!-- BEGIN:acceptance-criteria -->
- **Scenario 1 (RED)** — an exact-duplicate `context` member, including an escape-equivalent spelling such as `{"foo":1,"\u0066oo":2}`, returns `ErrCheckpointNonConforming` with `duplicate:context.foo` in the reported field list
- **Scenario 2 (RED)** — a fold variant aliasing a modeled context field (`shipment_id` plus `Shipment_Id`) returns `ErrCheckpointNonConforming` with `duplicate:context.shipment_id`
- **Scenario 3 (GREEN — the open-namespace preservation guard)** — one table asserts that distinct unmodeled fold variants (`foo` plus `Foo`), NFC/NFD-distinct extension keys, and a `context` object of unique extension keys **all** stay conforming and that every key survives the `Extra` round-trip. PR #377 cycle 16 combined these assertions here: cycle 15 split them across the tail of scenario 2 and the whole of scenario 3, which read as four effective flows. They are one predicate — "the open namespace is not narrowed" — and belong in one already-green regression scenario
- `ParseCheckpoint` and `CheckpointContext.UnmarshalJSON` are not modified by this task; no new sentinel is added
- Expected red: scenarios 1 and 2 fail (no context-member walk exists). Scenario 3 is a **declared regression guard** — every row of it is shipped 146-F behaviour and is green from the moment it lands. P-004 is satisfied by scenarios 1 and 2

<!-- BEGIN:implementation-notes -->
Reuse `decodeTopLevelEntries` (`internal/events/checkpoint_strict.go:75-90`) rather than writing a second token walker: it already returns every member in source order including exact-case duplicates, and it already fails cleanly on a non-object value. Locate the top-level `context` member from the entries this helper already decodes for the top-level rule, then walk that member's raw value with the same function.

A `context` value that is not a JSON object (null, scalar, array) is **not** a conformance failure — `ParseCheckpoint` governs that — and must not panic, matching the non-object `progress` rule in 147.003-T / U2b.

Reuse `isFoldKeyIn` / `isModeledContextKey` for the modeled-alias test. Do not introduce a normalized-map lookup: the doc comment on `isFoldKeyIn` records why normalization reintroduces the exact non-equivalence bug this package already closed.

Field entries are sorted and de-duplicated by 147.001-T / U1, and quoted and bounded by 147.030-T / U1b, so this task emits raw key paths and does not format them.

Red verification: `go test -count=1 -run '^TestU2g_' ./internal/events`.
