Plan unit U2. Give the Extra carrier U0a declared its behavior. Add custom UnmarshalJSON (pointer receiver) and MarshalJSON (VALUE receiver, because Context is a value field and a pointer receiver would be silently skipped for non-addressable values) re-emitting modeled keys followed by sorted Extra keys flattened into the same context object. DECODE MECHANISM IS PINNED (PR #372 remediation): UnmarshalJSON performs exactly two decodes of the SAME original bytes - (1) json.Unmarshal(b, (*plainContext)(c)) against the method-less shadow, which is the ONLY thing that may set a modeled field and which inherits encoding/json's deterministic source-order, case-insensitive, last-wins semantics; (2) a separate map[string]json.RawMessage decode of b used ONLY to populate Extra, keeping just the keys that do NOT case-insensitively match a modeled tag. Routing modeled keys OUT of that raw map is FORBIDDEN: a context carrying both shipment_id and Shipment_ID lands as two distinct map entries, and selecting a winner by map iteration would make the same bytes parse to A on one run and B on the next - a nondeterministic R4/R14 violation. Extra is order-immune because it is an accumulate-all set difference, never a single-winner selection. Replace U0a Keys() stub with Keys() ([]string, error). Both MarshalJSON and Keys() delegate to one unexported emit() (keys, body, err) so neither swallows an error. emit() MUST marshal the plainContext shadow through jsonutil.MarshalReadable and append each Extra raw message verbatim; json.Marshal MUST NOT appear in emit(), because HTML escaping must stay disabled. Modeled-key set derived by reflection via a package-level var initializer, no init() and no panic, compared case-insensitively.

Gate run 10 remediation: `Extra` **keys** must be produced through the same escape-free encoder as everything else — a `json.Encoder` with `SetEscapeHTML(false)`, i.e. the `jsonutil.MarshalReadable` path — and only a key's VALUE is appended verbatim from its stored `json.RawMessage`. Bare `json.Marshal(key)` is NOT acceptable: it is the same banned call the HTML-escape rule already forbids in `emit()`, and for a key containing `&`, `<`, or `>` it would emit `\u0026` into the key bytes, breaking the escape-free guarantee even though the value round-trips. Splicing a key into a `bytes.Buffer` as raw text is worse: a key containing `"`, `\`, or a newline could terminate the key string early and inject a sibling member that overwrites a modeled field on the next read. U1b (146.005-T) scenario 5 is the guard.
