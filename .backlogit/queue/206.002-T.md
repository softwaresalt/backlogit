* `--auto` emits only root covering feature(s) (`isRootCoveringFeature`, i.e. undotted top-level `feature` / `chore` items) in the leading prefix and includes **every remaining manifest member not already emitted in that root-feature prefix** — including nested/sub-epic dotted features (`100.001-F`), tasks (`task`), and subtasks (`subtask`) — as vertices in the Kahn topological sort graph over intra-manifest `blocks` dependencies: every intra-manifest `blocks` edge `A depends_on B` between two vertices in the non-root graph adds `B -> A`, any non-root member `C` whose `parent_id` `P` is also in the non-root graph (e.g. a task under a nested feature `100.001-F`, or a subtask under a task `P`) adds a default ordering edge `P -> C` unless `P` transitively depends on `C` via `blocks` edges, and priority-queue tie-breaking prefers ready children of the most-recently emitted parent when no `blocks` prerequisite is violated (verified by scrambled hierarchy test, nested-feature regression `[100-F, T, 100.001-F]` where `T` has `parent_id: 100.001-F` -> produces `[100-F, 100.001-F, T]`, AND flat manifest `[T, S]` where task `T` depends on subtask `S` with absent parent -> produces `[S, T]`).

Implement `ReorderShipmentResult` and `ReorderShipment` in `internal/core/shipment_manifest.go` with unit tests in `internal/core/shipment_manifest_test.go`.

* Validate mutually exclusive mode selection (`(len(opts.Items) > 0) != opts.Auto`, returning `blerrors.ErrValidation` if neither or both are supplied).
* For explicit `--items` (`mode: "explicit"`): verify exact set bijection with `NormalizeShipmentItems(shipment)` (no missing, extra, or duplicate IDs), verify root covering feature (`isRootCoveringFeature`) appears first before all non-root members, and verify every non-root member `C` whose parent `P` (`C.ParentID`) is in the non-root manifest appears after `P` unless `P` transitively depends on `C` via intra-manifest `blocks` edges.
* For `--auto` (`mode: "auto"`): emit only root covering feature(s) (`isRootCoveringFeature`) in the leading prefix, and include **every remaining manifest member not already emitted in the root-feature prefix** — including nested/sub-epic dotted features (`100.001-F`), tasks (`task`), and subtasks (`subtask`) — as vertices in the Kahn topological sort graph over intra-manifest `blocks` dependencies (`B -> A` for every `A depends_on B`, plus default `P -> C` for any non-root member `C` whose `parent_id` `P` is in the non-root graph unless `P` transitively depends on `C` via `blocks` edges, failing closed with `blerrors.ErrValidation` on cycles), with priority-queue tie-breaking that prefers ready children of the most-recently emitted parent when no `blocks` prerequisite is violated and otherwise preserves original manifest index order.
* Enforce `queued`-only default and unconditional refusal of `blocked` shipments (`ErrShipmentBlockedManifestSealed` / `ErrInvalidStatus` / `blerrors.ErrShipmentConflict`) even when `Force: true` in both live and `DryRun` modes, support read-only zero-write `--dry-run` preview (`ensureNoPendingShipmentRecoveryReadOnly` + `readArtifactFromDiskReadOnly`), and emit/index `shipment_reordered` events when `!opts.DryRun`.
