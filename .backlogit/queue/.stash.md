- [ ] [3C7BCC11] [priority:medium] task: For the backlogit tool, we want the agent to review the way we store work items in the queue. Should we prefix each item, for example, with a T or F  or ST, etc., or should we structure the items only at the beginning of the file names with their number level, such as 001.001.001, and then a dash and then the artifact type, such as review or feature or task or subtask? There are potentially advantages to only having the first part of the name be in a strict syntactical order so that all work items are easily sorted at the file system level. They all show and group together naturally in a view. Some additional considerations: I'm beginning to think it actually makes the most sense to just have the ID of the work item also be the file name of the work item. The related event.jsonl file for that work item also shares the same root file name, just having a separate extension of.jsonl rather than.empty, and then using the enum prefix for each work item type as a suffix at the end of the file name as well as at the end of the ID so that they match.Here's an example. If the work item is a feature and it is a top-level item, it would be 001-FA. A task might be of the same feature, might be 001.001-T. The second task after that same feature might be 001.002-T. A subtask could be 001.001.001-S. A bug on a specific feature could be as simple as 001.001.001-B. Reviews are probably a little different, because they would most likely be at the same level as the feature. For example, that could be 001.001-R. The review might be itself at level two but parented to a feature by design, so that would be 001.001.001-R. The hierarchy is where you determine the lineage of parents and children. If you want to have a review at the task level, or if a review is of a task, it would have to be leveled at a third level, so it would be 001.001.001-R, so that review lineage is two parent tasks as opposed to the parent feature. Actually, that isn't, by convention, really any different from the other work item types, I guess.
