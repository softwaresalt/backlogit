# Class-level GateBroker-nil default for shared ShipShipment test fixtures (155-S full-suite unblock)

## Problem Frame

<!-- BEGIN:problem-frame -->
The full-suite timeout root cause is that 11 of 34 internal/core ShipShipment tests inherit the real default GateBroker (ExecVersionRunner/ExecRunner) via setupShipmentWorkspace or external setupTestWorkspace, spawning a real gate version subprocess. Completed 174.066-T isolated ONLY the shipped-event durability family; ordinary shipment/gate/archive fixtures still rely on every caller remembering to inject a fake. This is shared-fixture-infrastructure work spanning multiple families, out-of-scope for any single done task (P-021 C1 OUT OF SCOPE re 174.066-T).
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
- Option A (per-test patches): inject a fake broker in each of the 11 offending tests. Rejected: fragile, per-test, re-opens the same class of bug whenever a new ShipShipment test is added.
- Option B (class-level default, CHOSEN): add a test-only disableExecGateForTest(t,ws) that sets and asserts ws.GateBroker=nil, called by default in setupShipmentWorkspace and newGateTestWorkspace; intentional gate tests explicitly inject fakes afterward; add a local external-package archive-workspace wrapper for 025_archive_harness_test.go that clears/asserts the broker (do NOT modify broad core_test.setupTestWorkspace). Preserve durability fail-open fake fixture/assertions. Add an inventory regression proving no ordinary ShipShipment fixture retains exec types.
- Option C (production default change): change the production default broker to nil under test build tags. Rejected: touches production/config/default/API — forbidden.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B — one class-level, test-only correction. Single shared disableExecGateForTest(t,ws) default in the two shared shipment/gate fixture constructors + a local external archive wrapper; intentional gate tests keep explicit fake injection; durability fixture untouched (already explicit fail-open); inventory regression enforces the invariant going forward. No production/config/default/API change. One queued/high task under 174-F, governed member of active 155-S.
<!-- END:chosen-direction -->
