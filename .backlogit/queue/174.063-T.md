Behavior RED harness pinning the **post-ship-hook cascade-isolation contract** for the flat-manifest
non-member boundary (spec §0.5 point 8 / SBLK-R28; plan §0.4 rev6, concurrency fix-cycle-3). It closes
the SECOND concurrency defect that the naive form of `174.062-T` would introduce: the shipment
member-completion cascade must be bounded to explicit members ONLY around the governed in-closure
member mutations, and that boundary must NOT leak onto the ship's escaping function-scope `ctx`. The
`ctx` reassigned by `lockArtifactMutations` (`internal/core/shipment_lifecycle.go:615`) escapes the
governed closure and is the same context later handed to `collectArchiveCandidateIDs` (`:664`),
`VerifyPostShipConsistency` (`:689`), and the top-level post-ship `FirePost` hook (`:704`). If
`174.062-T` set the membership boundary on that escaping `ctx` (rather than on a separate in-closure
`scopedCtx`), an UNRELATED artifact update performed inside a post-ship hook callback would inherit the
shipment boundary and its legitimate GLOBAL parent-status cascade would be silently SUPPRESSED — a P1
regression. This harness asserts BEHAVIOR only and introduces no production change.

Determinism uses the real `ws.HookRunner` post-ship hook seam plus the generic parent-status cascade
(`cascadePersistedParentStatuses`), both present in production today, so the harness compiles against
current code and its RED-now anchor fails now. No new production symbol is required.

Scenario (<4, exactly 1 — compound assertion):
1. **Post-ship hook's unrelated update keeps the global cascade; non-member ancestor untouched during
   ship.** Fixture: a shipment whose manifest lists child task `T` whose parent feature `F` is NOT in
   the manifest and whose recorded children all become terminal on ship (the `ComputeParentStatus`
   rollup condition), plus a separate unrelated subtree `P → C` where `P` is NOT a shipment member and
   `C`'s siblings are already terminal. Install a `ws.HookRunner` whose `FirePost(HookShipShipment)`
   callback performs the unrelated mutation — set `C` to a terminal status via the normal
   `setArtifactStatus` path using the `ctx` the hook receives — which SHOULD roll `P` up through the
   generic global cascade. After a successful ship, assert BOTH:
   * **(a) RED-now anchor** — the non-member ancestor `F` received NO shipment-originated status write
     (no `"child status rollup"`, no revert event) and its status equals its pre-ship value. RED today
     because the current cascade rolls `F` to `done` then the preserved restore reverts it; GREEN after
     `174.062-T` bounds the cascade to members and deletes the snapshot/restore. This anchor makes the
     `^TestUPostShipHookCascadeGlobal_` selector RED against current committed code.
   * **(b) discriminator** — after the post-ship hook fires, `P` DID receive the normal GLOBAL
     parent-status rollup (`P.Status` rolled up per `ComputeParentStatus`). This asserts the shipment
     member boundary did NOT leak into the post-ship hook context. GREEN against current code (no
     boundary exists) and GREEN after the CORRECT separate-`scopedCtx` `174.062-T`; RED against the
     NAIVE `174.062-T` that sets the boundary on the escaping function-scope `ctx` (which would stop
     the `C → P` up-walk at the non-member `P`). Anchoring the discriminator on a post-ship-hook
     mutation of a genuinely unrelated non-member subtree is what distinguishes the correct fix from
     the naive one.

AC: (1) the harness FAILS against the current committed code (via anchor (a)) and PASSES after the
CORRECT `174.062-T`; (2) asserts an unrelated artifact update performed inside a post-ship `FirePost`
hook still triggers the normal GLOBAL parent-status cascade (the member boundary does not leak onto the
escaping outer `ctx` reaching `collectArchiveCandidateIDs`/`VerifyPostShipConsistency`/`FirePost`);
(3) asserts (RED-now anchor) a hierarchy-derived non-member ancestor receives no shipment-originated
status write on the success path; (4) FAILS against a naive `174.062-T` that binds the boundary to the
escaping function-scope `ctx` instead of a separate in-closure `scopedCtx`; (5) uses only production
seams that exist today (the `ws.HookRunner` post-ship hook + the generic `cascadePersistedParentStatuses`
cascade), introduces no production change, and does not restore any archived/superseded artifact.
Terminology (authoritative): the ship's transactional lock/snapshot/rollback set is
`{shipment control record ID} ∪ explicit manifest IDs`; the shipment control record is the sole
non-member exemption. Domain: tests. <4 scenarios. Minimal overlap with `174.061-T` scenario 1 is
intentional — assertion (a) is the RED-now anchor for a harness whose discriminating assertion (b) is
green against current code and only goes red against the naive fix.
