title: Spike Work Item Type
updated_at: 2026-04-03T23:44:47.8633978-07:00
---

Add `spike` as a first-class work item type at the same hierarchy level as `feature`. Spikes represent time-boxed research or exploration activities that inform feature decisions.

A spike lives in `.backlogit/queue/` with its own prefix (e.g., `SP`), appears in artifact type listings, and supports a `spike_ref` field that links a spike to the feature, task, or epic it informs. By default, spikes sit at level 1 alongside features and are linkable primarily to features via `spike_ref`.

This requires changes across config schema, header-def, DB schema, naming/routing, MCP tool metadata, and CLI output. The artifact hierarchy in `config.yaml` gains a new `spike` type entry. The `header-def.yaml` gains a `spike` type block with the `spike_ref` custom field. The SQLite schema needs to accommodate the new type and field during rehydration. MCP tools like `backlogit_list_types`, `backlogit_get_wit_metadata`, and `backlogit_create_item` must recognize and handle spikes.
