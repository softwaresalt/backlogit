Make the shipment gate broker's member-evidence staleness check ancestor-aware. The pre-task-completion shipment gate (internal/core/shipment_gate.go validateMemberGateEvidence) currently rejects any member whose recorded gate-evidence head_sha is not strictly EQUAL to the current shipment head, so after a merge commit every member's feature-branch build commit (now an ANCESTOR of the merge) is falsely rejected as stale, blocking post-merge multi-commit shipment closure (blocked 083-S). Fix: accept a member head that is a git ancestor of (or equal to) the shipment head via 'git merge-base --is-ancestor'; reject only genuinely divergent heads; fail closed on any git/timeout/drift error. Security guard: reviewed non-weakening (ancestor-inclusion = the member's gated work is in the shipment; the unchanged shipment-level aggregate diff check covers later modifications; both checks bound to one bracketed head). Source stash 885A7F65. Planning artifacts referenced. Scope: NON-empty head_sha only; empty-member-head (B85DAEE8) and a separately-flagged empty-shipment-head fail-open are OUT of scope.
