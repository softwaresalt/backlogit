    source_stash_text: |-
        Add a `backlogit update` CLI command for self-updating the installed binary.

        Goal: give operators one canonical, exclusive update command so future "installs" that are really just version updates go through a single mechanism, instead of choosing between the curl install script, `go install`, or manual binary download.

        Behavior:
        - `backlogit update` -- detect the current version (internal/version), query the latest GitHub Release (softwaresalt/backlogit), and if a newer version exists, download the platform-matched asset (backlogit-{os}-{arch}[.exe]), verify against the release SHA256SUMS, and atomically replace the currently-installed binary. Report old -> new version.
        - Windows self-replace: a running .exe cannot be overwritten in place; use rename-current-then-move-new (e.g. backlogit.exe -> backlogit.old, write new) and clean up the .old on next run.
        - `backlogit update --check` (dry-run): report whether an update is available without applying it.
        - `--to <tag>`: update to a specific release instead of latest.
        - Update the binary at the location it runs from; fail clearly with manual instructions if that path is not writable.
        - Optional `--source`: build+install from source via `go install .../cmd/backlogit@latest` when Go is available.

        Acceptance criteria:
        - `backlogit update` upgrades an older install to the latest release with SHA256 verification and a clear old->new report; friendly no-op when already current.
        - Cross-platform incl. the Windows running-exe replace.
        - `--check` reports availability without applying.
        - Clear, actionable errors when the target path is not writable or the network/release lookup fails.

        Relationship: shares the "latest GitHub Release lookup + SHA256 verify + platform match" infra with the plugin-off-npm migration (stash 60B8564F) and the version-diff enhancement (companion stash).
