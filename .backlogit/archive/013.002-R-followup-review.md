### 📄 tests/integration/ci_compliance_test.go

#### R-001 — P2 · Advisory

**Title:** `fmt.Sprintf("%v", ...)` used for YAML-unmarshaled `any` values  
**Lines:** ~57 (`goVerStr`), ~86 (`goVerStr` in release build job subtest), ~110 (`versionStr`)  
**Action:** `advisory`

`step.With["go-version"]` and `step.With["version"]` fields are typed as `any` from `map[string]any`. Converting them with `fmt.Sprintf("%v", val)` works correctly for string YAML values (as these are in practice), but silently produces unexpected representations for non-string types (e.g., a bare YAML integer `1.24` would give `%!v(float64=1.24)`).

**Suggestion:**

```go
// Prefer explicit type assertion with a fallback
goVerStr, ok := step.With["go-version"].(string)
if !ok {
    goVerStr = fmt.Sprintf("%v", step.With["go-version"])
}
```

**Risk:** Low — YAML values are quoted strings in practice; no current production failure. Defer to a follow-up.

#### R-003 — P3 · Advisory

**Title:** `versionPattern` regex declared locally instead of at package level  
**Lines:** ~199 (inside `TestGolangciLintVersionPinned`)  
**Action:** `advisory`

`shaPattern` is declared at package level for reuse. `versionPattern` is declared inside the test function. For consistency, move `versionPattern` to package level.

**Suggestion:**

```go
var (
    shaPattern     = regexp.MustCompile(`^[a-f0-9]{40}$`)
    versionPattern = regexp.MustCompile(`^v\d+\.\d+\.\d+$`)
)
```

#### R-004 — P3 · Advisory

**Title:** Action identification via `strings.Contains` — marginally imprecise  
**Lines:** ~103 (`actions/checkout`), ~206 (`golangci/golangci-lint-action`)  
**Action:** `advisory`

`strings.Contains(step.Uses, "actions/checkout")` would match a hypothetical `third-party/actions/checkout-extra@...`. Using `strings.HasPrefix` with the `@`-terminated prefix is slightly more precise.

**Suggestion:**

```go
action := step.Uses[:strings.LastIndex(step.Uses, "@")]
if action != "actions/checkout" { continue }
```
