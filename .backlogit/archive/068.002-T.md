New stdlib-only leaf package internal/atomicfile with WriteFileAtomic(path string, data []byte) error: os.CreateTemp -> write via an io.Writer seam with short-write guard (n != len(data) is a hard error) -> Chmod to clamped mode (existing mode with group/world write stripped, perm &^ 0o022, or 0644 for new file) -> Close -> os.Rename, with Windows-only pre-remove-and-retry fallback. Temp removed on any failure. Deliberately Sync-free (rename gives atomic visibility; git is durability/rollback). doc.go documents path-agnostic contract (callers must pre-validate via core.SafeResolve) + Sync-free-by-design. Imports: fmt, io, os, path/filepath, runtime. Posture: test-first. Maps to plan unit U2.

## Acceptance criteria

- `go test ./internal/atomicfile/...` green.
- Overwrite existing file: content byte-identical AND 0600 source mode preserved.
- Create new file: exists at 0644 with exact content.
- Short-write surfaced as an error via the io.Writer seam with a short-writing fake (observed red before the guard is added).
- Over-permissive 0666 source written back clamped to 0644 (not perpetuated).
- doc.go documents the path-agnostic (caller-validates-path) + Sync-free-by-design contract.
