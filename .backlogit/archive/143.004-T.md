# Classify the shipped-append failure and halt archival on indeterminate

## Description

<!-- BEGIN:description -->
Unit 4. In `internal/core/shipment_lifecycle.go`. (1) Classify ONLY the `shipmentEventAppendError` boundary value declared in 143.003-T; every other closure error keeps the existing unconditional rollback. (2) Classification precedence is indeterminate-first: `blerrors.IsWriteIndeterminate`, then `blerrors.IsWriteNotApplied`, then everything else as indeterminate. Indeterminate dominates, matching `internal/core/mutation_envelope.go:28-38`, so an error carrying both sentinels can never be compensated; only a PROVEN not-applied outcome compensates. The append site cannot prove pre-write status because `EventWriter.AppendEvent` exposes only `error` and `appendFast` discards the `fmt.Fprintf` byte count (`internal/events/stream.go:243`, `:290-291`); compensating over a possibly-applied append to an append-only log is what the `AppendEvent` contract forbids, while leaving a detectable documented residue is not. Record BOTH divergences from `MutationEnvelope` in the doc comment: untagged is unproven here, and this branch HALTS rather than continuing the remaining steps. (3) Evaluate the classification branch BEFORE the existing `closureErr == nil || len(shipSnapshots) == 0` guard at `:391-393`; `restoreShipArtifacts` stays behind it, and `restoreRolledUpNonMemberFeatures` is called only from inside the indeterminate branch, leaving the success-path call at `:536` and the outer fallback untouched so the 133.004-T ordering guarantee survives. (4) On the indeterminate branch: suppress `restoreShipArtifacts`, synchronously restore rolled-up non-member covering features while artifact locks are held, halt archival, and return `MutationPartialError` with `Class: indeterminate`, `FailedStep: blerrors.StepShippedEventAppend`, `CompensationState: not-compensated`, and `Cause: errors.Join(appendErr, restoreErr)`; the join goes INSIDE `Cause`, because `internal/mcp/errors.go:116-118` extracts the partial error and renders only that value, so a joined outer error would drop the restore failure from every MCP response. Populate `Completed` with the steps that landed. (5) On the proven not-applied branch: compensate through the existing snapshot rollback and return `MutationPartialError` with `Class: not-applied`, `FailedStep: blerrors.StepShippedEventAppend`, `CompensationState: compensated`, and `Cause: appendErr`, rather than a bare wrapped error that would reach MCP as an unclassified internal error with no measurement surface for SLI 4. (6) Emit `slog` on both branches with a fixed shape including `class`, `failed_step`, `compensation_state`, `unrestored_ids`, and `cause`, asserted by a log-capture test rather than by inspection. (7) Doc-comment the invariants: the guarantee covers the governed `ShipShipment` path and, within it, only the shipment's own terminal transition; item-level events stay best-effort and non-`ShipShipment` producers are not prevented at all. Execution posture: implementation, gated behind the 143.001-T red state.
