# Scope MCP recovery guidance to the producing step

## Description

<!-- BEGIN:description -->
Unit 10. `mutationPartialRecovery` (`internal/mcp/errors.go:165-176`) is keyed on `Class` ONLY and is reached from `domainError` (`:116-119`), `handleTrackCommit` (`internal/mcp/tools.go:1595`, dispatch `:1613-1616`), and `checkpointDispositionError` (`internal/mcp/errors.go:229`, dispatch `:230-233`). Repointing the indeterminate case would mis-advise all three. Instead pass `err.FailedStep` AND `err.CompensationState`, both already in scope at `internal/mcp/errors.go:153`, `:154`, `:156`, and branch on `blerrors.StepShippedEventAppend`, leaving the class-only default text untouched. The guidance must differ by compensation state because the operator's next action does: compensated means retry, partially-compensated means reconcile the named un-restored IDs first and warns that the doctor audit may report clean while they remain torn, and not-compensated routes to the named-limitation procedure. The shipped-event guidance must be DUAL-SURFACE, naming both `check_shipped_event_completeness` (MCP) and `--check-shipped-event-completeness` (CLI), and must carry the reconcile-before-archiving instruction. Also correct the structured `Retryable` field: `internal/mcp/errors.go:155` sets `Retryable` to `Class == not-applied`, so the new not-applied plus partially-compensated result would advertise itself as safe to retry while release-scope items remain un-restored; gate `Retryable` as `Class == "not-applied" && CompensationState == "compensated"`. This task depends on 143.012-T rather than 143.004-T because the partially-compensated result it must describe is 143.012-T's contract, and both land in the same pull request so no released state advertises the wrong retryability. Keep the single dispatch site in `handleShipShipment`: `gateErrorResult` runs first but cannot match `MutationPartialError` (`internal/mcp/gate_errors.go:22-38`), so add a regression guard rather than restructuring the dispatch. Execution posture: test-first.
<!-- END:description -->

## Acceptance Criteria

<!-- BEGIN:acceptance-criteria -->
- Guidance branches on `FailedStep` and `CompensationState`, not on `Class` alone, and the class-only default text is unchanged.
- The shipped-event guidance names both the MCP parameter and the CLI flag and carries the reconcile-before-archiving instruction.
- Guidance differs by compensation state: `compensated` says the ship can be retried, `partially-compensated` names the un-restored IDs in the structured result and warns that the doctor audit may report clean while those items remain torn, and `not-compensated` routes to the named-limitation procedure.
- `Retryable` is `Class == "not-applied" && CompensationState == "compensated"`, so a partially-compensated result is never reported as retryable.
- `internal/mcp/error_mapping_test.go:200` (`track_commit` guidance contains `check_partial_mutations`) still passes.
- A regression guard asserts the indeterminate result is not consumed by `gateErrorResult`.
- All three scenarios were written and observed failing before the guidance change; the red output is recorded in this task.
