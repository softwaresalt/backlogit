Implement `ReorderShipmentResult` and `ReorderShipment` in `internal/core/shipment_manifest.go` with unit tests in `internal/core/shipment_manifest_test.go`.

* Validate mutually exclusive mode selection (`(len(opts.Items) > 0) != opts.Auto`, returning `blerrors.ErrValidation` if neither or both are supplied).
* Build the two-phase non-root dependency graph `G` shared by both `mode: "auto"` and `mode: "explicit"`: partition root covering feature(s) (`isRootCoveringFeature`, i.e. undotted top-level `feature` / `chore` items) from the remaining non-root manifest members (nested/sub-epic dotted features `100.001-F`, tasks `task`, and subtasks `subtask`, which form the vertices of `G`). In Phase 1, add every hard intra-manifest `blocks` prerequisite edge `B -> A` (`A depends_on B`) between two vertices in `G`, rejecting any cycle among hard `blocks` edges with `ErrDependencyCycle` / `blerrors.ErrValidation`. In Phase 2, iterate over candidate default parent-before-child edges `P -> C` (for each non-root vertex `C` whose `parent_id` `P` is also a vertex in `G`) in deterministic original manifest order (`itemsBefore` index order) and admit `P -> C` into `G` **if and only if** `P` is not reachable from `C` in the current graph `G` (containing all hard `blocks` edges from Phase 1 plus all previously admitted `P -> C` parent edges from earlier iterations of Phase 2).
* For explicit `--items` (`mode: "explicit"`): verify exact set bijection with `NormalizeShipmentItems(shipment)` (no missing, extra, or duplicate IDs), verify root covering feature (`isRootCoveringFeature`) appears first before all non-root members, and verify that for every directed edge `U -> V` in the two-phase graph `G` (every hard intra-manifest `blocks` edge `B -> A` and every admitted default parent-before-child edge `P -> C`), `pos(U) < pos(V)` in `opts.Items`; otherwise return `blerrors.ErrValidation`.
* For `--auto` (`mode: "auto"`): emit only root covering feature(s) (`isRootCoveringFeature`) in the leading prefix, and run Kahn's topological sort over the two-phase graph `G` with priority-queue tie-breaking that prefers ready children of the most-recently emitted parent when all incoming edges in `G` are satisfied and otherwise preserves original manifest index order (failing closed with `blerrors.ErrValidation` on cycles).
* Enforce `queued`-only default and unconditional refusal of `blocked` shipments (`ErrShipmentBlockedManifestSealed` / `ErrInvalidStatus` / `blerrors.ErrShipmentConflict`) even when `Force: true` in both live and `DryRun` modes, support read-only zero-write `--dry-run` preview (`ensureNoPendingShipmentRecoveryReadOnly` + `readArtifactFromDiskReadOnly`), and emit/index `shipment_reordered` events when `!opts.DryRun`.
