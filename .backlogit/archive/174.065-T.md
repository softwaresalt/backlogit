Enforce deterministic LF working-tree materialization for the implicated Faultline parity golden fixture(s) so the mandatory local full suite can pass on Windows (core.autocrlf=true) without weakening any byte-stability contract. Corrective prerequisite for 155-S final readiness. P-021 C1 provenance: the fixture byte-stability contract is owned by archived Faultline task 156.006-T under archived feature 156-F; because that feature is terminal, this live corrective is hosted under the ACTIVE covering feature 174-F and made an explicit member of active shipment 155-S. Root cause: repo blobs for internal/faultline/testdata/parity_v1.golden.json are LF, but .gitattributes carries only * text=auto, so Windows checkout materializes CRLF and TestU4aBehaviorCanonicalByteStable byte-compares a.Canonical() LF output to the CRLF working-tree fixture and fails. Fix is a path-specific .gitattributes eol=lf entry only; NO test weakening and NO global line-ending change. Stage planning only: do not implement now.
