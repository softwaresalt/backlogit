# Backlogit Workflow Custody, Pre-Existing Change Adoption, and Stage-to-Ship Handoff Native Domain Extension (1D48B514)

## Problem Frame

<!-- BEGIN:problem-frame -->
GSD blocker 1D48B514 exposed that legitimate Stage-authored deliberation/plan/review docs and operator-edited files collide with worktree cleanliness gates when baseline capture is identity-blind and backlogit lacks a native workflow custody, pre-existing change adoption, and producer-to-recipient handoff receipt contract (R1-R8). We need a governed backlogit extension that binds workflow_id, scope_branch (rejecting default branch for mutable actions), base_commit_sha, exact path/rename/patch SHA-256 digests, Profile A (operator_verified CustodyApprovalToken) vs Profile B (agent_workflow_handoff) authority, and zero-write preview/verify across CLI and MCP.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Pure Configuration / Existing API Composition (No backlogit Go changes) — Rejected because update_item/update cannot write custom_fields, references, or branch, and append_comment provides zero schema validation, CAS, or authority verification.
Option B: Narrow Native Workflow Custody Domain Extension on shipment Artifacts + Append-Only Custody Log + Derived SQLite Projection (Units B1-B4) — Recommended; composes existing canonical hashing, A/C/B locks, shipmentLifecycleJournal, TrustAnchors, NonceLedger, and NewReadOnlyWorkspace.
Option C: Overload ReconstituteShipments (210-S) or ReconcileShipmentToShipped (167-F) — Rejected because it violates domain separation (R7) and conflates manifest/archive repair with pre-commit change-set custody.
Option D: Store Custody State Only in External .gsd/ Files — Rejected because it violates R1 and R8 by creating a parallel workflow database outside .backlogit/.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Adopt Option B (Narrow Native Workflow Custody Domain Extension on shipment artifacts + append-only custody log + optional derived SQLite projection) and resolve OD-1, OD-2, and OD-3 per documented recommendations:
1. OD-1: Persist the structured workflow-custody/v1 envelope under custom_fields.workflow_custody on shipment Markdown files while promoting workflow_id (and preserving branch) as top-level optional string fields on shipment in defaultHeaderDef() with an automatic upgradeLegacyGeneratedHeaderDef bitmask upgrade rule.
2. OD-2: Enforce the RD1 non-negotiable authority floor — Profile A (operator_verified, mandatory for preexisting_adoption, ForeignPaths, and mixed_reconciled edits) requires a cryptographic CustodyApprovalToken verified against TrustAnchors and NonceLedger under locks shipment-lifecycle-global -> A -> C -> B using CLI/host-supervisor signer support and failing closed with APPROVAL_CHANNEL_UNAVAILABLE / ErrAuthorizationRequired when unavailable (never downgrading to --confirm or decision_ref). Profile B (agent_workflow_handoff) permits routine stage_to_ship_handoff and ship_task_custody when producer_role != accepting_role and all paths are workflow-created or prior Profile A adopted.
3. OD-3: Default receipt expires_at_utc = 168h (7 days) with 15m CustodyApprovalToken not_after_utc window; ship all four units (B1 -> B2 -> B4 canonical-direct MVP plus Unit B3 derived SQLite custody_receipts projection and backlogit sync rehydration) in shipment 211-S while keeping CLI/MCP custody operations strictly independent of SQLite.
<!-- END:chosen-direction -->
