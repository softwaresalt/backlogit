appendGateEvidence computes the next monotonic per-item counter, builds the purpose=task envelope, signs it, and writes proof, key_id, proof_schema, and counter as delta fields. Preserve append-before-status-write ordering and the evidence_required refusal. Counter allocation is not safe today: appendItemEventWithActorErr constructs a fresh NewWorkspaceEventWriter per call with no shared lock across read-current-counter/increment/append, so concurrent transitions on the same item can duplicate a counter. Wrap counter allocation plus append in a combined in-process mutex and cross-process sidecar-file lock, mirroring internal/events/hook_events.go's HookEventWriter pattern (sync.Mutex plus an O_CREATE|O_EXCL lock file with stale-lock recovery); the critical section must span read, increment, sign, and append. Add a concurrent regression test: N goroutines appending gate evidence for the same item concurrently produce N distinct, gapless counters with no duplicates. Files: internal/core/gate_evidence.go, internal/core/gate_transition.go.
