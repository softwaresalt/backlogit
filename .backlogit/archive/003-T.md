title: Rehydration not atomic — process crash between DELETE and WalkDir yields empty index
updated_at: 2026-04-08T17:02:28.0885999-07:00
---

Rehydrate() clears items and item_deps with two DELETE statements, then rebuilds via WalkDir + UpsertItem. These operations are not wrapped in a transaction. If the process crashes between the DELETEs and the end of WalkDir, the SQLite index is empty. Any query or MCP tool call during a partial rehydration returns no results.\n\nAffected file: internal/db/rehydration.go (Rehydrate function)\n\nFix: wrap the DELETE FROM items, DELETE FROM item_deps, and the full WalkDir/UpsertItem loop in a single SQLite transaction. Use BEGIN/COMMIT with ROLLBACK on error. This ensures the index is either fully rebuilt or fully rolled back to the pre-rehydration state.\n\nNote: the f015 compound learning documents that Rehydrate return counts are user-visible contract behavior. The transactional fix must preserve the count semantics.\n\nReview reference: 019.001-R (finding F-3)
