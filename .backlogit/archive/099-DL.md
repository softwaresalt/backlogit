# CAP-3 (9CFC88E5): Bound custodyGit subprocess execution with timeout/WaitDelay and deduplicate custodyBlobDigest calls

## Problem Frame

<!-- BEGIN:problem-frame -->
Deferred scope expansion `9CFC88E5` from `213.004-T` (`U11a`, `213-F`, `214-S`): during `214-S` Wave 1 unfiltered convergence, `TestExternal_LiveAcceptAndVerifyUseExternalStore` timed out at `30m0s` waiting in `os/exec.Cmd.Wait` via `custodyGit` / `custodyBlobDigest` (`internal/core/custody_exec.go`) because `custodyGit` lacks a self-derived timeout and `cmd.WaitDelay`, and spawns redundant `git cat-file blob` subprocesses on Windows under load.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Leave `custodyGit` using the caller's unbounded `ctx` (`context.Background()`) without `WaitDelay` or blob-OID digest deduplication. Pros: no code change. Cons: any hung Windows `git` child or inherited stdio pipe blocks `os/exec.Cmd.Wait` until the 30m package timeout while holding `global -> A -> C -> B` custody locks.
Option B (Recommended): Add a self-derived bounded timeout (`custodyGitTimeout`, default 15s) + `cmd.WaitDelay` + `-c core.fsmonitor=false -c gc.auto=0` + `GIT_TERMINAL_PROMPT=0` to `custodyGit` in `internal/core/custody_exec.go`, and deduplicate `custodyBlobDigest` (`git cat-file blob <oid>`) across identical immutable blob OIDs. Pros: guarantees fail-closed bounded execution on every `custodyGit` call and cuts `git cat-file` subprocess spawns in `TestExternal_LiveAcceptAndVerifyUseExternalStore` by 50%+. Cons: none.
Option C: Parse `.git/objects/pack/*.pack` and `.git/index` binary formats directly in Go without `git`. Pros: zero subprocesses. Cons: complex and brittle for packed/delta objects and git worktrees.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Harden `custodyGit`, `custodyBlobDigest`, and `custodyLiveDigests` in `internal/core/custody_exec.go`:
1. Enforce a self-derived per-invocation deadline in `custodyGit` (`const defaultCustodyGitTimeout = 15 * time.Second`, configurable via package-level test seam `custodyGitTimeout`) using `context.WithTimeout(ctx, custodyGitTimeout)`, set `cmd.WaitDelay = 2 * time.Second` so `os/exec.Cmd.Wait` never blocks indefinitely on Windows if a grandchild holds stdio handles open after exit/kill, pass `-c core.fsmonitor=false -c gc.auto=0` (and `GIT_TERMINAL_PROMPT=0` in `cmd.Env`), and check `runCtx.Err()` before returning so timeouts fail closed rather than hanging under the workspace custody locks (`global -> A -> C -> B`).
2. Eliminate redundant `git cat-file blob <oid>` subprocess spawns in `custodyLiveDigests` / `custodyBlobDigest`: when `indexOID == baseOID` (the common `unstaged_only` case) or when the same content-addressed Git blob `oid` is queried multiple times within `custodyBlobDigest` (via a bounded in-memory `oid -> sha256Digest` cache keyed by immutable 40/64-hex Git blob OID), reuse the computed LF-normalized SHA-256 digest without spawning another `git cat-file blob` subprocess.
<!-- END:chosen-direction -->

## Open Questions

None. Bounded `custodyGit` timeout + `WaitDelay` + immutable blob-OID digest memoization directly prevent both indefinite `Cmd.Wait` hangs and Windows `-race` subprocess storms in `TestExternal_LiveAcceptAndVerifyUseExternalStore`.
