internal/core/shipment.go:201-206,287-303 — ReturnBlockedItem persists the shipment and the item as two separate file/DB updates. If the second write fails, the function returns an error after partially mutating the workspace, leaving shipment membership and item status out of sync. Refactor to wrap both writes in an atomic transaction or use compensating writes with rollback. P1 finding from 015-F session-end review.
