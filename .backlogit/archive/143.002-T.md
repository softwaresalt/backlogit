# Add shipment-scoped error-returning appender and boundary type

## Description

<!-- BEGIN:description -->
Unit 2, first production task on the durability track, gated behind the observed-failing 143.001-T harness. Add `appendShipmentEventErr` in a NEW file `internal/core/shipment_events.go`, mirroring the `internal/core/gate_evidence.go` precedent rather than growing `shipment.go`: a shipment-scoped error-returning appender that acquires the item-log lock itself so a lock failure and an append failure arise in two distinguishable statements, and so the message reads `shipment event log`, not `gate evidence`. Tag ONLY the lock failure, with `blerrors.ErrWriteNotApplied` (nothing was written, so compensation is provably safe). PASS THE LOCKED CONTEXT FORWARD: the context returned by `events.LockItemLogCrossProcess`, not the caller's original ctx, must reach `writer.AppendEvent` and the SQLite index call, because `LockItemLog` is a non-reentrant uncancellable `mutex.Lock()` (`internal/events/stream.go:125`) that short-circuits only on the ctx marker (`:118-123`) and `AppendEvent` re-locks when the marker is absent (`:254-269`); dropping it deadlocks the ship goroutine permanently while it holds the membership lock and every artifact lock. Both existing appenders do this correctly (`internal/core/gate_evidence.go:53`, `:58`; `internal/core/shipment.go:688`, `:695`). Wrap the writer error with `%w` and add NO class of your own: durability sentinels must survive unwrapping and untagged errors must stay untagged so 143.004-T can treat them as unproven. Do NOT attempt to detect a short or partial write, and do not modify any file under `internal/events`. Preserve SQLite projection parity: after a successful append, index the event best-effort exactly as `internal/core/shipment.go:688-700` does, warning without reclassifying the durable outcome on index failure. Add the dispatcher `(ws *Workspace).appendShipmentEvent` mirroring `appendGateEvent` (`internal/core/gate_evidence.go:81-86`). Route the `shipment_status_changed` call site (`internal/core/shipment.go:205`) through the dispatcher while PRESERVING best-effort semantics: log the error, do not return it. Declare the failed-step name once as an exported constant in `internal/errors` (`StepShippedEventAppend = "shipped-event-append"`, matching the literal the harness asserts) and amend the `CompensationState` doc comment at `internal/errors/mutation_errors.go:26`, which today enumerates a closed set of compensated, not-compensated, unknown and would otherwise be falsified by the partially-compensated value 143.012-T introduces. Execution posture: implementation with colocated tests.
<!-- END:description -->

## Acceptance Criteria

<!-- BEGIN:acceptance-criteria -->
- `appendShipmentEventErr` owns the item-log lock, passes the LOCKED context to `AppendEvent` and to the index call, tags only the lock failure `ErrWriteNotApplied`, preserves any durability sentinel the writer attached, leaves untagged writer errors untagged, and never mentions gate evidence.
- Colocated tests in `internal/core/shipment_events_test.go` were written first and observed failing (first as a compile failure, then as an assertion failure) and now assert: a lock failure satisfies `IsWriteNotApplied`; with durable writes enabled a tagged indeterminate writer error survives unwrapping while an untagged one stays untagged; and the success-ordering characterization moved here from the harness still holds, with the shipped event present and ordered before the archival records.
- Event indexing parity with `internal/core/shipment.go:688-700` is preserved and an index failure never reclassifies the append outcome.
- `appendShipmentEvent` dispatches through the `shipmentEventAppend` seam when set and to `appendShipmentEventErr` otherwise.
- `blerrors.StepShippedEventAppend` equals the literal `shipped-event-append` asserted by 143.001-T, and the `CompensationState` doc comment admits `partially-compensated`.
- The shipped call site routes through the dispatcher with unchanged best-effort behavior.
- No file under `internal/events` is modified, verified by `git diff --name-only`.
- All three 143.001-T scenarios are still red, because semantics are unchanged. A green 143.001-T scenario here means the routing was flipped a task early: halt. A hang rather than a failure means the locked context was dropped: halt.
- `go test ./internal/core/ -run 'TestShipShipment|TestClaimShipment|TestRestoreShipArtifacts|TestAppendShipmentEvent'` is green with no edits to existing tests.
