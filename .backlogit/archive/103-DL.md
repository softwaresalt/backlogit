# Prompt for target tool directory, install backlogit binary, and configure .mcp.json on init and install (269D054D)

## Problem Frame

<!-- BEGIN:problem-frame -->
Currently, backlogit init and backlogit install (internal/cli/root.go and internal/cli/self_install.go) self-install the runtime executable only into the workspace storage directory (.backlog/backlogit[.exe] or .backlogit/backlogit[.exe]), which pinnedMCPDaemonBinary and toolchain verification (217-F) treat as a reserved storage root rather than a valid target tool directory. Neither init nor install prompts the operator for a target tool install directory (.bin, bin, or a custom workspace-relative directory), creates the target tool directory in the workspace, installs backlogit[.exe] into that target tool directory, or configures .mcp.json to point to the installed binary in that directory.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Hard-code .bin creation and .mcp.json write in init/install without operator prompt or custom directory support. Option B (Recommended): Interactive prompt + --tools-dir flag on init/install with .bin/bin/custom workspace-relative directory support, step-by-step *os.Root handle-pinned directory creation and atomic binary installation prior to atomic .mcp.json configuration (preserving existing non-backlogit mcpServers entries), config.yaml tools_dir persistence, idempotent ignore entries, and CLI reference regeneration via cmd/gen-docs. Option C: Shell out to external PowerShell/POSIX installer scripts from Go CLI init/install.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Adopt Option B and promote directly to implementation planning and backlog harvest.
<!-- END:chosen-direction -->
