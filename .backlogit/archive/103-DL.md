# Prompt for target tool directory, install backlogit binary, and configure .mcp.json on init and install (269D054D)

## Problem Frame

<!-- BEGIN:problem-frame -->
Currently, backlogit init and backlogit install (internal/cli/root.go and internal/cli/self_install.go) self-install the runtime executable only into the workspace storage directory (.backlog/backlogit[.exe] or .backlogit/backlogit[.exe]), which pinnedMCPDaemonBinary and toolchain verification (217-F) treat as a reserved storage root rather than a valid target tool directory. Neither init nor install prompts the operator for a target tool install directory (.bin, bin, or a custom workspace-relative directory) or accepts --tools-dir, creates the target tool directory in the workspace, installs backlogit[.exe] into that target tool directory, or configures .mcp.json to point to the installed binary in that directory.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Hard-code .bin creation and .mcp.json write in init/install without operator prompt or custom directory support. Option B (Recommended): Interactive/piped stdin prompt + --tools-dir flag on init/install with .bin/bin/custom workspace-relative directory support, non-short-circuiting defaultTargetToolsDir(cleanRoot string) (string, error) and full ancestor-chain preflight validation on every path (including --tools-dir overrides and nonexistent first-init roots), step-by-step *os.Root handle-pinned directory creation and non-short-circuiting atomic binary installation prior to atomic .mcp.json configuration (preserving unrelated keys/servers via json.RawMessage, detecting backlogit aliases across mcpServers and servers, and reconciling existing toolchain.yaml via canonical ToolchainManifest load-mutate-validate-write when present), idempotent .gitignore/.git/info/exclude entries for the installed tool binary, and CLI reference regeneration via cmd/gen-docs across 5 atomic 2-file tasks (218.001-T..218.005-T). Option C: Shell out to external PowerShell/POSIX installer scripts from Go CLI init/install.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Implement interactive/piped stdin prompting and --tools-dir flag on backlogit init and backlogit install, run unconditional full-ancestor and non-short-circuiting config/directory preflight via defaultTargetToolsDir(cleanRoot string) (string, error) on every path (including --tools-dir overrides and nonexistent first-init roots), reuse canonical validators (validateDaemonToolsDirRel, validateBacklogitCommandRel, isBacklogitDaemonCommand, scanDaemonJSON, validateDaemonYAMLKeys(node, fileName)), create the target tool directory via step-by-step pinned *os.Root handles and install backlogit[.exe] there prior to configuring .mcp.json (without short-circuiting .mcp.json/ignore provisioning when os.SameFile skips binary copy), atomically merge .mcp.json via json.RawMessage (and reconcile existing toolchain.yaml via canonical toolchain.LoadToolchainManifest + toolchain.WriteToolchainManifest when present, without mutating config.yaml or introducing unrequested env vars), record idempotent ignore entries for the installed tool binary in .gitignore and .git/info/exclude, and regenerate docs/cli-reference/backlogit_init.md via cmd/gen-docs across 5 atomic 2-file tasks (218.001-T..218.005-T).
<!-- END:chosen-direction -->
