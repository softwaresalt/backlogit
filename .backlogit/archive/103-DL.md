# Prompt for target tool directory, install backlogit binary, and configure .mcp.json on init and install (269D054D)

## Problem Frame

<!-- BEGIN:problem-frame -->
Currently, backlogit init and backlogit install (internal/cli/root.go and internal/cli/self_install.go) self-install the runtime executable only into the workspace storage directory (.backlog/backlogit[.exe] or .backlogit/backlogit[.exe]), which pinnedMCPDaemonBinary and toolchain verification (217-F) treat as a reserved storage root rather than a valid target tool directory. Neither init nor install prompts the operator for a target tool install directory (.bin, bin, or a custom workspace-relative directory) or accepts --tools-dir, creates the target tool directory in the workspace, installs backlogit[.exe] into that target tool directory, or configures .mcp.json to point to the installed binary in that directory.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Hard-code .bin creation and .mcp.json write in init/install without operator prompt or custom directory support. Option B (Recommended): Interactive/piped stdin prompt + --tools-dir flag on init/install with .bin/bin/custom workspace-relative directory support, non-short-circuiting defaultTargetToolsDir(cleanRoot string) (string, error) and full ancestor-chain preflight validation on every path (including --tools-dir overrides and nonexistent first-init roots), step-by-step *os.Root handle-pinned directory creation, handle-confined bootstrap defaults/templates/migration writes (writeWorkspaceBootstrapDefaults), and non-short-circuiting atomic binary installation prior to atomic .mcp.json configuration (canonicalizing into mcpServers.backlogit via json.RawMessage and reconciling existing toolchain.yaml via override-aware canonical ToolchainManifest load-mutate-validate-write with canonical ID migration to backlogit and unconditional SHA256 population), idempotent literal-escaped .gitignore/.git/info/exclude entries for the installed tool binary, and CLI reference regeneration via cmd/gen-docs across 6 atomic 2-file tasks (218.001-T..218.006-T). Option C: Shell out to external PowerShell/POSIX installer scripts from Go CLI init/install.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Implement interactive/piped stdin prompting and --tools-dir flag on backlogit init and backlogit install; validate every path component from the trusted filesystem/volume root anchor handle and create any missing workspace-root, storage-root, or target-tool-directory suffix handle-relatively on pinned *os.Root handles (never via path-based os.MkdirAll after an Lstat check); perform handle-confined bootstrap writes (writeWorkspaceBootstrapDefaults on the pinned storageHandle *os.Root, rejecting pre-existing redirected <storage>/templates, <storage>/queue, or <storage>/logs entries and re-verifying ancestor/handle identity so ancestor swaps during the defaults phase fail closed with zero outside writes); treat BACKLOGIT_WORKSPACE_DIR="" as unset in resolveDaemonStorageDirName and loadToolchainManifest (matching resolveInstallStorageDir and TestU6) while honoring non-empty BACKLOGIT_WORKSPACE_DIR=.backlog or .backlogit on dual-root workspaces in both reconciliation and LoadToolchainManifest / AuditRepositoryToolchain; run unconditional non-short-circuiting read-only preflight of all 5 recognized sources (.mcp.json, <storage>/toolchain.yaml with full typed ToolchainManifest KnownFields(true) and manifest publication constraints using the existing 1-arg validateDaemonYAMLKeys(&doc), <storage>/config.yaml with duplicate-key attribution mapped to config.yaml and !!str scalar check, .bin, and bin, plus existing <storage>/templates, queue, logs, and bootstrap files) before any mutation on every path (including --tools-dir overrides); reject line separators/control chars in validateDaemonToolsDirRel and escape gitignore metacharacters when constructing /<tools_dir>/backlogit[.exe] ignore patterns; install backlogit[.exe] into the target tool directory prior to configuring .mcp.json (without letting os.SameFile short-circuit downstream provisioning);
