# Artifact Identity, Hierarchy & Relationships

## Problem Frame

<!-- BEGIN:problem-frame -->
Six high-priority stash entries converge on a single design surface: how backlogit artifacts are named, parented, linked, and reconciled across their lifecycle.\n\n**Current state:**\n- Prefix-based hierarchical IDs (015.009-T.ST001) with dot-separated parent lineage\n- `allowed_children` config restricts parenting: feature→[task, review], task→[subtask], all others→[]\n- Bug type exists at level 3 but has NO valid parent path (neither feature nor task lists bug as allowed child)\n- Relationships limited to `item_deps(blocks, relates_to, parent_of)` table and ad-hoc custom fields\n- No formal cross-reference system (related_to, duplicate_of, informs)\n- Status reconciliation gap: parent status not updated when children complete; children can remain active under a done parent\n- 002-DL already decided orphan identity: status-as-authority with parent_id nulled, ID immutable as provenance\n\n**Stash entries in scope:**\n- 3C7BCC11: Queue naming conventions (user's top priority)\n- 6A545842: Derive parent hierarchy from typed IDs + structured related_id\n- BA3DB37B: Generalize hierarchical parenting for bugs and other types\n- AA10AF37: Richer artifact relationship links (related_to, duplicate_of)\n- 51B11D29: Orphaned work item identity (002-DL decided)\n- CE39AE5D: Completion-scope status reconciliation\n\n**Core tension:** The identity system must remain stable (IDs are immutable keys in logs, events, stash links, and commit references) while becoming more expressive (supporting richer parenting, cross-references, and lifecycle consistency).
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
**Option A: Naming overhaul to numeric hierarchy (3C7BCC11 original proposal)**\nReplace prefix-based IDs (015.009-T) with purely numeric IDs (001.001.001) plus type suffixes (-F, -T, -B). Natural filesystem sorting.\n- Pro: Clean numeric ordering, type visible at a glance\n- Con: Massive migration of all existing IDs across logs, events, stash_links, commit_links, item_deps. Breaks all external references. The current prefix system already provides type visibility (F=feature, T=task).\n- Assessment: The current system was built after this stash entry was written. The problem it identified is already addressed differently.\n\n**Option B: Extend current prefix system incrementally**\nKeep F/T/ST/B/R/DL/S prefix IDs. Fix parenting gaps, add relationship types, implement status reconciliation.\n- Pro: Zero migration, preserves all operational history, incremental delivery\n- Con: Prefix system quirks remain (e.g., bug at level 3 but no parent path)\n- Assessment: Highest value-to-risk ratio. Each sub-feature ships independently.\n\n**Option C: Hybrid — keep IDs, add relationship layer**\nKeep current naming unchanged. Add a dedicated `item_links` table for typed cross-references (related_to, duplicate_of, informs, supersedes). Extend allowed_children for bug parenting. Add status cascade logic.\n- Pro: Clean separation between identity (immutable) and relationships (mutable). New link types don't require schema changes per type.\n- Con: Slightly more DB complexity with a new table\n- Assessment: Option B refined with a proper relationship model. This is the recommended path.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
**Option A (revised): Numeric hierarchy naming overhaul + relationship layer + parenting + reconciliation.**

Operator direction: The existing prefix-based system (015.009-T) is replaced with a numeric hierarchy system per the original 3C7BCC11 proposal. Migration of internal references (logs, events, stash_links, commit_links, item_deps) is expected work — temporary migration scripts are acceptable. No external dependencies exist to constrain the rename.

This decomposes into five implementation streams:

**Stream 1: Naming overhaul (3C7BCC11)**
Replace prefix-based IDs with numeric hierarchy: `001.001.001` with type suffix (e.g., `001-F`, `001.001-T`, `001.001.001-ST`, `001.001.001-B`). File names match artifact IDs. Event JSONL files share the same root filename with `.jsonl` extension. Update `internal/core/naming.go`, `config.yaml` name_format templates, `header-def.yaml` id_format, and all ID generation paths. Create migration scripts to rename existing artifacts, update DB references, and rewrite JSONL log filenames.

**Stream 2: Bug parenting fix (BA3DB37B)**
Bugs default to level 3 (child of task) but level placement is **user-configurable** to level 2 or level 3, mirroring Azure DevOps flexibility. Add `bug` to the appropriate parent's `allowed_children` based on configured level. Update `validateArtifactParent` to enforce dynamically based on config.

**Stream 3: Typed relationship links (AA10AF37, 6A545842)**
Create `item_links` table: `(source_id TEXT, target_id TEXT, link_type TEXT, created_at DATETIME)` with link_type enum: related_to, duplicate_of, informs, supersedes, spike_ref. Expose through MCP tools (backlogit_add_link, backlogit_get_links) and CLI. **Migrate** existing ad-hoc custom_fields (spike_ref, source_stash_id) to the formal item_links system — item_links are durable domain metadata the application can be coded around, whereas custom_fields are an untyped property bag.

**Stream 4: Status reconciliation (CE39AE5D)**
Implement **blocking** bidirectional status cascade: when all children of a parent reach done, parent auto-transitions to done. When a parent moves to done, block the transition if children are still active/queued. Blocking enforces workflow behavior — advisory mode silently swallows unhandled work.

**Stream 5: Orphan lifecycle (51B11D29/002-DL)**
Implement 002-DL's chosen direction: null parent_id on shipment return. Add adopt/reparent operation for pulling orphans into new features. **Keep provenance IDs** on adoption — easier to maintain than cascading renames. Add orphan indicator to queue views.

**Dependency order:** Stream 1 (naming) first — all other streams build on the new ID system. Stream 2 (parenting) next. Streams 3 and 4 can parallelize after 1+2. Stream 5 last, depends on all prior streams.
<!-- END:chosen-direction -->
