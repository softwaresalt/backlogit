# CLI/MCP list_items request-contract parity for priority/owner filters

## Problem Frame

<!-- BEGIN:problem-frame -->
CLI `backlogit list` already implements `--priority` (internal/cli/list.go:250) and `--owner` (internal/cli/list.go:169, :200). The MCP tool `backlogit_list_items` (internal/mcp/tools.go:78-84) does NOT expose priority/owner params. This is an existing CLI/MCP request-contract ASYMMETRY: the CLI already has the filters and MCP lacks them. Deferred from 117-F adversarial review (Parity-P2). Adding priority/owner to MCP `list_items` would CLOSE the asymmetry (achieve CLI/MCP parity), not widen it. The decision must still be deliberate, because compound learnings caution against changing request-contract parity between surfaces without an explicit, documented decision.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
- Option A: Add `priority` and `owner` filters to MCP `backlogit_list_items` to reach CLI/MCP parity (close the existing asymmetry). Preferred if parity is the goal.
- Option B: Intentionally keep the asymmetry; document the rationale for MCP omitting the filters (e.g. agents should prefer `backlogit_query_sql` for filtered lookups).
- Option C: Narrow the CLI surface instead (deprecate/remove CLI `--priority`/`--owner`) to reach parity from the other direction. Listed for completeness; likely undesirable because it removes working CLI functionality.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
**Option A** — add `priority` and `owner` filter parameters to the MCP tool `backlogit_list_items` to reach CLI/MCP request-contract parity. Rationale: closes the existing asymmetry (the CLI already exposes both filters and the data layer already supports them), additive/backward-compatible, and improves agent ergonomics. Decided 2026-07-23; promoted to plan (target v1.7.0). See `docs/decisions/2026-07-23-cli-mcp-list-items-parity-deliberation.md`, `docs/exec-plans/2026-07-23-mcp-list-items-parity-plan.md`, and feature `122-F`.
<!-- END:chosen-direction -->
