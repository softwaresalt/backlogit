scanCanonicalArtifacts (internal/core/canonical_scan.go) walks+parses every queue/archive .md on each CreateArtifact (internal/core/artifacts.go) call, so bulk callers -- the internal/core/migrate.go external import loop and internal/stash harvest -- and large mature backlogs incur O(files) per create -> O(N^2). Scan once per batch and pass the canonical map in, or memoize within a create batch; single interactive creates stay unchanged. Source: 066-S review of feat/066-root-id-integrity.

<!-- BEGIN:acceptance-criteria -->
- Bulk create paths (internal/core/migrate.go external import loop and internal/stash harvest) perform the canonical scan at most once per batch, not once per CreateArtifact call.
- Single interactive CreateArtifact calls retain existing behavior; canonical-uniqueness is still enforced.
- Existing internal/core guard tests (066_create_guard_test.go, canonical_scan_test.go) pass; a test or benchmark shows per-batch scan count is O(1), not O(N).
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Approach: (a) hoist scanCanonicalArtifacts to build the canonical map once and pass it into CreateArtifact for the batch, or (b) memoize the canonical map within a create-batch scope. Leave the interactive single-create path unchanged (YAGNI). Scope: internal/core/canonical_scan.go, internal/core/artifacts.go (CreateArtifact), callers internal/core/migrate.go + internal/stash. Source: 066-S review of feat/066-root-id-integrity. ~2h, single domain (Go code).
