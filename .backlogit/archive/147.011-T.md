Plan unit **U6** (partition 4). `ListCheckpoints` surfaces non-conforming files.

Files: `internal/events/checkpoint_lifecycle.go`, `internal/events/checkpoint_lifecycle_test.go`.

After the existing `ValidateCheckpoint` branch, run `CheckConformingTopLevelNamespace(data)`; on failure set `NeedsQuarantine = true` and `RemediationIntent`, and **append** to `ValidationErr` rather than overwriting it - a file can fail both validation and conformance and the operator needs both reasons.

**Cycle-17 change (gate finding H1): the conformance branch publishes structured intent, never a command string.** Set `RemediationIntent = &RemediationIntent{Verb: "quarantine", TargetFilename: <bare filename>, RequiresApproval: true, ApprovalClass: "A4c", Reason: "non_conforming"}` - the carrier 147.032-T / U1d declares - and leave `RemediationCommand` untouched. `internal/events` has no knowledge of the caller''s working directory, so any command string it emits is bound to an ambient cwd and carries no approval, preimage, or no-clobber obligation. Rendering an operator command is the CLI boundary''s job and belongs to 147.039-T / U16. The shipped `RemediationCommand` population on the pre-existing parse-failure branch is left exactly as it is; removal is follow-up stash `F350503F`.

`ListCheckpoints` stays strictly read-only. The conformance branch runs **before** the filter block so the verdict is computed for every parsed document. Ordering is not exemption: whether a quarantine candidate also becomes filter-exempt is owned by 147.023-T / U6d, and this task must not claim a drop-through guarantee it does not implement.

Red verification: `go test -count=1 -run '^TestU6_' ./internal/events`.
