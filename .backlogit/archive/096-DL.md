# CAP-3 (703835DC): Fix commit-writer lock-order inversion (global before C) across persistence and compensation with shipment-member regression test

## Problem Frame

<!-- BEGIN:problem-frame -->
Deferred scope expansion `703835DC` from `200-F` / `200-S` (PR #540, review thread `PRRT_kwDORzozKM6tyLh3`): commit writers (`AssociateCommit` / `LinkCommit` / `track_commit` in `internal/core/commits.go`) must acquire `lifecycle-global` before item-log lock `C` (when the item is a shipment member) and maintain `global -> C -> B` lock order through persistence and compensation, matching `ArchiveItem` and `ShipShipment`, with a forced-interleaving regression test using a real shipment member.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Leave `LinkCommit` acquiring `C` without `lifecycle-global` and writing `commit_links` unlocked. Pros: no code change. Cons: leaves `LinkCommit` / `AutoLinkCommits` vulnerable to `C`-then-`global` lock-order inversion and unserialized `commit_links` writes against `ReconstituteShipments`, `ArchiveItem`, and `ShipShipment`, and lacks forced-interleaving regression coverage for shipment members.
Option B (Recommended): Enforce `lifecycle-global -> C -> B` lock ordering across both `AssociateCommit` and `LinkCommit` in `internal/core/commits.go` (including preheld-`C` validation and `global` acquisition before `commit_links` SQLite writes and `LockItemLogCrossProcess`), and add forced-interleaving regression tests using a real shipment member in `internal/core/commits_test.go`. Pros: eliminates the commit-writer lock-order inversion across all entrypoints (`AssociateCommit`, `LinkCommit`, `AutoLinkCommits`, `track_commit`) and proves ordering across persistence and compensation. Cons: none.
Option C: Remove `LinkCommit` entirely. Pros: eliminates deprecated function. Cons: breaks `attachCommitToItems` (`shipment_lifecycle.go:975`), `AutoLinkCommits`, and existing `TestLinkCommit_*` callers.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Harden `LinkCommit` and `AssociateCommit` in `internal/core/commits.go` so that all commit writers enforce canonical lock ordering `lifecycle-global -> C (item-log) -> B (artifact mutation)` when the target item is a shipment or shipment lifecycle member (or across commit-writer mutations). Specifically: (1) in `LinkCommit`, check `events.ItemLogCrossProcessLockHeld` and verify preheld lifecycle ownership via `validateShipmentLifecycleGlobalReentry(ctx, ws, "LinkCommit")` (refusing with `shipmentLifecycleLockOrderError` / `ErrShipmentLockOrderInverted` when `C` is held without verified `global` on a shipment or shipment member), and when `C` is not preheld (and `ws != nil` and `ws.RootPath != ""`), acquire `lockShipmentLifecycleGlobal(ctx, ws)` BEFORE `db.ExecContext(ctx, "INSERT OR REPLACE INTO commit_links ...")` and BEFORE `events.LockItemLogCrossProcess`, holding it through `AppendEvent` and `IndexEvent`; (2) in `AssociateCommit`, retain `lockShipmentLifecycleGlobal` acquisition before `findArtifact`, `commit_links` snapshot, and `LockItemLogCrossProcess`, keeping `global -> C -> B` across persistence and compensation; and (3) add a deterministic forced-interleaving regression test in `internal/core/commits_test.go` using a real shipment member.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
None. When `ShipShipment` calls `attachCommitToItems` -> `LinkCommit`, `ShipShipment` already holds `lockShipmentLifecycleGlobal` in `ctx`, so `lockShipmentLifecycleGlobal` inside `LinkCommit` re-enters cleanly.
<!-- END:open-questions -->
