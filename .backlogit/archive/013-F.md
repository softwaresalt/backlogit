The CI and release workflows in `.github/workflows/` have three defects that block reliable tagged releases and CI validation for the current codebase version.

1. The release.yml tag trigger uses regex-like syntax (`v[0-9]+.[0-9]+.[0-9]+*`) but GitHub Actions tag filters expect glob patterns, so semver tags may silently fail to trigger the release workflow.
2. Both ci.yml and release.yml run Go 1.22/1.23, but go.mod requires Go 1.24.0. Builds and tests may fail or produce binaries compiled against the wrong Go version.
3. All third-party GitHub Actions are version-pinned with tags (`@v4`, `@v5`) instead of full commit SHAs, violating the repository's own `.github/instructions/workflows.instructions.md` security requirements.

Fixing these three issues unblocks reliable release publishing and brings workflows into compliance with repository standards.
