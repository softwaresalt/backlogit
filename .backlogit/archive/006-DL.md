# Archive consistency invariants and workflow backstops

## Problem Frame

<!-- BEGIN:problem-frame -->
Shipping and archival are intended to move released scope out of `.backlogit/queue` and into `.backlogit/archive`, but the current workspace reached a state where the shipped 021-F / 009-S scope existed in both locations. Inspection shows this is not purely a prompt gap: `ShipShipment` already routes through `ArchiveItem`, and `ArchiveItem` already removes the original file, but current shipment tests only assert archived status/loadability and do not assert that the original queue path is absent. The practical result is that agents can complete shipping while duplicate current-state artifacts linger in queue, leaving misleading workspace state and forcing later cleanup.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: instruction-only fix. Update Ship and operational-closure definitions to require a post-ship verification that every archived ID exists in `.backlogit/archive` and does not exist in `.backlogit/queue`. Fast and low-risk, but only helps compliant agents.\n\nOption B: product invariant in backlogit core. Extend `backlogit_ship_shipment` and/or `ArchiveItem` to verify original-path removal and fail when an archived ID still exists in queue. Strongest guarantee, but requires code changes.\n\nOption C: add a doctor or audit command and MCP tool. Detect duplicate IDs across queue/archive, shipped shipments left active, and stale queue leftovers. Broad coverage for agents, humans, and CI, but detects after the fact unless wired into required workflows.\n\nOption D: CI integrity check for `.backlogit/`. Fail when the same ID exists in both queue and archive or when shipped scope remains in queue. Valuable backstop, but still secondary to runtime invariants.\n\nOption E: test hardening only. Extend archive and shipment tests to assert queue-path absence and no duplicate IDs after shipping. Cheap and high leverage, but incomplete without runtime or workflow enforcement.\n\nOption F: policy-only archival design under existing 012-T. Clarify manual versus shipment-close versus age-based archival policy. Useful for lifecycle semantics, but policy alone does not prevent duplicate storage state.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Adopt a layered approach. First, harden tests so queue-path absence becomes a required invariant. Second, add a product-level archive consistency check, either directly in shipment/archive flows or via a dedicated doctor command that can also be used from CI and MCP. Third, update Ship and operational-closure instructions so agents must verify that archived IDs are absent from queue before declaring shipment closure complete. Keep the policy discussion in 012-T, but route the mechanical invariant and doctor implementation as stability work under 020-F or a child task of that feature.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
Should archive consistency enforcement live inline inside `ArchiveItem` / `ShipShipment`, or should the core flow remain permissive and delegate strictness to a doctor command plus CI?\n\nShould duplicate ID detection be limited to queue/archive, or generalized to all workspace storage roots to catch broader storage drift?\n\nShould the agent-facing verification step be mandatory only for Ship, or also for any direct `backlogit archive` bulk operation?\n\nIf an invariant check fails after partially archiving a release scope, what rollback or repair behavior should backlogit provide?
<!-- END:open-questions -->
