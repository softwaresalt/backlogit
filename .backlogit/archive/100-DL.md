# CAP-3 (B25BF131): Harden TestU4 profile_b custody handoff under concurrent -race load with git seed isolation and diagnostic failure capture

## Problem Frame

<!-- BEGIN:problem-frame -->
Stash `B25BF131` (from `210-F` / `211-S`, PR #641): `TestU4_CustodyPreviewOfferAcceptVerifyAndRecovery/profile_b_stage_to_ship_handoff_and_stale_digest_invalidation` failed once in ~9 `-race` runs under concurrent package load (taking 78s) without diagnostic context captured. Investigation of `custody_exec_test.go` and `custody_exec.go` shows each `profile_b` run spawns ~25 serial `git` subprocesses without `core.fsmonitor=false` / `gc.auto=0` in `buildCustExecSeed` and with bare `require.NoError(t, err)` / `assert.Equal` calls that omit the full `CustodyVerifyResult.Verdicts` reason details.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Leave `TestU4_CustodyPreviewOfferAcceptVerifyAndRecovery/profile_b_stage_to_ship_handoff_and_stale_digest_invalidation` unchanged. Pros: no change. Cons: leaves `custExecSeed` without `core.fsmonitor=false` / `gc.auto=0` and lacks diagnostic failure capture on `profile_b` steps.
Option B (Recommended): Harden `buildCustExecSeed` and `TestU4_CustodyPreviewOfferAcceptVerifyAndRecovery/profile_b_stage_to_ship_handoff_and_stale_digest_invalidation` in `internal/core/custody_exec_test.go` with `core.fsmonitor=false` / `gc.auto=0` in the seed repo config, bounded subtest contexts, and detailed diagnostic messages on every step/verdict assertion (while keeping `PRAGMA synchronous = FULL` on `repo.ws.DB`). Pros: eliminates background Git daemon interference under `-race`, captures complete diagnostic context on any failure, and respects the Ordinal 17 WAL `ModTime` invariant. Cons: none.
Option C: Set `PRAGMA synchronous = OFF` in `custExecNewRepo`. Pros: slightly faster SQLite writes. Cons: KNOWN REGRESSION (caused Ordinal 16 failure in `preview_and_verify_zero_write_and_default_branch_refusal` due to delayed Windows NTFS `backlogit.db-wal` `ModTime` updates). Explicitly rejected!
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Harden `TestU4_CustodyPreviewOfferAcceptVerifyAndRecovery/profile_b_stage_to_ship_handoff_and_stale_digest_invalidation` (and `custodyReviewOfferAdoption`) in `internal/core/custody_exec_test.go` by: (1) adding diagnostic step-timing and rich error/verdict context to every `PreviewCustodyCandidates`, `OfferCustodyHandoff`, `AcceptCustodyHandoff`, and `VerifyCustodyState` assertion in `profile_b_stage_to_ship_handoff_and_stale_digest_invalidation` so any future failure records the exact step, elapsed duration, and full verdict/reason payload; (2) bounding each subtest's `ctx` with an explicit per-subtest timeout and ensuring `custExecSeed` disables Git `core.fsmonitor` and `gc.auto` in the seed config so cloned custody test repositories never trigger background Git fsmonitor/gc daemons under concurrent `-race` package load; and (3) leveraging the `custodyGit` / `custodyBlobDigest` optimization from `9CFC88E5` so `profile_b` spawns fewer `git` subprocesses under `-race`.
<!-- END:chosen-direction -->

## Open Questions

None. Preserves `PRAGMA synchronous = FULL` in `custExecNewRepo` (Ordinal 17 invariant).
