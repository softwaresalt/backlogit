Follow-up hardening identified during 122-S PR review (Copilot, review-fix cycle 5, accepted as
backlog per the 3-cycle review-fix limit rather than blocking merge).

moveNoReplace's os.Link + os.Remove sequence (used by QuarantineCheckpoint to move a malformed
checkpoint to the archive) does not respect the workspace's durable_writes config option: neither
the new destination dirent nor the removal of the source dirent is fsynced. When durable_writes is
enabled, other mutation paths in this codebase fsync the affected directories after a mutation
(see internal/core/durable_fs.go) so a power loss cannot silently lose or resurrect a file; this
move path is currently an exception to that contract.

Fix: route the destination-directory and source-directory fsyncs through the repository's existing
durable directory-sync primitives (internal/core/durable_fs.go) when WorkspaceDurableWrites(ws) is
true, and classify any post-mutation fsync failure as indeterminate (ErrWriteIndeterminate) rather
than silently succeeding.

Files likely touched: internal/core/checkpoint_disposition.go (moveNoReplace), possibly
internal/core/durable_fs.go for a reusable directory-fsync-after-link-remove helper.
