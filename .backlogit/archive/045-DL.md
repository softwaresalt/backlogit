# events.jsonl Fact Table Harvest — Design Decision Record

## Problem Frame

<!-- BEGIN:problem-frame -->
The existing telemetry harvest pipeline (`backlogit telemetry harvest`) ingests session-state data from `.copilot/session-state/*/telemetry.jsonl` files, producing session-level aggregates. However, there was no granular fact-table layer capturing individual tool invocations or per-session context window composition. This meant agents could not answer questions like "which tool is called most often?", "what is the average MCP tool call duration?", or "how much of my context window is consumed by tool definitions vs conversation?". The problem was: how do we add a granular telemetry fact-table layer that is additive (no breaking changes), incrementally harvested (not re-processed on every run), and queryable via the existing `backlogit telemetry report` surface?
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A — Extend telemetry.jsonl schema to include per-call rows: Rejected. telemetry.jsonl is session-scoped and the schema is stable. Adding per-call rows would mix granularities, break the aggregate-only reader, and require a migration of all existing telemetry files.

Option B — Star schema with separate dimension tables: Rejected. The reporting surface (CLI, JSONL, CSV, Markdown) is flat. Star-schema joins add complexity for readers and agents. Wide flat rows with all dimensions embedded were simpler and sufficient for the reporting queries needed.

Option C — Wide fact-table JSONL files (chosen): Two new JSONL fact tables in .backlogit/telemetry/: tool-calls.jsonl (one row per tool call) and session-facts.jsonl (one row per shutdown session). Schema evolution via omitempty — additive fields only, no breaking changes. Each row is self-contained for direct consumption. MCP tool name resolution: use mcpToolName (short form) when present; otherwise strip server prefix from toolName.

Option D — Separate CLI command (backlogit telemetry facts): Rejected. Adds CLI surface area without benefit. Extending the existing --by flag on backlogit telemetry report was backward-compatible and consistent with the --by model and --by class dimensions already present.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option C (wide fact-table JSONL) was chosen for tool-calls.jsonl and session-facts.jsonl, with Option D rejected in favour of extending the existing --by flag. Key design decisions: (1) events.jsonl has two coexisting schemas — old-format uses event_type (compaction events only); new-format uses type + nested data. The parser uses type exclusively, ignoring event_type entirely. (2) Token data is only available at session aggregate level in session.shutdown — not per-turn — so session-facts.jsonl is keyed per-session, not per-turn. (3) Incremental checkpoint: sessions with a session.shutdown event are recorded in HarvestCheckpoint.ProcessedEventSessions and skipped on subsequent harvests. Force mode clears the checkpoint. (4) Two new reporting dimensions: --by tool (call count, success%, avg/total duration, session count) and --by context (system%, conversation%, tooldef%, cache% per session). (5) All quality gates passed: go test ./... (7 new tests), go vet, golangci-lint, gofmt.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
None — all design questions were resolved during implementation. Live harvest confirmed correctness: 38,910 tool call facts across 60 sessions, 44 session facts with shutdown events. PR #98 is open with all CI checks green, awaiting merge approval.
