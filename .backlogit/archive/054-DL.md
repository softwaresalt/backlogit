# Provision markdownlint tooling to make P-008 reproducible and CI-enforced

## Problem Frame

<!-- BEGIN:problem-frame -->
P-008 (workflow-policies.md) asserts a precondition that a .markdownlint.json enabling MD001/MD025/MD041 exists and a postcondition that markdownlint '**/*.md' exits 0, but the repo ships NO config, NO Makefile md-lint target, and NO CI job. The gate is unreproducible and unenforced; agents fall back to markdownlint defaults. Complication: a read-only inventory (markdownlint-cli2 v0.23.1, MD001/MD025/MD041 only, git-tracked .md) found 249 violations across 248 tracked files, so a literal repo-wide '**/*.md' exit-0 gate cannot be turned on today.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) Fix all 248 violating files then gate repo-wide. B) Scoped rollout: provision config + curated ignore set aligned to CI's existing .backlogit exclusion, gate green Day-1, widen over time. C) Baseline existing violations via a generated baseline file, gate only new violations.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
SUPERSEDED DECISION (operator — repo-wide doctor-to-compliance). This deliberation initially recommended Option B (scoped rollout with a curated ignore set). After a feasibility read, the operator superseded it with a refined Option A — make the whole repo compliant and gate repo-wide — because ~92% of the 250 violations dissolve via configuration rather than file edits. Chosen direction: (1) `.markdownlint.json` enabling exactly MD001/MD025/MD041 (`default:false`) with MD025's `front_matter_title` retargeted to a non-existent `_title` key, so a frontmatter `title:` is not counted as a heading — this eliminates all 229 frontmatter-`title:` + body-`# H1` MD025 double-counts with ZERO file edits (MD041 stays default so `title:` still credits it). (2) Remediate the ~21 real structural violations (20 SKILL.md missing a leading `# H1` → MD041; 1 H2→H4 skip → MD001). (3) `.markdownlint-cli2.jsonc` with `gitignore:true` so the gate lints the non-gitignored Markdown corpus — in a clean CI checkout this equals exactly the tracked set, and locally it also covers new/untracked non-ignored Markdown (no scoped `ignores` array). (4) Paired `scripts/md-lint.{sh,ps1}` (guard-safe) delegated from Makefile/make.ps1. (5) A repo-wide, SHA-pinned, hard-failing `md-lint` CI job (no `md_touched` classifier, no advisory cycle). (6) P-008 reconciled to the now-genuinely-true universal statement. EMPIRICAL VERIFICATION (markdownlint-cli2@0.23.1, 1839 tracked files): default rule set = 250 (MD001=1/MD025=229/MD041=20); `_title` config alone (zero edits) = 21; config + ~21 remediations = 0 repo-wide. Rejected the original scoped Option B (unnecessary once the `_title` config makes universal compliance achievable) and baseline Option C (no native cli2 baseline).
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
RESOLVED by the operator's repo-wide decision: the md-lint check is repo-wide and blocking from the start (no advisory-vs-required staging; branch-protection registration is an external admin step tracked in follow-up stash 918BCDAF). No directories are permanently ignored — universal compliance is achieved via the `_title` config plus the ~21 remediations. Exact `actions/setup-node` pin SHA resolved at implementation (F013).
