# Provision markdownlint tooling to make P-008 reproducible and CI-enforced

## Problem Frame

<!-- BEGIN:problem-frame -->
P-008 (workflow-policies.md) asserts a precondition that a .markdownlint.json enabling MD001/MD025/MD041 exists and a postcondition that markdownlint '**/*.md' exits 0, but the repo ships NO config, NO Makefile md-lint target, and NO CI job. The gate is unreproducible and unenforced; agents fall back to markdownlint defaults. Complication: a read-only inventory (markdownlint-cli2 v0.23.1, MD001/MD025/MD041 only, git-tracked .md) found 249 violations across 248 tracked files, so a literal repo-wide '**/*.md' exit-0 gate cannot be turned on today.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) Fix all 248 violating files then gate repo-wide. B) Scoped rollout: provision config + curated ignore set aligned to CI's existing .backlogit exclusion, gate green Day-1, widen over time. C) Baseline existing violations via a generated baseline file, gate only new violations.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (scoped rollout with curated ignore set). Provision .markdownlint.json (exactly MD001/MD025/MD041, default:false) + .markdownlint-cli2.jsonc carrying an ignores glob array over all currently-violating tracked dirs (.backlogit, .autoharness, .github/skills, plugin, docs/archive, docs/closure, docs/compound, docs/decisions, docs/design-docs, docs/exec-plans, docs/memory, docs/research, docs/reviews) plus the root file offenders README.md and AGENTS.md (file-level ignores) and ephemeral dirs (.copilot, .copilot-tracking, logs) so make md-lint is provably exit-0 on Day 1. VERIFIED (cli2 v0.23.1): a bare .markdownlintignore is NOT honored, whereas the ignores array in .markdownlint-cli2.jsonc IS honored; cli2 also auto-reads .markdownlint.json for rules. Makefile md-lint target via a bare pinned npx markdownlint-cli2@0.23.1; a new always-reporting md-lint job in ci.yml gated by a md_touched paths-filter output with SHA-pinned actions/setup-node; and a P-008 wording fix. Rejected A (violates 2h/single-domain granularity, churns historical/archival + template-generated .github/skills which Principle IV forbids fixing durably) and C (cli2 lacks first-class baseline; stale baselines hide regressions in touched files).
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
Should the md-lint check be made a REQUIRED status check immediately or after one green cycle? Which historical/archival dirs stay permanently ignored vs scheduled for future widening remediation? Exact SHA for actions/setup-node (Ship resolves at implementation).
