# CAP-2 (0D073C21): Expose server-owned coordinator/full-shutdown drain API on mcp.Server preserving CloseAllSessions session-only semantics

## Problem Frame

<!-- BEGIN:problem-frame -->
Deferred scope expansion `0D073C21` from `211.005-T` (`U5`, `211-F`, `212-S`): `RunMCPDaemon` in `internal/cli/mcp_daemon.go` requires draining both active sessions and the server-owned `OperationCoordinator` on graceful stop, while `(*Server).CloseAllSessions()` in `internal/mcp/session_mux.go:543-574` must preserve session-only semantics so in-process `InvokeTool` callers are not broken after session closure.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Leave `s.coordinator.Close()` inside `(*Server).CloseAllSessions()`. Pros: zero code change. Cons: violates `CloseAllSessions` session-only contract by permanently killing `s.coordinator` (breaking in-process `InvokeTool` after session drain) and leaves `0D073C21` unresolved.
Option B (Recommended): Decouple session drain (`(*Server).CloseAllSessions()`) from coordinator closure (`(*Server).CloseCoordinator()` / `(*Server).Shutdown()`) in `internal/mcp/session_mux.go`, track and drain all admitted in-flight handlers inside `(*OperationCoordinator).Close()` (`internal/mcp/coordinator.go`), and wire `RunMCPDaemon` in `internal/cli/mcp_daemon.go` to call `s.Shutdown()`. Pros: honors U5 graceful-stop contract (`docs/plans/2026-11-04-multi-session-mcp-runtime-plan.md:649`), preserves `CloseAllSessions` session-only semantics for in-process `InvokeTool` callers, ensures `Shutdown()` never returns while an admitted in-process `InvokeTool` handler is still using `s.Workspace`, and keeps `s.coordinator` encapsulated. Cons: touches 2 packages (`internal/mcp` and `internal/cli`), so decompose into two width-isolated tasks (`internal/mcp` API task -> `internal/cli` daemon caller task).
Option C: Export `Server.Coordinator *OperationCoordinator` field directly. Pros: trivial. Cons: leaks internal concurrency primitive across package boundaries.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Restore `(*Server).CloseAllSessions()` in `internal/mcp/session_mux.go` to pure session-only semantics (stopping session admission, cancelling active sessions, and joining their drains without closing `s.coordinator`), update `(*OperationCoordinator).Execute` and `(*OperationCoordinator).Close()` in `internal/mcp/coordinator.go` to decouple `stopAdmission()` from draining and to track/drain all admitted in-flight handlers (`activeHandlers sync.WaitGroup` synchronized with `c.closed` under `admitMu`), and expose `(*Server).CloseCoordinator() error` and `(*Server).Shutdown() error` on `*mcp.Server` in `internal/mcp/session_mux.go` such that `Shutdown()` stops both session admission and coordinator admission (`s.coordinator.stopAdmission()`) FIRST before waiting on either session drains or coordinator handler drains. Update `RunMCPDaemon` in `internal/cli/mcp_daemon.go` (lines 108 and 167) to invoke `s.Shutdown()` before `workers.Wait()` and `s.Workspace.Close()`.
<!-- END:chosen-direction -->
