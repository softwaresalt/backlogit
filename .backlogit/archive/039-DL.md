# Telemetry Validation and Markdown Report Builder

## Problem Frame

<!-- BEGIN:problem-frame -->
The telemetry package (`internal/telemetry/`) is extensive — parser, correlator, harvest orchestrator, reporter, context window metrics, session events, session store, and attribution — but has two gaps:\n\n1. **Behavioral test coverage is minimal.** Existing tests (`cli/telemetry_test.go`) verify command registration and flag existence but do not exercise harvest, correlation, or report generation with realistic data fixtures. The package has good unit test files but the end-to-end pipeline is untested.\n\n2. **No markdown report format.** The reporter supports table and JSON output but not markdown, which is the natural format for agent consumption and documentation embedding. The stash entry specifically calls for a markdown report builder.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
**Option A: Behavioral Tests Only**\nAdd integration tests with realistic JSONL fixtures that exercise the full harvest-correlate-report pipeline. Validates the existing code works correctly. Does not add new features.\n\n**Option B: Markdown Report Builder Only**\nAdd a `markdown` format option to the reporter and MCP tool. Includes session summary tables, token usage breakdowns, and context window metrics in markdown. Does not validate existing code.\n\n**Option C: Both Tests + Markdown Report (Recommended)**\nAdd behavioral test fixtures first (TDD), then implement the markdown report builder against those tests. Validates the foundation before building on it. Follows the constitution's test-first mandate.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option C — Behavioral tests with realistic data fixtures, followed by a markdown report builder. The test-first approach validates the existing harvest and correlation pipeline before adding new output formats. The markdown reporter adds practical value for agent consumption (backlogit MCP tool returns structured reports) and documentation embedding.\n\nThe markdown report should include: session summary table, token usage by model, tool call attribution by server, and context window utilization metrics. ASCII charts are out of scope (YAGNI).
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
1. Should the markdown report include a per-session detail section or just aggregated summaries?\n2. Should the MCP tool `backlogit_telemetry_harvest` return a report preview, or should reporting remain a separate operation?\n3. What realistic test fixtures should be created — synthetic JSONL or sanitized real data?
<!-- END:open-questions -->

## Notes

<!-- BEGIN:notes -->
Existing telemetry surface:\n- CLI: `backlogit telemetry harvest|list|top|report`\n- MCP: `backlogit_telemetry_harvest`\n- Reporter: `GenerateReport()` with ReportOptions (SessionID, GroupBy, Format, Limit)\n- Supported GroupBy: session, server (model and tool are not yet implemented)\n- Supported Format: table, json (markdown would be new)\n- Context window: `ComputeContextMetrics()` with PeakUtilization, RemainingCapacity, DepletionRate\n- Records: SessionSummaryRecord, ToolUsageRecord in telemetry-sessions.jsonl\n\nScope boundaries:\n- IN: behavioral test fixtures, end-to-end harvest test, markdown format for reporter, markdown format flag in CLI and MCP\n- OUT: graphical output, model/tool groupBy dimensions (future work), dashboard UI, real-time streaming
<!-- END:notes -->
