## Findings

### P1 — Fixed

#### fetchBuf(): crash on missing Location header (FIXED — b5a45ff)

**File:** `npm/backlogit-mcp/lib/resolve.js`
**Persona:** JS/npm Reviewer

Malformed 3xx responses without a `Location` header caused `get(undefined)` to be called in `fetchBuf()`, crashing the promise chain with an opaque error. Fixed by adding an explicit guard that rejects the promise with a descriptive error when `headers.location` is absent.

**Fix applied:** Added `if (!headers.location) return reject(new Error(...))` before the recursive `get()` call. Also added `res.resume()` to drain the response body on redirect to prevent socket leaks.

### P2 — Backlog follow-up items created

#### Version validation before tier3 download (048.006-T)

**File:** `npm/backlogit-mcp/lib/resolve.js`
**Persona:** JS/npm Reviewer

`tier3()` constructs a GitHub Releases URL using `version` directly from `package.json`. In development/pre-release, `version` is `0.0.0` (placeholder stamped by CI before publish). A direct `npm install` from the repo produces a confusing HTTP 404 when tier3 fires. CI stamps the correct version before publishing so released packages are unaffected, but a semver guard would produce a clear error message in the placeholder case.

**Follow-up:** `048.006-T` — add semver validation in tier3, reject `0.0.0` with an actionable message.

#### HTTPS proxy support (048.007-T)

**File:** `npm/backlogit-mcp/install.js`, `npm/backlogit-mcp/lib/resolve.js`
**Persona:** JS/npm Reviewer

Node.js built-in `https` module does not respect `HTTPS_PROXY`/`https_proxy` environment variables. Tier3 downloads will fail silently for users behind corporate HTTP proxies. Tier1 (PATH) and Tier2 (npm optional dep) are unaffected. The postinstall already silently continues on download failure, but users in proxy environments will see a silent failure with no guidance.

**Follow-up:** `048.007-T` — check `process.env.HTTPS_PROXY` and configure an `https.Agent`, or document `go install` as the proxy-safe installation path.

#### Test coverage: install.js and bin/backlogit-mcp.js (048.008-T)

**File:** `npm/backlogit-mcp/install.js`, `npm/backlogit-mcp/bin/backlogit-mcp.js`
**Persona:** Constitution Reviewer (Principle III)

The `test/resolve.test.js` suite covers the resolver module comprehensively (14 tests). However, the CLI entry point (`bin/backlogit-mcp.js`) and postinstall script (`install.js`) have no test coverage. Uncovered surfaces: exit code propagation, error display on resolve failure, tier2/tier3 preinstall paths, and silent failure on network error.

**Follow-up:** `048.008-T` — add `test/install.test.js` and `test/backlogit-mcp.test.js` using `node:test` with dependency injection.

### P3 — Advisory

#### Parallel SHA256SUMS + binary download

**File:** `npm/backlogit-mcp/lib/resolve.js`

`Promise.all([fetchBuf(SHA256SUMS_URL), fetchBuf(binary_URL)])` downloads both in parallel. Conventional security practice downloads the checksum manifest first, verifies it, then fetches the artifact. No practical vulnerability since verification happens before writing, but sequential ordering is the industry norm.

#### Cache directory not user-configurable

**File:** `npm/backlogit-mcp/lib/resolve.js`

Binary cache is hardcoded to `~/.cache/backlogit/bin/`. Consider honouring `BACKLOGIT_CACHE_DIR` env var or `XDG_CACHE_HOME` for environments with restricted home directories or multi-user deployments.

#### `jq` not explicitly verified in package-npm.sh

**File:** `scripts/package-npm.sh`

`jq` is pre-installed on `ubuntu-latest` but is an implicit dependency. Adding `command -v jq >/dev/null 2>&1 || { echo "jq required"; exit 1; }` guards against environment drift.

#### npm-publish failure visibility

**File:** `.github/workflows/release.yml`

`continue-on-error: true` on npm-publish (per plan review P3-1) means npm failures do not break the GitHub Release. This is intentional. However, there is no alerting mechanism (Slack, issue comment) when npm publish silently fails. Maintainers may not notice a failed npm release cycle until users report missing packages.
