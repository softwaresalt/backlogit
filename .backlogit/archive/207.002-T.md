Project complexity_source and complexity_ruleset_version into the SQLite items table for task artifacts only, add bound-parameter filter support (ComplexitySource, ComplexityRulesetVersion) in db.QueryFilters and db.QueryItems, and implement IsTaskRouteEligible requiring all 6 size + complexity provenance fields to be present and valid.

<!-- BEGIN:acceptance-criteria -->
* RED phase is observed failing in `go test -count=1 -run '^TestU2_ComplexityProvenanceProjectionAndRouteEligibility$' ./internal/db` before production implementation.
* `db.UpsertItem` and `db.Rehydrate` project `complexity_source` and `complexity_ruleset_version` into the SQLite `items` table for `task` artifacts only (skipping non-tasks) and null all 3 complexity columns when cleared.
* `db.QueryItems` supports bound-parameter filtering via `QueryFilters.ComplexitySource` and `QueryFilters.ComplexityRulesetVersion` (injection-safe) while preserving all existing null-complexity and value-only tasks without error.
* `db.IsTaskRouteEligible` and `core.IsTaskRouteEligible` return `true` if and only if the artifact is a `task` and all 6 size + complexity provenance fields (`size`, `size_source`, `size_ruleset_version`, `complexity`, `complexity_source`, `complexity_ruleset_version`) are present and valid against their allowed enums and ruleset constraints, and return `false` after a value-only complexity update clears `complexity_source` and `complexity_ruleset_version` on a previously provenance-complete task.
* GREEN phase passes `go test -count=1 -race ./internal/db/... ./internal/core/...`.
<!-- END:acceptance-criteria -->
