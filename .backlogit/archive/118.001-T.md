## Measurement — EXPLAIN QUERY PLAN

Query shape (GetTaskChildrenByParentIDs chunk):
`SELECT ... FROM items WHERE parent_id IN (...) AND artifact_type='task' ORDER BY parent_id, id`

- BEFORE (no composite index):
  - `SEARCH items USING INDEX idx_items_type (artifact_type=?)`
  - `USE TEMP B-TREE FOR LAST TERM OF ORDER BY`
  - Scans every task by artifact_type, then sorts.
- AFTER (idx_items_parent_type_id on `items(parent_id, artifact_type, id)`):
  - `SEARCH items USING INDEX idx_items_parent_type_id (parent_id=? AND artifact_type=?)`
  - Targeted seek; the index supplies the ordering; no temp b-tree.

Retention check: a bare `WHERE parent_id = ?` still plans
`SEARCH items USING INDEX idx_items_parent (parent_id=?)`, so idx_items_parent
is retained (the planner prefers the narrower index for parent-only lookups).

Locked by `internal/db/task_children_index_test.go` and the schema-column
assertion in `internal/db/schema_gen_test.go`.
