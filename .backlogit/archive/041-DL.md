# Telemetry Quality — Parser Fix & Documentation

## Problem Frame

<!-- BEGIN:problem-frame -->
The telemetry subsystem has four outstanding quality gaps left after the recently shipped 043-S (Doctor Completion and Telemetry Parser) and 044-F (Telemetry Parser Update). These gaps span a parser bug, a CLI behavior defect, and two documentation omissions:\n\n1. **Parser bug (144CA2BB)**: The Copilot telemetry parser uses bufio.Scanner with default token size. Oversized log entries (common in verbose Copilot sessions) trigger a token-too-long error, causing the parser to produce partial sessions with zero-token counts. This corrupts telemetry data quality.\n\n2. **CLI behavior defect (736ABA8A)**: The `telemetry top` docs command currently reports server-level tool-call counts rather than top tool calls ranked by token usage. This misleads users about which tools consume the most context.\n\n3. **Documentation gap — harvest side effects (1FB3E504)**: The telemetry harvest command rehydrates SQLite telemetry tables in addition to writing telemetry-sessions.jsonl. This side effect is undocumented, confusing users who expect harvest to be write-only to JSONL.\n\n4. **Documentation gap — field reference (6DE63CCD)**: The harvested telemetry fields (tokens_by_model, tool_calls_by_server, completed_tasks, tokens_per_task, context-window metrics) lack documentation, making the telemetry output opaque to consumers.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
**Option A: Single shipment with all 4 items**\nGroup all fixes and docs into one feature with 4 tasks. Ship as one branch and PR. Pros: single review cycle, coherent telemetry quality improvement. Cons: slightly larger diff.\n\n**Option B: Split into two shipments (code fixes vs docs)**\nSeparate the bug fix and CLI fix from the documentation tasks. Pros: smaller PRs. Cons: two review cycles for tightly related work, documentation may reference behavior that changes in the code shipment.\n\n**Chosen: Option A** — The scope is small (one bug fix, one behavior fix, two doc additions). A single shipment keeps the telemetry quality story coherent and avoids documentation drift.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Single feature with 4 tasks, shipped as one unit:\n\n- Task 1 (high/bug): Fix bufio.Scanner token-too-long — increase buffer size or switch to bufio.Reader for oversized log entries. Execution order: first, since it affects data quality that docs describe.\n- Task 2 (high/task): Fix telemetry top docs command to rank by token usage, not server-level counts.\n- Task 3 (medium/task): Document telemetry harvest side effects (SQLite table rehydration).\n- Task 4 (medium/task): Document harvested telemetry fields and metrics reference.\n\nDependency: Task 1 should complete before Tasks 3-4 (documentation should reflect fixed behavior). Task 2 is independent.
<!-- END:chosen-direction -->
