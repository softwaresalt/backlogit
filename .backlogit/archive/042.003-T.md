title: Add CHECK constraint on item_links.link_type in SQLite schema
updated_at: 2026-04-23T16:16:59.2512369-07:00
---

Application-layer `isValidLinkType` validation was added in rehydration.go and merge_sync.go (042.001-T, commit 52f734f), but the SQLite schema has no corresponding `CHECK (link_type IN ('related_to', 'duplicate_of', 'informs', 'supersedes', 'spike_ref'))` constraint on the `item_links` table.

Any raw SQL write path that bypasses the application layer can insert invalid link_type values without DB-level rejection.

**Fix**: Add CHECK constraint to the CREATE TABLE / migration for item_links and provide a schema migration for existing databases.

**References**: Review 041.001-R, commit 52f734faf0d659e5f6689a5c97a6ecae15870ffa.
