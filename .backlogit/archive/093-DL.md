# CAP-2 (D1455316): Extend static workspace-toolchain validation to identify backlogit by executable identity and require --cwd on aliased entries

## Problem Frame

<!-- BEGIN:problem-frame -->
Deferred scope expansion `D1455316` from `212.002-T` (`U9`, `212-F`, `213-S`): static workspace-toolchain validation in `internal/toolchain/verify.go` and `internal/toolchain/launcher.go` currently checks `strings.EqualFold(strings.TrimSpace(tool.ID), "backlogit")` when requiring workspace-root `--cwd` bindings, allowing a differently named (aliased) entry pointing to `backlogit.exe` to omit `--cwd` and potentially attach to the wrong workspace.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Identify `backlogit` only when `strings.EqualFold(strings.TrimSpace(tool.ID), "backlogit")`. Pros: no code change. Cons: an aliased inventory/server entry (e.g., `id: "backlog-alias"`, `executable_path: "./bin/backlogit.exe"`) bypasses the `--cwd` workspace-root binding check in `verifyLocalTool`, `validateMCPConfigPinning`, and `validateManifestForProvisioning`.
Option B (Recommended): Identify `backlogit` by both inventory/server ID AND executable path/basename identity (`isBacklogitExecutable` / `isBacklogitTool`) in `internal/toolchain/verify.go` and `internal/toolchain/launcher.go`, enforcing `WorkspaceLocalPinned` `./bin/backlogit.exe` and mandatory workspace-root `--cwd` binding on aliased entries. Pros: closes the static alias bypass completely while staying within Level 1 static verification. Cons: touches `verify.go` and `launcher.go` inside `internal/toolchain`.
Option C: Perform content-based binary header / symbol inspection on every tool binary. Pros: catches renamed binaries. Cons: belongs to Level 2 binary provenance (`EC589C00` / `082-DL`) and is out of scope for Level 1 static validation.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Add `isBacklogitExecutable(abs, execPath string) bool` and `isBacklogitTool(abs string, tool ToolEntry) bool` in `internal/toolchain/verify.go`, recognizing `backlogit` both by trimmed case-insensitive `tool.ID == "backlogit"` AND by executable identity (`samePath(rel, filepath.Join("bin", "backlogit.exe"))` / `samePath(rel, filepath.Join("bin", "backlogit"))` or executable basename matching `"backlogit"`, `"backlogit.exe"`, `"backlogit-*"`, `"backlogit_*"`, `"backlogit.*"`). Require `WorkspaceLocalPinned` containment to `./bin/backlogit.exe` and workspace-root `--cwd` binding for all such entries (including aliased tool/server IDs) across `validBacklogitTool`, `verifyWorkspaceToolchain`, `verifyLocalTool`, `validateMCPConfigPinning`, `validateManifestForProvisioning`, and `RenderPinnedMCPConfig`.
<!-- END:chosen-direction -->
