# CAP-2 (3083FC1A): Cross-branch and multi-session artifact ID sequence counter reservation and isolation

## Problem Frame

<!-- BEGIN:problem-frame -->
Intermittent switching between two sessions working on separate branches/issues (or concurrent multi-session creates) causes duplicate `backlogit` feature (`NNN-F`) and task (`NNN.MMM-T`) sequence numbers because `allocateTypedHierarchicalID` and `NextID` only inspect the currently checked-out working tree and SQLite cache without cross-branch sequence reservation or cross-process allocation locking.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Rely solely on current working-tree `.backlogit/queue/` + `.backlogit/archive/` scan and SQLite `items` table. Pros: zero new state. Cons: switching branches (`git checkout`) hides unmerged artifacts created on another branch, and concurrent sessions race between `allocateTypedHierarchicalID` and file write.
Option B (Recommended): Serialize ID allocation + file creation under `<storage_root>/.locks/id_allocator.lock`, persist monotonic high-water-mark reservations in `<storage_root>/.locks/id-sequences.json` (with rollback on failed/compensated create), and augment `historicalIDsFromDisk` with fingerprint-cached local Git branch tree discovery (`refs/heads/*`) when `.git` is present. Pros: prevents duplicate `NNN-F` / `NNN.MMM-T` sequence numbers across concurrent sessions, interleaved branch switches, and multi-branch repos without writing outside the workspace. Cons: adds bounded lock + JSON ledger read/write on `CreateArtifact` and `AdoptItem`.
Option C: Replace sequential numeric IDs (`001-F`) with random UUIDs. Pros: collision-free. Cons: breaks the repository-wide `NNN-F` / `NNN.MMM-T` schema and every existing test.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Introduce a cross-process + in-process sequence reservation ledger and lock in `internal/core/id_history.go` and `internal/core/artifacts.go`. Acquire an advisory file lock (`<storage_root>/.locks/id_allocator.lock`) plus in-process mutex across the ID-allocation and `CreateArtifact` file-creation critical section. Persist monotonic high-water-mark sequence reservations in `<storage_root>/.locks/id-sequences.json` (which is git-ignored under `.locks/` and therefore survives `git checkout` branch switches across sessions in the same workspace) and, when `.git` exists at `ws.RootPath` with multiple local branches, include a fingerprint-cached scan of `.backlog/` and `.backlogit/` artifact filenames across local `refs/heads/*` trees in `historicalIDsFromDisk(ws)`. Only commit the sequence reservation after `MutationEnvelope` succeeds (or roll back the reservation if `CreateArtifact` or `ReconstituteShipments` rolls back).
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
None. Keeping `<storage_root>/.locks/id-sequences.json` inside `.locks/` preserves CLI Workspace Containment (Principle IV) and `workspaceFileSnapshot` (`.md`/`.jsonl` only).
<!-- END:open-questions -->
