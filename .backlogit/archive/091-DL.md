# CAP-2 (3083FC1A): Cross-branch and multi-session artifact ID sequence counter reservation and isolation

## Problem Frame

<!-- BEGIN:problem-frame -->
Intermittent switching between two sessions working on separate branches/issues (or concurrent multi-session creates and adoptions) causes duplicate `backlogit` feature (`NNN-F`) and task (`NNN.MMM-T`) sequence numbers because `allocateTypedHierarchicalID` and `NextID` only inspect the currently checked-out working tree and SQLite cache without cross-branch sequence reservation or cross-process allocation locking across `CreateArtifact`, `AdoptItemWithOptions`, and `ReconstituteShipments`.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Rely solely on current working-tree `.backlogit/queue/` + `.backlogit/archive/` scan and SQLite `items` table. Pros: zero new state. Cons: switching branches (`git checkout`) hides unmerged artifacts created or adopted on another branch, and concurrent sessions race between `allocateTypedHierarchicalID` and file write/rename.
Option B (Recommended): Serialize ID allocation + file creation/adoption under `<storage_root>/.locks/id_allocator.lock` using a pinned `.locks` `*os.Root` directory handle, persist monotonic high-water-mark reservations in `<storage_root>/.locks/id-sequences.json` via handle-relative `atomicfile.ReplaceTempFileInRoot` across `CreateArtifact`, `AdoptItemWithOptions`, and `ReconstituteShipments` (with compensated rollback and outer-operation reconstitution rollback/recovery), and augment `historicalIDsFromDisk` with `eventLogIDs` (`adopted` / `shipment_reconstituted`) and fingerprint-cached local Git branch tree discovery (`refs/heads/*`). Pros: prevents duplicate `NNN-F` / `NNN.MMM-T` sequence numbers across concurrent sessions, create-vs-adopt interleavings, cross-branch reconstitutions, and branch switches without writing outside the workspace. Cons: spans `id_history.go`, `artifacts.go`, `shipment_lifecycle.go`, and `shipment_reconstitute_exec.go` (split into two width-isolated tasks `U5a` and `U5b`).
Option C: Replace sequential numeric IDs (`001-F`) with random UUIDs. Pros: collision-free. Cons: breaks the repository-wide `NNN-F` / `NNN.MMM-T` schema and every existing test.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Introduce a handle-confined (`*os.Root` on `<storage_root>/.locks`) cross-process + in-process sequence reservation ledger and lock across `internal/core/id_history.go`, `internal/core/artifacts.go` (`Unit U5a` / `215.006-T`), `internal/core/shipment_lifecycle.go`, and `internal/core/shipment_reconstitute_exec.go` (`Unit U5b` / `215.008-T`):
1. Confine all `.locks/id-sequences.json` reads, temp creation, `atomicfile.ReplaceTempFileInRoot` publication, rollback removal (`locksRoot.Remove`), and `id_allocator.lock` operations to a pinned `*os.Root` handle (`locksRoot`) opened via `storageHandle.OpenRoot(".locks")`, rejecting leaf symlinks/reparse points and verifying `GetFinalPathNameByHandle` against `EvalSymlinks(locksDirAbs)` on Windows so a `.locks` parent-directory swap can never redirect writes outside the workspace.
2. Acquire `id_allocator.lock` + in-process mutex across both `CreateArtifact`'s and `AdoptItemWithOptions`'s (`!opts.KeepID`) read-allocate-persist critical sections, persisting reserved IDs in `<storage_root>/.locks/id-sequences.json` unconditionally (including covering features and adopted tasks in `ReconstituteShipments`), with compensated `MutationStep` rollback in `CreateArtifact`, preimage rollback in `adoptItem`, and `unreserveIDSequences(ws, ours)` in `rollbackReconstitute` for both in-process failure and crash-recovery (`Phase == "intent"`) rollback.
<!-- END:chosen-direction -->
