title: MergeSync reports deleted items even when DeleteItemCascade fails
updated_at: 2026-04-21T11:24:28.5397531-07:00
---

In `internal/db/merge_sync.go` (lines 152–168), `result.Deleted` is populated from `diff.Deleted` unconditionally, regardless of whether `DeleteItemCascade` succeeded for each entry.\n\nWhen a non-ErrNotFound delete failure occurs, the function logs a warning and continues. The new manifest returned is `current`, which lacks the deleted file. Future MergeSync calls will not see the item in the diff again and will not retry the delete. The SQLite index retains a ghost entry until a full `Rehydrate` is triggered.\n\n**Fix direction:** Track which deletes succeeded; only include those in `result.Deleted`. For failed deletes, retain the original manifest entry so the next sync detects and retries them.\n\n**References:** `internal/db/merge_sync.go:152-168`, review `037.001-R`
