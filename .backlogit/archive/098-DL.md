# CAP-3 (F448AA52): Remediate pooled SQLite schema visibility under -race and harden TestReconcileResumeForgedPreparedEvent & TestUR1B timeouts

## Problem Frame

<!-- BEGIN:problem-frame -->
Deferred scope expansion `F448AA52` from `210.003-T` (`210-F`, `211-S`): under concurrent `-race` package runs, (a) `TestU2_ReconstituteShipmentsAtomicExecutionAndRollback/concurrent_associate_commit_and_post_hook_isolation` intermittently fails with `no such table: commit_links` when a second pooled SQLite connection opens while Connection #1 holds an `IMMEDIATE` transaction before WAL schema frames are checkpointed and before `busy_timeout` is applied, and (b) `TestReconcileResumeForgedPreparedEvent` and `TestUR1B_FailClosedValidationAndAuthoritativeActiveSlot` intermittently hang/time out past 12m due to repeated unseeded fixture setup and unbounded subprocess `cmd.Wait()` / tight 10s readiness polling.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Force `db.SetMaxOpenConns(1)` in production `db.Open`. Pros: avoids pooled-connection schema/pragma races. Cons: eliminates concurrent WAL reader throughput documented in `internal/db/connection.go` (F-19) and does not fix the `TestReconcileResumeForgedPreparedEvent` or `TestUR1B` timeouts.
Option B (Recommended): Fix DSN pragma ordering (`busy_timeout(30000)` first) + post-`EnsureSchema` WAL checkpoint in `internal/db`, seed `newAuthSeamFixture` via `sync.Once` in `internal/core/shipment_reconcile_auth_seam_test.go`, and bound child subprocess execution/readiness in `TestUR1B_FailClosedValidationAndAuthoritativeActiveSlot` (`internal/core/shipment_blocked_lifecycle_harness_test.go`). Pros: fixes the root cause of `no such table: commit_links` across pooled SQLite connections while keeping `MaxOpenConns(4)`, and eliminates the two 12m+ test hangs/timeouts under `-race`. Cons: touches `internal/db` and `internal/core` (split into two width-isolated tasks).
Option C: Skip the three tests under `-race`. Pros: trivial. Cons: violates P-004 and hides genuine concurrency defects.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Remediate all three `F448AA52` race/timeout root causes across `internal/db` and `internal/core`:
1. For `(a)` `TestU2_ReconstituteShipmentsAtomicExecutionAndRollback/concurrent_associate_commit_and_post_hook_isolation` failing under `-race` with `no such table: commit_links`: in `internal/db/connection.go` (`Open`), place `_pragma=busy_timeout(30000)` FIRST in the DSN pragma list before `_pragma=journal_mode(WAL)` and `_pragma=foreign_keys(1)` so newly opened pooled connections (`SetMaxOpenConns(4)`) never execute `PRAGMA journal_mode(WAL)` with `busy_timeout=0` while another connection holds an `IMMEDIATE` transaction; and in `internal/db/schema.go` (`EnsureSchema` / `EnsureSchemaWithExtensions`), run a best-effort WAL checkpoint (`PRAGMA wal_checkpoint(PASSIVE)`) after committing the schema transaction so the schema tables (`commit_links`, `items`, etc.) are materialized in the main database file immediately and visible to all pooled connections opened under concurrent `-race` load.
2. For `(b1)` `TestReconcileResumeForgedPreparedEvent` (`internal/core/shipment_reconcile_resume_auth_test.go` / `shipment_reconcile_auth_seam_test.go`): cache the base `authSeamFixture` workspace (git seed + archived shipment + member + closure file + Ed25519 keypair + request digest) via `sync.Once` (`authSeamSeed`) and clone it per subtest instead of rebuilding artifacts, shipments, and Ed25519 keys from scratch 50+ times.
3. For `(b2)` `TestUR1B_FailClosedValidationAndAuthoritativeActiveSlot` (`internal/core/shipment_blocked_lifecycle_harness_test.go`): bound the child subprocess in `claim_and_unblock_serialize_across_boundaries/processes` with `exec.CommandContext` (30s timeout + `cmd.WaitDelay`), signal `ReadyPath` after opening `NewDiagnosticWorkspace` (avoiding redundant recovery contention during child startup), and raise the readiness/start barrier deadline from 10s to 30s under `-race`.
<!-- END:chosen-direction -->
