# CAP-3 (F448AA52): Remediate pooled SQLite schema visibility under -race and harden TestReconcileResumeForgedPreparedEvent & TestUR1B timeouts

## Problem Frame

<!-- BEGIN:problem-frame -->
Deferred scope expansion `F448AA52` from `210.003-T` (`210-F`, `211-S`): under concurrent `-race` package runs, (a) `TestU2_ReconstituteShipmentsAtomicExecutionAndRollback/concurrent_associate_commit_and_post_hook_isolation` intermittently fails with `no such table: commit_links` when a second pooled SQLite connection opens against a newly created 0-byte `backlogit.db` file while Connection #1 holds an `IMMEDIATE` transaction (because `db.Open` leaves `backlogit.db` at 0 bytes on disk without a persistent Page 1 WAL header and executes `PRAGMA journal_mode(WAL)` before `PRAGMA busy_timeout(30000)`, and SQLite's `PRAGMA journal_mode(WAL)` on a locked 0-byte file returns `"delete"` with `SQLITE_OK` rather than `SQLITE_BUSY`, leaving the new connection in `delete` mode or with an empty cached `pSchema` reading the 0-byte main file instead of the WAL), and (b) `TestReconcileResumeForgedPreparedEvent` and `TestUR1B_FailClosedValidationAndAuthoritativeActiveSlot` intermittently hang/time out past 12m due to repeated unseeded fixture setup and unbounded subprocess `cmd.Wait()` / tight 10s readiness polling.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Force `db.SetMaxOpenConns(1)` in production `db.Open`. Pros: avoids pooled-connection schema/pragma races. Cons: eliminates concurrent WAL reader throughput documented in `internal/db/connection.go` (F-19) and does not fix the `TestReconcileResumeForgedPreparedEvent` or `TestUR1B` timeouts.
Option B (Recommended): Fix DSN pragma ordering (`busy_timeout(30000)` first) AND separately materialize the persistent Page 1 WAL header (`hdr[18]==2, hdr[19]==2`) and verify `journal_mode == "wal"` / schema initialization in `internal/db` (`db.Open` and `EnsureSchema`), seed `newAuthSeamFixture` via `sync.Once` in `internal/core/shipment_reconcile_auth_seam_test.go`, and bound child subprocess execution/readiness in `TestUR1B_FailClosedValidationAndAuthoritativeActiveSlot` (`internal/core/shipment_blocked_lifecycle_harness_test.go`). Pros: fixes both the `busy_timeout` pragma order and the 0-byte non-WAL pooled-connection `no such table: commit_links` defect while keeping `MaxOpenConns(4)`, and eliminates the two 12m+ test hangs/timeouts under `-race`. Cons: touches `internal/db` and `internal/core` (split into two width-isolated tasks).
Option C: Skip the three tests under `-race`. Pros: trivial. Cons: violates P-004 and hides genuine concurrency defects.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B (Selected): Remediate all three `F448AA52` race/timeout root causes across `internal/db` and `internal/core`:
1. For `(a)` `TestU2_ReconstituteShipmentsAtomicExecutionAndRollback/concurrent_associate_commit_and_post_hook_isolation` failing under `-race` with `no such table: commit_links`:
   * **Busy-timeout ordering (`internal/db/connection.go`)**: Place `_pragma=busy_timeout(30000)` FIRST in the DSN pragma list before `_pragma=journal_mode(WAL)` and `_pragma=foreign_keys(1)` so newly opened pooled connections (`SetMaxOpenConns(4)`) set their 30s busy timeout before executing `PRAGMA journal_mode(WAL)`.
   * **Database identity, persistent WAL header, and schema initialization (`internal/db/connection.go` & `internal/db/schema.go`)**: Because SQLite's `PRAGMA journal_mode(WAL)` on a brand-new 0-byte `.db` file does not write Page 1 to disk (and on a locked 0-byte file returns `"delete"` with `SQLITE_OK` rather than `SQLITE_BUSY`, leaving a newly opened pooled connection in `delete` mode reading the 0-byte main file and failing with `no such table: commit_links`), ensure `db.Open` verifies `PRAGMA journal_mode == "wal"` and materializes Page 1 (with the persistent WAL header bytes `18..19 = 2, 2` via `PRAGMA user_version` / `PRAGMA wal_checkpoint(TRUNCATE)` when `dbPath` on disk is 0 bytes) before returning `db`, and ensure `EnsureSchema` / `EnsureSchemaWithExtensions` verifies `commit_links` schema readiness across pooled connections, with a deterministic reproducer in `internal/db/connection_test.go`.
2. For `(b1)` `TestReconcileResumeForgedPreparedEvent` (`internal/core/shipment_reconcile_resume_auth_test.go` / `shipment_reconcile_auth_seam_test.go`): cache the base `authSeamFixture` workspace (git seed + archived shipment + member + closure file + Ed25519 keypair + request digest) via `sync.Once` (`authSeamSeed`) and clone it per subtest instead of rebuilding artifacts, shipments, and Ed25519 keys from scratch 50+ times.
3. For `(b2)` `TestUR1B_FailClosedValidationAndAuthoritativeActiveSlot` (`internal/core/shipment_blocked_lifecycle_harness_test.go`): bound the child subprocess in `claim_and_unblock_serialize_across_boundaries/processes` with `exec.CommandContext` (30s timeout + `cmd.WaitDelay`), signal `ReadyPath` after opening `NewDiagnosticWorkspace` (avoiding redundant recovery contention during child startup), and raise the readiness/start barrier deadline from 10s to 30s under `-race`.
<!-- END:chosen-direction -->
