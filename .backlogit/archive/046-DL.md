# Lifecycle Hygiene: Cascading Archive & Stash Cleanup

## Problem Frame

<!-- BEGIN:problem-frame -->
After every build and release cycle, artifact leftovers remain in the queue and stash because cleanup is manual and distributed across agent harness steps. When an agent crashes mid-workflow, no cleanup happens at all. The backlogit tool should own data-integrity cascades on state transitions so the workspace stays consistent regardless of harness behavior. This also includes renaming stash_remove to stash_archive to better communicate the soft-delete semantics.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Tool-owned cascades only — backlogit enforces cascading archive on shipment close, feature close, and stash entry linkage. Simple, deterministic. Option B: Harness-owned cleanup — keep current model, add more explicit cleanup steps to Ship skill. Fragile, crash-unsafe. Option C: Hybrid — tool owns cascades, harness owns workflow timing. Best of both.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option C (Hybrid): backlogit owns cascading state transitions (when a shipment archives, its manifest items cascade; when a feature archives with linked stash entries, those entries are marked archived; doctor --fix-orphans detects and resolves leftovers). The agent harness retains ownership of workflow decisions (when to trigger transitions). The stash_remove command is renamed to stash_archive with reason 'archived' and backward-compatible alias.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
Should cascade be opt-in (flag) or always-on? Should doctor --fix-orphans auto-fix or report-only by default? What is the deprecation timeline for the stash_remove alias?
<!-- END:open-questions -->
