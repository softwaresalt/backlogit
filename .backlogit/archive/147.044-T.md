Plan unit **U14b** (partition 2). Replaces the `AbandonCheckpoint` in-place rewrite site with a seam call.

Files: `internal/core/checkpoint_disposition.go`, `internal/core/checkpoint_migration_test.go` (new).

`AbandonCheckpoint` (`internal/core/checkpoint_disposition.go:105-118`) stops calling `atomicfile.WriteFileAtomic` directly and calls `events.RewriteCheckpointFile` with its existing mutation closure.

**Why this is a separate unit from `147.037-T` / U14 (cycle-37).** Cycle 17 split the seam work into declaration, contract harness, implementation, and caller migration so that no single unit carried a five-file branch. The migration unit still carried two production packages plus a new test file — three files, which is not *fewer than three* and therefore outside the 2-Hour Rule heuristic the Constitution states and this plan has already enforced against `147.021-T` and `147.014-T`. The two verb migrations touch disjoint packages and share no code, so they split cleanly: `147.037-T` migrates the resolve site in `internal/events`, this task migrates the abandon site in `internal/core`, and each unit is two files.

**This task introduces no new verb-facing sentinel and changes no ordering.** Its only claim is that the write mechanism moved. After it lands, `AbandonCheckpoint` refuses untrustworthy documents with the seam's raw verdict errors at the *write* step, which is after the audit append and after the already-abandoned short-circuit. `147.008-T` / U4's own `errors.Is` sentinel assertions and the audit-free, short-circuit-proof ordering it installs therefore still fail until U4 lands — which is what keeps U4 honestly red.

**Test-lifecycle classification**: red harness plus one green-step guard. One scaffolded `TestU14b_` function — the structural assertion that `internal/core/checkpoint_disposition.go` contains **no** direct atomic-write call whose target resolves under the checkpoint directory **and** does contain a call to `events.RewriteCheckpointFile` inside `AbandonCheckpoint` — fails before the migration. Both halves are required: removal alone would be satisfied by routing through any other helper, which is not this task's contract. The shipped-accept-path assertion is green on landing and is committed with the migration as `TestU14bGuard_AbandonAcceptPathUnchanged`, never in the harness commit.

Red verification: `go test -count=1 -run '^TestU14b_' ./internal/core`.
