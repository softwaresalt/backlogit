# Stash Archive for Durable Entry History

## Problem Frame

<!-- BEGIN:problem-frame -->
Removed and harvested stash entries vanish from stash.jsonl with no durable trace. The SQLite state column is ephemeral and rebuilt on rehydration. There is no Git-friendly historical record of what ideas entered and exited the stash.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
1. Append to .backlogit/archive/stash.jsonl on remove/harvest — lightweight, Git-friendly, consistent with JSONL conventions
2. Write per-entry archive files — excessive filesystem churn for small records
3. Rely on SQLite state column — violates CQRS principle (ephemeral cache is not durable)
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option 1: Append removed/harvested entries to .backlogit/archive/stash.jsonl. Each archived entry preserves original fields (id, priority, kind, text, created_at, deliberation_id) plus removal metadata (removed_at timestamp, removal_reason: "harvested"|"removed"|"pruned", harvested_artifact_id when applicable).
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
None — scope is well-bounded. Implementation touches RemoveStashEntry() and harvestStashEntryLocked() in internal/core/stash.go.
<!-- END:open-questions -->

## Notes

<!-- BEGIN:notes -->
Building blocks: RemoveStashEntry() at stash.go:583-610 already has the entry in hand before deletion. harvestStashEntryLocked() at stash.go:271-338 also has the entry. Both need an appendToArchive() call before rewriting stash.jsonl. The archive directory .backlogit/archive/ already exists for artifact files.
<!-- END:notes -->
