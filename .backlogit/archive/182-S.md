**DAG root (Stage, 2026-09-28).** `182-S` carries the `dag-root` label: it has
no predecessor shipment and is the flake prerequisite for `154-S` (`154-S`
depends on `182-S`, never the reverse). No `blocks` edge onto `182-S` exists or
should be invented.

**Composition (Orchestrator decision, 2026-09-28, PR #459 review cycle 1).**
`182-S` stays SINGLE-MEMBER: `[181.001-T]` only. Covering feature `181-F` is
deliberately outside the manifest. Adding `181-F` would make `182-S`
multi-member, and condition (b) forbids claiming a multi-member shipment before
the `154-S` marker exists. `154-S` depends on `182-S`, so that would deadlock.

**Governed post-ship close step for `181-F` (Ship, post-merge closure of
`182-S`; 157-S precedent).** Because `181-F` is not a manifest member, shipping
`182-S` leaves it `queued`. In Ship's post-merge closure for `182-S`:

1. Complete the normal closure. `181.001-T` must end up archived with shipped
   provenance: `status: archived` with `archived_status: shipped` (or `done`),
   read from the Markdown source.
2. Only after step 1 is confirmed, associate the `182-S` merge SHA with
   `181-F` BEFORE archiving it: `backlogit update 181-F --commit <merge-sha>`
   (MCP: `backlogit_track_commit`). Both route through
   `core.AssociateCommit`, which writes the frontmatter `commit` field, a
   `commit_links` row and a `commit_tracked` event.
3. Then move `181-F` to done and archive it:
   `backlogit move 181-F --status done`, then `backlogit archive 181-F`.
4. Optional narrative:
   `backlogit comment add 181-F --actor ship --comment "..."`. This writes
   only a `comment` event. It does NOT associate the commit, so it cannot
   replace step 2.

If `181.001-T` has not reached shipped provenance, do NOT close `181-F`. Leave
it `queued` and report the gap.

**Consumer guard.** `154-S` and the `173-F` tasks that hold `blocks` edges onto
