# Single backlogit MCP daemon per workspace via CLI-only OS advisory lock and lifecycle commands

## Problem Frame

<!-- BEGIN:problem-frame -->
Multiple concurrent 'backlogit mcp' stdio server processes in the same workspace contend on .backlogit/backlogit.db (or .backlog/backlogit.db), maintain divergent in-memory manifest snapshots across backlogit_merge_sync, and leave orphaned background processes with no CLI inspection or stop mechanism.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: CLI-Only OS-Lock Single-Instance Guard + Lifecycle CLI (backlogit mcp --replace, backlogit mcp status, backlogit mcp stop) [Chosen]; Option B: Detached Background Daemon with Named Pipe / Unix Domain Socket + Stdio Proxy [Rejected - high IPC/lifecycle complexity]; Option C: External Wrapper Script Only [Rejected - bypassed by direct MCP host launches].
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Adopt Option A (CLI-Only OS-Lock Single-Instance Workspace Guard + Lifecycle CLI): enforce one backlogit mcp daemon per workspace via an exclusive OS advisory lock (<storage_root>/runtime/mcp-daemon.lock) and JSON metadata sidecar (<storage_root>/runtime/mcp-daemon.json), fail fast with ErrDaemonAlreadyRunning on duplicate startup, and add 'backlogit mcp status', 'backlogit mcp stop', and 'backlogit mcp --replace' CLI controls. Promoted to plan docs/exec-plans/2026-10-29-single-daemon-per-workspace-plan.md.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
None for single-instance CLI enforcement; multi-client IPC multiplexing remains out of scope unless needed by a future feature.
<!-- END:open-questions -->
