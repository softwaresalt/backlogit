Unit 2 of the plan (persisted-config legacy-map upgrade). CONFIRMED GAP: internal/config/loader.go:120-151 LoadHooks unmarshals hooks.yaml and normalizes ONLY the PreTaskCompletionGate block; it does NOT merge newly-added default transition entries. WriteDefaults persists hooks.yaml with a full lifecycle.transitions: map, and internal/core/workspace.go:114-118 wires THAT persisted map. So the Task 124.002-T defaults.go edit reaches ONLY newly-initialized workspaces; existing consumer workspaces keep their persisted map and keep rejecting blocked->queued / active->queued until it is upgraded on load.

DESIGN CONSTRAINT (do NOT blind-inject): the persisted lifecycle.transitions map is an operator-customizable contract. A blind "always inject queued on load" would SILENTLY OVERRIDE an operator who intentionally excluded queued (a restrictive custom policy). The load-time upgrade MUST discriminate legacy-generated vs operator-customized. Depends on 124.002-T (mandatory default entries must be defined first). Execution posture: test-first (TDD red->green).

APPROACH:
1. (red) Add an internal/config loader test whose OLD hooks.yaml carries the KNOWN PRIOR generated-default lifecycle.transitions map verbatim (queued:{active,blocked}, active:{done,blocked,review,shipped,abandoned}, blocked:{active}, review:{done,accepted,rejected}, done:{archived} -- i.e. NO queued on blocked/active). Call LoadHooks; assert the returned transitions now include blocked->queued and active->queued. Confirm RED against current LoadHooks.
2. (green) In internal/config/loader.go LoadHooks, after unmarshal/validate, compare the persisted Lifecycle.Transitions map against the KNOWN PRIOR generated default captured as a frozen constant. If it deep-equals the prior generated default -> it is a legacy generated map -> upgrade to the new default (add blocked->queued, active->queued). If it differs in ANY way -> treat as operator-customized and leave it UNTOUCHED (never inject queued; optionally emit slog.Warn / doctor note, but never mutate). Implement as a small upgradeLegacyTransitions helper invoked from LoadHooks, mirroring the PreTaskCompletionGate.Normalize() precedent (082-F). When transitions is entirely absent, the existing empty-map fallback to DefaultTransitions() already yields the correct set -- assert this too.
3. (preservation test) Add a test whose persisted map intentionally omits queued AND differs from the prior default (e.g. operator-restricted active:[done]); assert LoadHooks leaves it UNCHANGED (no queued injected, no targets added/dropped).
4. Run targeted suite + quality gates.

ACCEPTANCE CRITERIA:
- Legacy-vs-custom discrimination: LoadHooks upgrades the persisted map ONLY when it deep-equals the KNOWN PRIOR generated default; any map that differs in any way is treated as operator-customized and left byte-for-byte unchanged.
- (a) A legacy generated-default hooks.yaml (== prior default, no queued) is upgraded so blocked->queued and active->queued are honored after LoadHooks (red before, green after).
- (b) An operator-customized restrictive map that intentionally omits queued is PRESERVED, not mutated (no queued injected).
- A config with an absent transitions block still resolves to the correct default set via the existing fallback.
- The upgrade never rejects a valid config and never removes operator-customized targets.
- go test ./internal/config/..., go vet ./..., golangci-lint run, gofmt -l . all pass.

OUT OF SCOPE: the transition-map definition edits themselves (Task 124.002-T); comment/doc alignment (Task 124.003-T); any schema/config-file format change beyond the in-memory load-time upgrade.
