# Execution Plan — Governed archived-shipment reconciliation to shipped (#423)

**Covering feature:** Governed archived-shipment reconciliation to shipped
**Stash member:** 055D507E (critical)
**Source deliberation:** `docs/decisions/2026-09-05-423-archived-shipment-reconciliation-to-shipped.md`
**Issue:** softwaresalt/backlogit#423

## Problem Frame

Repair a legacy shipment archived directly from `active` (so `status: archived`,
`archived_status: active`, no `shipment_status_changed -> shipped` event) to a
governed `shipped` archived state, WITHOUT fabricating a normal shipping event.
Reuse the #394 `ReconcileArchivedLifecycle` governed conventions; keep the general
`reconcile` allowlist unchanged; append a DISTINCT `shipment_reconciled_shipped`
event; verify (never infer) evidence; fail closed; idempotent; dry-run.

## Constitution Check

Go-only; test-first (TDD per unit); workspace-isolated (all paths handle-bound under the
workspace/archive root); destructive-approval respected (explicit-confirmation-gated + audited CLI, dry-run
default-safe, fail-closed); structured observability (distinct durable audit event);
single-responsibility (reuses #394 conventions, adds a shipment-scoped surface, does not
widen the general allowlist); no new external dependency. The sole review residual
(cryptographic authenticity) is an out-of-scope, documented, deferred follow-up, not a
constitutional violation.

Constitution Check: pass

## Implementation Units

> **Design correction (adversarial review cycle 1, consensus P0):** the operation MUST NOT reuse `UnarchiveItem → set status shipped → ArchiveItem`. `ArchiveItem` runs `archiveShippedEventPreflight` (144-F guard 2, `archive.go`), which refuses to archive a shipment at status `shipped` unless `shippedEventPresence` (which counts ONLY `shipment_status_changed`) finds a normal shipped event — the exact event #423 is forbidden to synthesize — and the round-trip opens a non-atomic live-queue window. The primitive therefore performs an **IN-PLACE ATOMIC frontmatter edit of the archive file** (`.backlogit/archive/<id>.md`), keeping `status: archived` and setting `archived_status: shipped`, never entering the live queue and never invoking the `ArchiveItem` preflight.

Mechanics:
  - **Locking + ordering (GLOBAL sorted batch — no lock-order inversion):** the repository's global artifact-lock discipline is `lockArtifactMutations`, which sorts the COMPLETE id set and acquires in sorted order (`internal/core/shipment.go:447-471`); `ReconcileArchivedLifecycle` locks its whole shipment+member batch that way (`archive_reconcile.go:117`). A SEQUENTIAL "shipment-lock-first-then-members" order would INVERT against a concurrent `lockArtifactMutations({shipment}∪members)` batch whenever a member id sorts before the shipment id → deadlock. Therefore this op does NOT lock the shipment then members separately. Sequence: (1) read the shipment manifest (unlocked) to compute the member id set via `NormalizeShipmentItems`; (2) run the SLOW bounded evidence I/O (git merge-commit + reachability under `boundedHelperTimeout`, closure handle open+read+hash) with NO artifact locks held; (3) acquire the SINGLE globally-sorted `lockArtifactMutations({shipment}∪members)` batch (one sorted set — identical ordering to every other caller, so no inversion); (4) UNDER that batch, RE-READ + validate identity/location (artifact_type/status/archive-containment), re-read the manifest, and re-check every member terminal from Markdown, with NO slow I/O between the re-check and the write; (5) write; (6) the durable appender's NEW HANDLE-RELATIVE item-log lock (NOT `LockItemLogCrossProcess`) is acquired last, nested inside the batch, for the event append. The item-log lock is a DISTINCT lock namespace (per-item log sidecar), not an artifact-mutation lock, so it does not participate in the sorted-batch ordering. No separate non-reentrant "membership lock" is taken.
  - **Post-lock re-validation (TOCTOU):** the SLOW evidence I/O runs BEFORE the sorted lock batch (so no locks are held across slow bounded I/O, avoiding `ErrTaskBusy`/`ErrGateInProgress` contention). After acquiring the single sorted `lockArtifactMutations` batch, RE-READ the shipment + members from Markdown and RE-CHECK identity/location + every member terminal with NO slow I/O between that re-check and the write; re-run the idempotency/conflict classification under the held locks (mirroring `ShipShipment` re-gating). Members are READ for terminality only, under their locks, and are NEVER mutated.
