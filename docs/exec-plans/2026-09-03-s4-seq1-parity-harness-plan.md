# S4 Execution Plan — Cross-Surface Golden Parity Harness (Seq 1/7)

**Covering feature**: Cross-surface golden parity harness
**Stash member**: 5A4DBE3C (critical)
**Tier**: feature (shipment sequence S4) — program foundation

## Problem Frame

Transport and contract divergence between CLI, MCP, and internal/event APIs
recurs (typed errors collapsing to exit 1, domainError mapping drift, retryability
disagreement, arrays lost through omitempty) and is caught late. Build a
generated, table-driven harness that runs one governed scenario through all three
surfaces and compares response shape, error category, exit code, retryability,
remediation guidance, serialization guarantees, and durable side effects.

## Implementation Units

### U1 — Parallel-safe three-surface scenario driver
* Scope: define the governed-scenario table schema and a driver that executes one scenario through the CLI, MCP, and internal/event surfaces against a per-scenario ISOLATED temp workspace, using PARALLEL-SAFE injected runners — NO process-global mutation:
  - CLI: construct a FRESH root command per scenario and use `cmd.SetArgs([...])` + `cmd.SetOut`/`SetErr(buf)` (the existing test seam); capture the returned `error` and derive the CLI exit code via `internal/cli.ExitCodeFor(err)` (the SAME mapping `cmd/backlogit/main.go` uses via `os.Exit(cli.ExitCodeFor(err))`) — do NOT read or mutate `os.Args`/`os.Stdout`. A subprocess runner is an optional alternative only when real-process fidelity beyond `ExitCodeFor` is required.
  - MCP: `internal/mcp.Server.InvokeTool(ctx, name, request)` in-process.
  - internal/event: the corresponding `internal/core` / `internal/events` call in-process.
  Every surface call takes a `context.Context`, but the cancellation contract is NARROWED to the parity DRIVER's own goroutines and teardown: the harness does NOT claim to cancel in-flight PRODUCTION command work, because the gated CLI paths call `context.Background()` directly (`internal/cli/move.go:55`, `internal/cli/update.go:92`) so a cancelled cmd-context cannot stop them — threading `cmd.Context()` through those production commands is a SEPARATE production-migration task explicitly OUT of this harness-only scope. Each scenario gives EACH surface its OWN root CLONED from the same seed fixture — a MUTATING scenario CANNOT share one physical workspace (sequential calls would observe the prior surface's mutation; concurrent calls would contend on the same Markdown/SQLite/event state, so a difference would reflect execution order/locks, not surface parity): CLI runs with `--cwd <cliRoot>`, MCP with `internal/mcp.NewServerForRoot(mcpRoot)`, internal with `core.NewWorkspace(internalRoot)` — the three roots are INDEPENDENT clones of the identical seed, and the comparator (U2) compares their POST-states through a DETERMINISTIC SEMANTIC PROJECTION that NORMALIZES volatile wall-clock fields — `created_at`, `updated_at`, and event timestamps — WITHOUT simply deleting them (grounded: artifacts stamp `models.NowUTC()` in `internal/models/frontmatter.go:12-17` and event writers fill `time.Now()` in `internal/events/stream.go:243-249`, so raw bytes differ even when behavior is identical). Stripping the fields outright would HIDE a real persistence drift such as a surface that FAILS to bump `updated_at` (that bump is enforced elsewhere, e.g. `internal/cli/update_sync_test.go:69-70`); instead the projection PRESERVES presence, validity, and MUTATION SEMANTICS — it asserts each timestamp field is PRESENT, is a VALID parseable timestamp, and that `updated_at` was BUMPED relative to the seed (and `updated_at >= created_at`) — comparing those NORMALIZED relational facts across surfaces rather than the literal wall-clock value, applied IDENTICALLY to all three. Process-global bans (grounded in `internal/cli`): the driver MUST NOT pass `--log-level` (its `PersistentPreRunE` calls `applyLogLevel` → `slog.SetDefault`, a global logger swap) and MUST NOT configure via environment (`BACKLOGIT_LOG_LEVEL`/`BACKLOGIT_LOG_FORMAT`; `t.Setenv` panics under `t.Parallel()`) — ALL config flows through `SetArgs`; NO `os.Args`/`os.Stdout`/`os.Chdir`/`os.Setenv` and NO `slog.SetDefault`. Set `--no-update-check` (and inject `Server.LatestVersionLookup`) to stay hermetic. Teardown ordering: cancel the context and JOIN only the goroutines the parity DRIVER launched (the `Event`/`Telemetry`/`HookEvent` writers are synchronous mutex-protected and expose no goroutines/`Close`), then call `Workspace.Close` on EACH per-surface workspace (including the MCP server's lazily-initialized workspace) — `Workspace.Close` drains webhook dispatches and closes SQLite — before the temp-dirs are removed (register `Workspace.Close` AFTER temp-dir removal so LIFO closes handles first — Windows handle + goroutine-leak safety).
* Acceptance: a single seed scenario runs through all three surfaces (each on its own cloned root) in a parallel-safe way and captures response shape, error category, exit code (via `ExitCodeFor`), retryability, remediation guidance, serialization, and durable post-state; a `go test -race` run over the parallel scenarios is clean with NO `os.Args`/`os.Stdout`/`os.Chdir`/`os.Setenv` use and NO `slog.SetDefault` mutation; `Workspace.Close` (drains webhooks + SQLite) runs before temp-dir removal.
* Files: `internal/faultline/parity` harness (+ driver + tests). Single responsibility (parallel-safe driver).

### U2 — Dimension-aware cross-surface comparator + divergence report
* Scope: compare the three captures DIMENSION-BY-DIMENSION using APPLICABILITY / STATUS markers, NOT literal cross-surface equality. Each dimension carries a per-surface applicability marker (`applicable` / `not_applicable`) and a status; the comparator compares a dimension across surfaces ONLY where it is applicable on each:
  - exit code → CLI-only CAPTURE, but SEMANTICALLY cross-checked via COARSE EQUIVALENCE CLASSES, NOT exact 1:1 category parity: the CLI exposes NO machine error_type — `gateExitError` COLLAPSES setup/config → exit 7, timeout/in_progress → exit 8, ALL block-family outcomes → exit 6, governance → exit 9 — so a CLI exit code names a BUCKET, not a distinct MCP category, and claiming exact category parity would compare scenario-knowledge to MCP rather than what the CLI emitted. The comparator asserts the MCP machine category falls WITHIN the CLI exit-code bucket's equivalence class (exit 8 ⇒ retryable=true ⇒ MCP retryable=true AND MCP category ∈ the retryable/timeout/in_progress class; exit 6 ⇒ MCP category ∈ the block-family class; exit 7 ⇒ ∈ {config, setup}; exit 9 ⇒ governance). The ABSENCE of a stable CLI machine `error_type` is itself a tracked divergence recorded in the `166-F` expected-divergence set (or a future CLI `error_type` field closes it);
  - RAW `mcplib` tool-result envelope / `IsError` wrapper → MCP-only. But STRUCTURED error data is applicable to BOTH CLI `--json` (the `gateJSONPayload`: error, retryable, remediation, `retry_after_ms`, repeated_failure, old/new_status, gate_report_hash) AND MCP — field-level parity asserted across the two via an EXPLICIT FIELD MAPPING (the two surfaces name fields DIFFERENTLY: CLI stores the HUMAN message in `error` — `internal/cli/gate_exit.go:147-153` — while MCP stores the machine CATEGORY in `error` and the human text in `message` — `internal/mcp/gate_errors.go:85-90`). So the comparator normalizes CLI `error` (human) ↔ MCP `message`, and compares the CLI-DERIVED category ↔ MCP `error` (machine category) — NOT CLI `error` ↔ MCP `error` literally, which would produce a false untracked divergence on every gate-error scenario. A concrete KNOWN drift (owned by `166-F`): MCP gate errors carry `remediation` + `retry_after_ms` the CLI `--json` gate-error payload omits;
  - durable side effects / post-state (Markdown + SQLite + event stream) → applicable to ALL MUTATING surfaces: capture each surface's ISOLATED post-state (on its own cloned root) and compare them THROUGH THE DETERMINISTIC PROJECTION (volatile `created_at`/`updated_at`/event-timestamps NORMALIZED preserving presence + validity + mutation-semantics per U1 — NOT stripped, so a surface that FAILS to bump `updated_at` is still caught), so a CLI or MCP path that returns the right response but fails to persist the expected Markdown/DB/event change is detected while timestamp noise does NOT false-diverge (durable side effects are a cross-surface contract per the Problem Frame, NOT internal-only); `not_applicable` only for genuinely non-persisting (read-only) scenarios;
  - response shape → applicable to all three, but the success-path shape differs BY DESIGN (CLI flat `gateJSONPayload` vs MCP nested `gate` envelope) → compared via a documented field-mapping/normalization, not literal equality;
  - error category / retryability → applicable to all three; `retry_after_ms` quantitative backoff hint applicable to all three. Retryability extraction per surface with explicit `absent == false` normalization (CLI `retryable,omitempty` omits the key on non-retryable; MCP always emits `false`) — semantic parity asserted here while the omitempty-vs-always serialization drift is caught by the SEPARATE serialization dimension, not masked;
  - remediation → applicable to CLI `--json` and MCP ONLY, `not_applicable` for internal: `internal/errors.GateError` carries class/retry metadata but NO remediation string (`internal/errors/gate_errors.go:137-144`); the human-readable `remediation` is SYNTHESIZED at the CLI/MCP boundaries, so marking it applicable-to-internal would force a false divergence or invented internal output. Compare `remediation` field-level parity across CLI `--json` ↔ MCP; keep category/retryability/`retry_after_ms` cross-checked against internal;
  - serialization → applicable to all three (omitempty vs always-emit, null-vs-empty-array): captured explicitly so a serialization drift is reported here rather than masked by the semantic dimensions;
  - force-lever / destructive-approval capability → applicable to all three: any bypass/force affordance MUST be symmetrically present-or-absent and identically gated across surfaces (a surface-specific escape hatch is a divergence).
  Explicit comparison semantics: a mismatch on an APPLICABLE dimension fails closed; a `not_applicable` dimension is recorded but NEVER compared as a false divergence (so a CLI-only exit code is not a false MCP/internal mismatch). The field-level parity is the DIMENSION the harness asserts; a field that currently DIVERGES across surfaces (e.g. CLI `--json` omitting `remediation`/`retry_after_ms`) is NOT left as a failing (red) test — it is captured as an EXPECTED-DIVERGENCE scenario that asserts the divergence exists AND names the concrete tracked defect (the STANDALONE tracked-defect feature `166-F`, the durable owner deliberately OUTSIDE the 138-S/156-F hierarchy so it is never swept into the shipment — NOT a free-form string), so the assertion is GREEN (report-only) while the drift stays visible. To prevent an UNRELATED future mismatch from silently riding the same exemption, the fixture DECLARES the EXACT `(dimension, field-path)` SET owned by `166-F`, and the assertion requires EXACT SET EQUALITY of the observed divergent fields to that declared set — a MISSING expected field OR an ADDITIONAL unrelated divergent field FAILS closed. A NEW, un-expected divergence therefore still fails closed. This keeps the seed corpus green at closure without requiring a production remediation of the CLI payload (which is OUT of this harness-only scope) and without silencing genuine new drift. Emit a deterministic divergence report AND an `EvidenceArtifact` envelope with `NodeFamily = NodeFamilyParity` carrying a `ParityEvidence` payload, conforming to the U4a contract.
* Acceptance: identical behavior passes; an injected divergence in each APPLICABLE dimension is detected and reported; a gate scenario asserts field-level parity of STRUCTURED error data (remediation, `retry_after_ms`, repeated_failure, old/new_status) across CLI `--json` and MCP; exit 8 ⇔ retryable ⇔ MCP retryable and exit 6/7/9 ⇔ the matching MCP category; a force/bypass affordance present on one surface but not the other is flagged; the success-path flat-vs-nested shape difference does NOT false-diverge while genuine field drift is still caught; a CLI-only exit-code difference does NOT produce a false cross-surface divergence for MCP/internal; durable POST-STATE (Markdown/DB/events) is captured and compared THROUGH THE DETERMINISTIC PROJECTION (volatile created_at/updated_at/event-timestamps normalized) for EVERY mutating surface (a surface that returns correctly but under-persists is flagged; timestamp noise does not false-diverge); the emitted evidence artifact validates against the U4a contract. Depends on U1 and U4a-BEHAVIOR (`156.006-T`) — U2 both emits and VALIDATES the artifact, so it needs the `Canonical`/`Validate`/`DecodeAndValidate` behavior, not merely the declarations.
* Files: harness comparator (+ tests). Single responsibility (dimension-aware comparator).

### U4a — Standalone versioned fault-line evidence-artifact contract (program foundation)
* Owner / dependency direction (grounded): a NEW STANDALONE foundation package `internal/faultline` (the program namespace; e.g. `internal/faultline/evidence.go`) owns the versioned `EvidenceArtifact` schema. It is NOT owned by the S4 parity harness (a test-infra consumer) and NOT by any single detector. It is a LEAF whose ONLY intentional internal dependencies are `internal/canonical` (the shared canonical serializer, below) and — if strictly needed — `internal/errors`; it imports no detector/harness/`core`/`events` package. ALL of S4 (the harness emits against it), S5-S9 (producers), and S10/S11 (consumers) import IT — dependency flows foundation ← producers/consumers, never the reverse. It is DISTINCT from `internal/gateevidence` (shipment-gate evidence, coupled to `internal/events`/`internal/core`); the fault-line contract MUST NOT be coupled to shipment-gate internals.
* Scope: `EvidenceArtifact` is the SHARED, FAMILY-AGNOSTIC ENVELOPE consumed by ALL of S4-S11 — `EvidenceArtifact{ SchemaVersion int `json:"schema_version"`; ProducingTask string `json:"producing_task"`; ProducingCommit string `json:"producing_commit"`; NodeFamily string `json:"node_family"`; Applicability []string `json:"applicability"`; ValidatorIdentity string `json:"validator_identity"`; VerifiedEvidence json.RawMessage `json:"verified_evidence"`; Status string `json:"status"` }` (ALL OUTER JSON tags snake_case and explicit). The `VerifiedEvidence` payload is a DISCRIMINATED, node-family-specific typed document — NOT one parity-shaped struct forced on every producer (S5 records representation convergence, S9 records separate observed red/green results; forcing those into parity fields or the `Detail` string would defeat the versioned schema). A `FamilyPayload` interface (`CanonicalMap() map[string]any` + `Validate(view EvidenceView) error`, where `EvidenceView` is a FOUNDATION-OWNED READ-ONLY view of the envelope's cross-cutting fields — `Status`, `Applicability`, `SchemaVersion`, `NodeFamily` — so a family can enforce its OWN cross-envelope invariants WITHOUT the foundation importing the producer package and WITHOUT reversing dependency direction) plus a VERSION-AWARE family REGISTRY keyed by the COMPOSITE `(SchemaVersion, NodeFamily)` — `map[int]map[string]func() FamilyPayload` — decodes `VerifiedEvidence` into the CONCRETE family struct for THAT schema version. Version-awareness is required so decode/`Validate` select the allowed family SET and the concrete payload SHAPE from the artifact's own `SchemaVersion`. VERSION UNIQUELY IDENTIFIES THE FAMILY SET (round-7 fix): each `EvidenceSchemaVersion` defines a COMPLETE, CLOSED family set; ADDING OR REMOVING a family REQUIRES incrementing `EvidenceSchemaVersion` (a new golden per version; old versions immutable), so `schema_version: 1` means EXACTLY `{parity}` for every consumer forever and two consumers can never interpret the same version's family set differently. A later producer targets a NEW version whose closed set is the superset (e.g. v2 = `{parity, representation}`); it does NOT mutate v1's set. The closed set is a FOUNDATION-OWNED per-version MANIFEST (a static `map[int][]string` declared IN `internal/faultline`, binary-INDEPENDENT — NOT derived from whichever producer packages happen to link/init): `knownFamilies(version)` returns the MANIFEST set. `freeze()` validates that the REGISTERED factories match the manifest EXACTLY for each version — a MISSING factory (a producer package not linked) OR an EXTRA/unmanifested registration FAILS freeze closed — so two binaries can never freeze different allowed sets for the same schema version (at v1 the sole `parity` family is foundation-owned, so v1 always freezes complete). To keep this binary-independent for LATER versions too, each family's PAYLOAD TYPE and its `RegisterFamily` call live in the SHARED foundation package `internal/faultline` (or an always-linked `internal/faultline/families` sub-package), NOT in a producer's separately-linked detector package — so ANY binary that imports the foundation links the COMPLETE manifest-matching set and `freeze()` never fails a consumer that imported only the foundation. A producer shipment CONTRIBUTES its distinct family type to this shared package and bumps the version (producers still OWN the SHAPE of their evidence — the type merely PHYSICALLY resides in the foundation so every consumer links it); a producer does NOT register from a package consumers might not import. This closes the "import every producer package for its registration side effect" gap. REGISTRY LIFECYCLE (Security Lens SEC-02 + round-7 freeze completeness): the registry is IMMUTABLE during ALL reads — `RegisterFamily(version int, name string, factory func() FamilyPayload) error` is INIT-ONLY and RETURNS AN ERROR on a duplicate `(version, name)` composite key, a nil factory, or any post-freeze call (NEVER last-writer-wins, never a silent panic-only path). `freeze()` snapshots an immutable copy, and the freeze is TRIGGERED by the FIRST of `DecodeAndValidate`, `Canonical`, `Validate`, OR `knownFamilies`; EVERY registry reader — `DecodeAndValidate`, `Canonical`, `Validate`, AND `knownFamilies` — reads ONLY the frozen snapshot, so no reader can race a concurrent `RegisterFamily`. Conformance covers duplicate registration, nil factory, and a post-freeze registration attempt (each returning the error) plus a concurrent register-vs-read race under `-race`. At VERSION 1 the ONLY registered family is `parity` (S4): `ParityEvidence{ ScenarioID string `json:"scenario_id"`; Dimension string `json:"dimension"`; Surfaces []string `json:"surfaces"`; DivergentFields []string `json:"divergent_fields"`; ExpectedDivergence bool `json:"expected_divergence"`; TrackedDefect string `json:"tracked_defect"`; Detail string `json:"detail"` }` (snake_case tags; `Surfaces`/`DivergentFields` non-nil empty slices per the always-array contract; `TrackedDefect` empty-string-valid only when `ExpectedDivergence` is false). Later producers REGISTER their OWN typed family payload (S5 `RepresentationEvidence`, S9 `RedGreenEvidence`, …) each with its OWN per-family golden — they do NOT overload the parity payload or hide data in `Detail`. Because BOTH the envelope AND the registered family payload participate in the golden fixture and `Canonical()` ordering, an envelope OR payload-shape change IS a schema change; with:
  - EXACT API signatures (so producers cannot diverge): `func (a EvidenceArtifact) Canonical() ([]byte, error)` (value receiver — canonicalizes the envelope AND the family payload decoded FROM `a.VerifiedEvidence`), `func DecodeAndValidate(data []byte) (EvidenceArtifact, FamilyPayload, error)` (the envelope AND the concrete family payload are BOTH decoded from the SAME `data`, so the returned payload is authoritative and cannot mismatch the raw bytes), `func Validate(a EvidenceArtifact) error` (takes ONLY the artifact and DERIVES the family payload from `a.VerifiedEvidence` via the frozen registry — round-7 fix: NO separately-supplied payload argument, so a caller can NOT validate a good payload alongside different malformed `verified_evidence` bytes and then emit those bytes), `func RegisterFamily(version int, name string, factory func() FamilyPayload) error` (returns an error on duplicate `(version,name)`/nil-factory/post-freeze), and `func knownFamilies(version int) []string` (reads the frozen snapshot);
  - TYPED ERROR CATEGORIES (so `Classify` can deterministically distinguish outcomes 3 vs 4): `DecodeAndValidate` returns typed sentinel errors — `ErrMalformed` (wire/shape: duplicate key, case-variant alias, `DisallowUnknownFields` reject, trailing data), `ErrUnknownVersion`, `ErrUnknownFamily`, and `ErrValidation` (a known-version/known-family artifact that fails an envelope/family invariant). `Classify` maps `ErrValidation` → `OutcomeValidationFailed` and `ErrMalformed`/`ErrUnknownVersion`/`ErrUnknownFamily` → `OutcomeUnknownOrMalformed` via `errors.Is`, so wire/shape failures are never conflated with invariant failures;
  - NODE-FAMILY ALLOWED SET (enumerated, per-version, CLOSED): the allowed `NodeFamily` values for a given artifact are exactly `knownFamilies(a.SchemaVersion)` — a COMPLETE, CLOSED set per version. At version 1 that set is exactly `{ NodeFamilyParity = "parity" }` (S4), permanently. Adding a family is a VERSION BUMP (never an in-place addition to an existing version's set): a later producer registers its constant (e.g. `NodeFamilyRepresentation`, `NodeFamilyRedGreen`) FOR A NEW schema version whose closed set is the superset, WITH its typed payload and golden. `Validate` rejects a `NodeFamily` not in `knownFamilies(a.SchemaVersion)`, so `schema_version: 1` can never be reinterpreted with a different family set;
  - VALIDATION INVARIANTS — enforced by `Validate(a)` (which DERIVES the family payload from `a.VerifiedEvidence`, so there is no separate-payload mismatch vector) plus the family's own ENVELOPE-AWARE `p.Validate(view)`:
    * ENVELOPE-level (in `Validate(a)`): `SchemaVersion` ∈ `knownVersions`; `ProducingTask`, `ProducingCommit`, `ValidatorIdentity` non-empty; `NodeFamily` ∈ `knownFamilies(SchemaVersion)`; `Applicability` non-empty with each ∈ `{cli, mcp, internal}`; `Status` ∈ `{pass, report_only, fail}`.
    * FAMILY-level, ENVELOPE-AWARE (in `p.Validate(view EvidenceView)` — the view carries `Status`/`Applicability`/`SchemaVersion`/`NodeFamily`, so EVERY family, INCLUDING future producer-owned families like S5/S9, enforces its OWN cross-envelope invariants WITHOUT the foundation importing the producer package and WITHOUT reversing dependency direction): for `ParityEvidence` at v1: intra-payload (`ScenarioID`/`Dimension` non-empty; `Surfaces` non-empty each ∈ `{cli, mcp, internal}`; `TrackedDefect`, when non-empty, MUST match the CANONICAL backlog-ID format — regex `^\d{3,}(\.\d{3,})*-[A-Z]{1,2}$` (segments are `\d{3,}`, a MINIMUM width — `%03d` pads short values but the parser accepts longer numeric segments like `1000-F`, per `internal/core/naming.go:29-34` / `internal/core/hierarchy.go:157-183` — NOT a fixed 3 digits; prefer the shared canonical ID validator if exposed) — so a FREE-FORM string is rejected, closing the allowlist gap `166-F` was created to fill) PLUS the CROSS-FIELD STATE MATRIX against `view.Status`: (a) `ExpectedDivergence == true` ⇒ `Status == report_only` (a KNOWN tracked drift is report-only, never `pass`/`fail`); (b) `Status == pass` ⇒ `DivergentFields` empty AND `ExpectedDivergence == false`; (c) `Status == report_only` ⇒ `ExpectedDivergence == true` AND `TrackedDefect` non-empty AND `DivergentFields` non-empty; (d) `Status == fail` ⇒ `DivergentFields` non-empty AND `ExpectedDivergence == false`.
    `Validate(a)` runs the envelope checks, DECODES `p` from `a.VerifiedEvidence` via the frozen registry, then calls `p.Validate(view)` (returning `ErrValidation` on any failure); the state matrix is directly conformance-tested, so no contradictory artifact (e.g. `ExpectedDivergence` with `Status: pass`, or `pass` with divergent fields) can validate;
  - `schema_version` = exported const `EvidenceSchemaVersion = 1`, plus a `knownVersions` set;
  - CANONICAL deterministic serialization — a `Canonical() ([]byte, error)` implemented as a THIN WRAPPER over the existing stdlib-only leaf `internal/canonical.Canonicalize` (do NOT invent a second serializer — `internal/canonical` is ALREADY the evidence-authenticity serializer used by `gateproof`/`core.gate_evidence`; a parallel one would drift from S10 authenticity hashing). Provide a `canonicalMap()` step (mirroring `gateproof.canonicalMap()`) that converts the `EvidenceArtifact` envelope to a `map[string]any` and MERGES the registered family payload's own `CanonicalMap()` under `verified_evidence`, with integers-only numbers (no float/timestamp; integer-exact per `gateevidence.asInt`) and non-nil collections BEFORE calling `Canonicalize`; AND — because `internal/canonical.Canonicalize` preserves ARRAY ORDER while `Applicability`, `Surfaces`, and `DivergentFields` are SET-LIKE — `canonicalMap()` normalizes those set-like fields to SORTED + DUPLICATE-FREE order before canonicalization, so semantically identical evidence yields an IDENTICAL digest (this is essential because the anti-replay identity is the canonical digest: without set-normalization, merely reordering `Surfaces` would produce a different digest and BYPASS dedup). `Validate` additionally rejects duplicate elements in those set-like fields. So the wrapper is byte-stable AND order-independent for set fields;
  - BOUNDED DECODE (DoS resistance, Security Lens SEC-01) — `DecodeAndValidate` enforces resource budgets BEFORE the version peek and token-stream scan: `MaxArtifactBytes` (reject oversized input up front), `MaxJSONDepth` (reject deep nesting), and bounded object-member-count, array-element-count, and string-length budgets; exceeding ANY budget fails closed with a typed `ErrMalformed` (resource-limit) error rather than being traversed. Conformance covers oversized, deeply nested, and high-member-count inputs;
  - UNKNOWN-VERSION rejection AND MALFORMED-WIRE rejection on decode — a two-phase decode peeks `schema_version` before full unmarshal; a version outside `knownVersions` returns a TYPED error; decode uses `DisallowUnknownFields` so an unstamped additive drift is REJECTED. Because `encoding/json` alone still applies LAST-VALUE-WINS on duplicate members and CASE-INSENSITIVE field matching (so `DisallowUnknownFields` does NOT catch a duplicated key or a case-folded alias like `Schema_Version`/`SCHEMA_VERSION`), `DecodeAndValidate` runs a RAW `json.Decoder` TOKEN-STREAM pre-scan that (a) rejects any DUPLICATE object member (case-sensitively equal OR case-fold-equal — family-agnostic, over BOTH the envelope AND the nested `verified_evidence` object) and (b) validates EXACT-CASING of the ENVELOPE's declared tags. The nested `verified_evidence` keys are FAMILY/VERSION-SPECIFIC, so their exact casing CANNOT be validated at this stage (the family is not yet known); the pre-scan only COLLECTS the nested key data, then AFTER `schema_version`/`node_family` are peeked and the concrete family payload type is selected from the frozen registry, the nested keys' exact casing is validated against THAT family's declared tags before the strict family unmarshal. Conformance cases cover duplicate `schema_version`, a case-variant envelope alias, a duplicate nested payload key, and a case-variant NESTED (family) key;
  - NON-NIL collections — slices/maps normalized to non-nil empty on marshal (always-array/object, per compound `2026-07-21-omitempty-defeats-arrays-always-json-contract.md`);
  - a documented COMPATIBILITY / SKEW policy — ANY field add/remove/rename increments `EvidenceSchemaVersion`; producers stamp the current version; forward-incompatible artifacts are rejected, not guessed; a NEW golden fixture is added per version (old goldens are never mutated). At N=1 there is NO predecessor: only version 1 is accepted and version 0/absent is rejected.
