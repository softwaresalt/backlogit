# 122-S Checkpoint Administrative Disposition — Operational Closure

## Readiness Status: READY WITH CONDITIONS

Conditions (none block merge/archival; all are disclosed follow-ups):

1. Four lower-severity review findings deferred as tracked backlog tasks
   (`136.014-T`, `136.015-T`, `136.016-T`) rather than fixed inline once the
   3-cycle review-fix limit was reached — see Review History.
2. The documented 3-cycle review-fix circuit breaker was exceeded (5 rounds)

3. Post-merge runtime verification of the merged PR #342 found a genuine

## Summary

Shipment 122-S (feature 136-F, tasks 136.001-T through 136.013-T) implements
two disjoint administrative disposition verbs for session checkpoints:
`AbandonCheckpoint` (parseable, schema-valid, active checkpoints only) and
`QuarantineCheckpoint` (malformed checkpoints only, verbatim byte-identical
move). Both are exposed identically through the CLI (`checkpoint abandon`,
`checkpoint quarantine`) and MCP (`backlogit_abandon_checkpoint`,
`backlogit_quarantine_checkpoint`) surfaces, routed through shared core logic
and covered by governed-operation behavioral-parity fixtures. `ListCheckpoints`
was made strictly read-only, replacing its prior silent auto-quarantine side
effect with an explicit `NeedsQuarantine`/`RemediationCommand` signal.

Implementation PR #342 merged to `main` via merge commit
`5b963353afe33fd762ba860f0ae967b26fa7b2d4`. A same-session fix-forward PR #343
merged via `04d14fbe8fd95ac1b8c0076671118f22f13f38bd` after post-merge runtime
verification found a relative-`--cwd` regression (see below). This closure
covers post-merge shipment archival, runtime re-verification against the
corrected `main` tip, and backlog handoff.

## Review History

PR #342 went through 5 Copilot automated review-fix rounds (exceeding the
documented 3-cycle limit) before merge:

* **Round 1 (11 findings)** — all fixed and verified with regression tests:
  archive-destination symlink confinement, a TOCTOU clobber race in the
  quarantine move (replaced with an atomic link-then-remove sequence), a
  Windows rename-cannot-replace-existing-file bug (switched to
  `atomicfile.WriteFileAtomic`), `ResolveCheckpoint` silently undoing an
  abandon disposition, an MCP error mapper swallowing
  `MutationPartialError` classification, `quarantined`-count semantics being
  misleading after the read-only listing change (both CLI and MCP), missing
  whitespace-trimming on the MCP surface (CLI/MCP parity), missing test
  coverage for the `ErrWriteIndeterminate` audit-failure branch, and a
  checkpoints-subdirectory symlink confinement gap.
* **Round 2 (1 finding)** — a symlinked *workspace storage root* (`.backlogit`
  itself, not just the checkpoints subdirectory) could escape confinement;
  fixed with `verifyStorageRootContained`.
* **Round 3 (1 finding)** — `AbandonCheckpoint` did not enforce the U6
  contract's `status == active` requirement, silently transitioning a
  `resolved` checkpoint to `abandoned`; fixed with a new `ErrCheckpointNotActive`
  sentinel and regression test.
* **Round 4 (1 finding, accepted as backlog)** — a narrow TOCTOU window
  between classification and move in `QuarantineCheckpoint`; tracked as
  `136.014-T`.
* **Round 5 (2 findings, accepted as backlog)** — a discarded unwind error on
  a rare double-failure branch of the atomic move (`136.015-T`), and the
  quarantine move path not yet respecting the opt-in `durable_writes` config
  flag (`136.016-T`).

All 16 review threads were explicitly replied to (fix commit or decline
rationale) and resolved before merge; the pre-merge readiness gate (fresh
Copilot review covering the exact merged HEAD, zero unresolved threads,
all CI green) passed for PR #342's final commit `242b684e` prior to merge.

## Fix-Forward: Post-Merge Runtime Verification Regression

The first runtime-verification pass against the merged PR #342 (commit
`5b963353`) — run with a **relative** `--cwd`, a common CLI invocation
pattern — found that every disposition call failed with `target escapes
checkpoints directory`. Root cause: `ResolveDispositionTarget` built a
checkpoints-directory path via `filepath.Join` without normalizing it to an
absolute path, so `confineToStorageRoot` (which re-joins non-absolute inputs
onto the workspace root) double-joined the relative root onto itself,
corrupting the path. This is a genuine functional regression, not a hardening
nit, so it was fixed immediately in a dedicated PR (#343) with a TDD
red-then-green regression test, its own quality gates, its own Copilot
review-fix round (2 gofmt findings, fixed), and merged before shipment
archival. See `docs/closure/2026-08-10-122-S-runtime-verification.md` for the
full before/after verification transcript.

## Protected Invariants (verified by automated tests and runtime verification)

* Quarantined bytes are byte-identical to the original checkpoint (hash
  comparison).
* Exactly one file changes per disposition call (hash-all-before/after).
* A failed audit append (either `ErrWriteNotApplied` or
  `ErrWriteIndeterminate` class) leaves the target completely untouched.
* Abandon and quarantine are disjoint: each refuses to operate on the
  other's target class, naming the correct verb.
* `ListCheckpoints` never mutates the filesystem.
* Disposition confinement rejects path traversal, absolute paths,
  volume-qualified paths, UNC paths, symlinked leaves, symlinked
  intermediate directories (checkpoints dir, archive dir), and a symlinked
  workspace storage root.
* Disposition works correctly under both absolute and relative workspace
  roots (the relative case was the fix-forward regression above).

## Monitoring / Handoff Notes

No new runtime monitoring surface is introduced (no new metrics, dashboards,
or alert rules) — this is a CLI/MCP administrative tooling feature operating
on local filesystem state, not a running service. The audit trail
(`checkpoint-disposition-audit.jsonl`) is the durable observability artifact
for this feature; operators can inspect it directly or via
`backlogit_query_sql` once JSONL-to-SQLite indexing of the audit log is added
(not yet wired — the audit log is append-only JSONL today, consistent with
other per-item event logs).
