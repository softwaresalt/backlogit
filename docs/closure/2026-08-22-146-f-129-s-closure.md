# 146-F / 129-S — Operational Closure

**Mode**: post-merge
**Context**: PR #373 `feat/146-f-success-shaped-evidence-loss` merged to `main` as merge
commit `15ab30a2a394439f52e5338fc94d1c50e3f395ae` (mergedAt `2026-08-23T02:16:58Z`).
Covering feature `146-F`, shipment `129-S` (23 tasks).

## Summary of Change

Two governed-diagnostic-path defects fixed:

1. **Checkpoint context key loss** — `events.CreateCheckpoint` re-marshaled a parsed
   `CheckpointV1` struct, silently dropping every unmodeled `context` key and every
   unknown top-level key. Fixed with a pinned two-pass decode (`plainContext` shadow for
   modeled fields, a separate raw-map pass for `Extra`), an escape-free `emit()` shared by
   `MarshalJSON`/`Keys()`, and a case-insensitive-fold-aware collision guard. The schema
   (top-level) namespace stays **closed** (unknown top-level keys are rejected); the
   `context` namespace is **open** (unmodeled keys are preserved and reported via
   `context_keys` on both CLI and MCP surfaces).
2. **Docs lint whole-corpus abort** — `docline.LintTree` returned `nil, err` on the first
   per-file frontmatter decode failure, so `backlogit docs lint` exited 1 with **no**
   findings printed, and MCP returned a bare `InternalError`. Fixed: a per-file decode
   failure is now reported as a `decode_error` finding and the scan continues; genuine
   containment/I-O failures remain hard errors. The non-zero exit code for a corpus
   containing a decode error is retained.

**Feature 146-F**: `status: done` (all 23 tasks done; merge commit

**Shipment 129-S**: `status: active` — **NOT shipped**. `backlogit_ship_shipment` was

error:

```
gate blocked: 146.006-T remains active
```

### Root Cause

`validateMemberGateEvidence` (internal/core/shipment_gate.go) requires every release-scope
task's `pre_task_completion_gate_passed` evidence `head_sha` to be an ancestor of (or equal
to) the shipment head. Task `146.006-T`'s recorded evidence head_sha
(`52f1983516a65ef2d782f75d137426ae5a63dc21`) is a real commit
(`feat(core): preserve unmodeled checkpoint context keys (146.006-T)`, touching
`internal/events/checkpoint_schema.go`) but it is **dangling** — not reachable from any
current branch (`git branch -a --contains` returns empty) — almost certainly because the
long PR #373 review-fix cycle (13 Copilot review rounds, multiple force-pushes visible in
the review history) rewrote/rebased history at some point, orphaning the original
per-task completion commit while its diff content survived into a later, differently-SHA'd
commit.

**Verified NOT a functional regression**: `internal/events/checkpoint_schema.go` at current
`main` HEAD contains `CheckpointContext.UnmarshalJSON`, `MarshalJSON`, and `Keys()` exactly
as introduced by the orphaned commit. The work is genuinely present; only the historical
evidence pointer is stale.

**Scope**: verified narrow — ancestry-checked all 23 manifest members (146-F +
146.001/002/004/005/006/007-024-T) against current `main` HEAD; only `146.006-T` fails.
The other 22 pass cleanly.

### Why No Automated Repair Was Attempted

* No CLI or MCP tool exposes `UnarchiveItem` (internal/core/archive.go) — the only code
  path that could return an archived member to a re-gateable state. It is used only
  internally by a migrate-import test helper.
* CLI `move --force-gates` is operator-only (requires `--force-reason`) and, per the
  code's own documentation, does not apply to items in the terminal `archived` status
  ("archived is a terminal sink with no allowed status transitions, so it cannot be
  force-gated" — `internal/core/shipment_gate.go`).
* Hand-editing the archived markdown file or the JSONL evidence log to fabricate a
  matching `head_sha` would defeat the exact security guard this code path exists to
  enforce, and is explicitly out of scope ("Do not hand-edit generated cache state").

### Recommendation / Follow-up

Stashed as `DD957688` (kind: bug, priority: high) for Stage triage: add a supported,
audited repair path for this exact narrow scenario (single dangling-evidence commit whose
diff is independently verifiable at the shipment head), analogous to the existing
`--force-gates` contract but usable on already-archived release-scope members.
