## Rollback Trigger and Procedure

**Trigger**: Roll back when a reproducible post-merge rerun produces a
non-zero analyzer exit, an unexpected diagnostic, a race, a panic, or a hang,
or when retained evidence shows that the merged tree differs from the
successfully checked final PR tree.

**Procedure**:

1. Confirm the failure against the merge commit and distinguish it from the
   known Windows checkout baselines.
2. Halt post-merge closure and next-shipment routing.
3. Open a dedicated corrective PR that reverts PR #436 through normal Git
   history.
4. Preserve merge-commit history; do not squash, rebase, force-push, or rewrite
   `main`.
5. Run repository quality gates and the focused analyzer and race-test commands.
6. Merge the corrective PR only after normal review, P-018, CI, and operator
   approval.
7. Record the observation outcome as rolled back and update this closure.

No deployment rollback, feature-flag change, data restoration, or migration
reversal is required.
