# 086-S Malformed-JSONL-Line Convergence — Operational Closure (Pre-Merge)

## Summary of the change

Two per-item JSONL event-log parsers previously diverged on how they handled a
malformed line:

- `internal/events/reader.go` → `ReadAllEvents` **silently** `continue`d past a
  malformed line (no signal — a silent data loss).
- `internal/db/rehydration.go` → `parseItemLogFile` returned `nil, err`; the
  caller then dropped **all** of the item's events, **bricking rehydration** for
  that item.

This shipment converges both paths onto **Policy A — skip-with-warning** via a
single shared helper `events.ParseEventLine(line, itemID) (Event, ok, err)`.
Both parsers now skip only the malformed line, retain surrounding valid events,
and emit a structured `slog.Warn` (item_id + path + 1-based line number +
reason) on every skip — closing the pre-existing silent skip in `ReadAllEvents`
and un-bricking rehydration. The now-unused `encoding/json` import was removed
from `rehydration.go` (`go vet` clean).

## Change scope

| Surface | Change |
| ------- | ------ |
| `internal/events/reader.go` | Added exported `ParseEventLine` helper (single source of truth for blank/malformed/valid classification); `ReadAllEvents` tracks 1-based line number and warns on skip. |
| `internal/db/rehydration.go` | `parseItemLogFile` delegates to `events.ParseEventLine`, warns on skip, retains valid events; removed unused `encoding/json` import. |
| `internal/events/reader_test.go` (new) | `TestParseEventLine` table test (blank/whitespace/malformed/valid contract). |
| `internal/db/rehydration_malformed_line_test.go` (new) | Convergence (red gate), observability, valid-unaffected, whitespace-only lock. |

Deferred (explicitly out of scope, follow-up candidates below): oversized-line
`bufio.Scanner` token limit, doctor-aggregate skip signal, threading
`cfg.logger` through the parse paths.

## Invariants to preserve

1. **Both parsers converge byte-for-byte** on the same input: identical
   line-numbering (1-based), ItemID backfill, CRLF trimming, and event ordering.
2. **Every malformed skip is observable** via `slog.Warn` carrying `item_id`,
   `path`, `line`, and `error` — no silent data loss on either path.
3. **Only deterministic parse errors skip.** Transient/structural I/O failures
   (`os.ReadFile`/`os.Open` errors, `scanner.Err()` including
   `bufio.ErrTooLong`) are surfaced by the parser as **returned errors**, never
   silently converted into a per-line skip. Caller handling is out of 086-S scope
   and differs: `internal/core/shipment_gate.go` propagates the `ReadAllEvents`
   error, while the pre-existing rehydration walk callback
   (`internal/db/rehydration.go`) logs `failed to parse item log` and skips that
   item (tolerable because the SQLite index is an ephemeral, re-syncable cache).
   The parser-level guarantee: a retryable failure is never masked as a silent
   per-line skip.
4. **Valid events are never dropped** because a sibling line was malformed.
5. `go vet` stays clean (no unused imports).

## Runtime verification

**Verdict: PASS.** In a throwaway scratch workspace, a per-item log seeded with
`[valid, malformed, valid]` was synced:

- `sync` emitted exactly **one** `level=WARN msg="skipping malformed event log
  line" item_id=... path=... line=2 error="invalid character 'T'..."` — for the
  single malformed line only.
- The two valid lines produced no warning (retained).
- `sync` succeeded (`Indexed N artifacts`, exit 0) — no hard-fail, rehydration
  no longer bricked.

This exercises the previously-bricking `parseItemLogFile` path end-to-end and
confirms both the un-brick and the observable-skip behavior.

## Healthy signals

- `sync` / rehydration succeeds on workspaces that previously bricked on a
  single malformed line.
- Warnings appear only for genuinely malformed lines, with accurate line
  numbers and `item_id`.
- No change in event counts for well-formed logs.

## Failure signals

- Rehydration drops all events for an item that has one malformed line
  (regression to old behavior).
- A transient I/O error is silently skipped instead of propagated.
- Warnings fire on valid lines (over-eager skip) or line numbers are wrong.

## Monitoring plan

- Watch `slog` output at `warn` level for `msg="skipping malformed event log
  line"`; a sudden spike indicates upstream log corruption worth investigating.
- The unit + integration tests (`internal/events`, `internal/db`) are the
  standing regression guard in CI.

## Rollback trigger

Any evidence that valid events are being dropped, or a transient failure is
being masked as a permanent skip, after merge.

## Follow-up candidates (deferred, to be stashed for Stage)

1. **Oversized-line handling** — `bufio.Scanner` default token limit
   (`bufio.ErrTooLong`) still surfaces as a propagated error rather than a
   skip-with-warning; deliberate whether oversized lines should follow the same
   skip policy or remain hard failures. (Data-integrity adjacent.)
2. **Doctor-aggregate skip signal** — surface an aggregate count of skipped
   malformed lines to `backlogit doctor` so operators can see corruption
   without scraping warn logs.
3. **Thread `cfg.logger`** through the parse paths so warnings honor the
   configured logger/level instead of the default `slog` logger.
