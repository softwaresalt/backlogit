## Why This Is a P-002 Breach

### What P-002 and Constitution II require

Constitution Principle II (NON-NEGOTIABLE) requires: `write test, confirm
it fails (red), implement, confirm it passes (green). Never write production
code before the corresponding test exists and has been observed to fail.`

P-002 operationalizes this as the harness-satisfied precondition: tests MUST
exist and MUST be confirmed failing BEFORE any production code is written.
The red phase must be in an immutable committed state before implementation begins.

### What the breach is

Commit `87f06f62` introduced production stub functions for
`ReconcileArchivedLifecycle` and `CorrectStashProvenance` returning
`ErrNotImplemented`. These stubs are **observable production behavior**:

- They compile as production code in `internal/core/`
- They return a defined, exported sentinel error (`ErrNotImplemented`)
- They define the function signatures, parameter types, and return types
- They constitute production code that existed in the repository before any
  test was written or committed

Commit `e7276bcf` (RED harness) came AFTER `87f06f62` (production stubs).
At the point `e7276bcf` was written, production code already existed. The
tests compiled against pre-existing stubs — they did NOT drive the interface
design as P-002 intends.

### What is NOT a cure

The session memory for 152-F/134-S characterized this wave as "declaration
then RED then GREEN per wave." While the commits are in that order (decl → RED
→ GREEN), the declarations included production stub functions, not merely type
declarations. This distinction is material:

- Type-only declarations (structs, interfaces) do not constitute production
  behavior and do not violate P-002 by themselves
- Stub functions returning `ErrNotImplemented` constitute observable production
  behavior and MUST follow tests, not precede them

The stash entry A2C91FE5 (current, unmodified) characterizes 152-F as having
"followed P-002 discipline (declaration then RED then GREEN per wave)." That
characterization was authored for context on the systemic enforcement gap.
Regardless of the characterization in the stash, the immutable commit record
shows production stubs preceded the RED harness. The commit history cannot
be retroactively made P-002 compliant.

### What is NOT violated by this breach

* **Behavioral correctness**: ReconcileArchivedLifecycle and
  CorrectStashProvenance operate correctly. Both operations were verified at
  runtime (PR #395 application: 150.001-T and 150.002-T reconciled to
  `archived_status: done`; 11FFF601 → 150-F provenance correction applied).
* **Quality gates at merge**: All tests passed, vet passed, lint passed,
  format clean at `547e0a41`.
* **Adversarial review**: 3-model adversarial review (Claude Opus 4.8,
  Claude Sonnet 5, GPT-5.6 Terra) at pre-PR stage. HIGH P1 (C1, event
  ordering) fixed. MEDIUM P1s C2-C6 all fixed.
* **Copilot review**: All threads resolved across all three PRs (#394, #395, #396).
* **CI**: All checks green at each PR's reviewed HEAD.
* **P-009**: All merges used merge commits.
